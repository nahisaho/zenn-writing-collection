# 教育機関のデジタル化とセキュリティ課題

## 校務支援システムのクラウド化トレンド

教育機関において、デジタル化の波は急速に進んでいます。特に2020年のコロナ禍を機に、多くの学校がオンライン授業やデジタル校務システムの導入を余儀なくされました。この変化は、教育現場に大きな変革をもたらしています。

### 文部科学省による次世代校務DXの推進

文部科学省は、[「次世代の校務デジタル化推進実証事業」](https://www.mext.go.jp/a_menu/shotou/zyouhou/detail/mext_02603.html)を通じて、校務支援システムのクラウド化を積極的に推進しています。この背景には、現在の校務支援システムが抱える7つの重要な課題があります。

**現状の課題と問題点**

統合型校務支援システムの整備率は86.8%（令和5年3月）まで上昇し、校務効率化に大きく寄与してきましたが、その殆どがネットワーク分離（閉鎖系ネットワーク）による自組織内設置（オンプレミス）型運用であり、校務用端末は職員室に固定されているため、GIGA時代・クラウド時代の教育DXに適合しなくなっています。

**文部科学省が特定する7つの課題**

1. **データ連携の困難**: 学習系で生成される膨大なデータと校務支援システムのデータ連携が困難または高コスト
2. **自治体間データ連携不備**: 転校・進学時等の自治体間でのデータ引き渡しができない
3. **働き方改革の阻害**: 自宅や出張先での校務処理ができず、教職員の働き方に制約
4. **災害対応力の不備**: 大規模災害や感染症等の緊急時に業務継続が困難
5. **人事異動時の負担**: 自治体によってシステムが異なり、人事異動の際の負担が大きい
6. **高い導入コスト**: 小規模自治体での導入が進まない
7. **システム重複とデータ可視化の不備**: 汎用クラウドサービスとの機能重複、教育データの学校経営への活用不足

**実証事業による解決策の模索**

秋田県及び山口県を実証地域として、校務系・学習系ネットワークの統合、クラウド活用を前提とした次世代の校務支援システムの整備を行い、次世代校務DXのモデルケース創出に取り組んでいます。

### 従来のオンプレミス型からクラウド型への移行理由

文部科学省が校務支援システムのクラウド化を推進する背景には、前述の7つの課題解決に向けた明確な方針があります。

**データ連携・統合の実現**

- **校務系と学習系の統合**: 分離されたシステムではできなかった教育データの総合的な活用
- **教育行政データとの連携**: MEXCBT等との連携による効率的な教育行政
- **自治体間データ連携**: 転校・進学時のスムーズなデータ引き渡し

**教職員の働き方改革の推進**

- **場所を選ばない業務環境**: 自宅や出張先からの校務処理を可能にする
- **災害時・緊急時の業務継続**: 感染症や災害時でも教育活動と校務業務を継続
- **複数端末使い分けの解消**: 校務系・学習系端末の統合による業務効率化

**システム運用の標準化・効率化**

- **人事異動時の負担軽減**: 自治体間でのシステム差異による負担の解消
- **小規模自治体への導入促進**: クラウドサービスによる導入ハードルの低減
- **機能重複の解消**: 汎用クラウドサービスとの適切な役割分担

**3層分離からクラウドファーストへの転換**

従来の教育情報セキュリティでは、「3層分離」モデル（校務系・学習系・インターネット系の分離）が採用されてきましたが、GIGA時代には以下の問題が顕在化しています。

- **端末の使い分け問題**: 70%以上の学校で教職員が校務系・学習系の別々の端末を使用
- **データ連携の困難**: 校務データと学習データの統合活用ができない
- **働き方改革の阻害**: 校務用端末が職員室に固定され、柔軟な働き方を制限
- **クラウドサービス活用の制約**: 教育効果の高いクラウドツールの導入が困難

**GIGAスクール構想との整合性**

文部科学省は、GIGAスクール構想の理念「個別最適な学び」と「協働的な学び」を実現するため、以下の方針を示しています。

- **1人1台端末の活用促進**: 学習者主体のICT活用環境整備
- **高速大容量ネットワーク**: 学校規模に応じた推奨帯域幅の設定
- **クラウドファースト**: セキュリティを確保しつつクラウドサービス活用を推進

**教育データ利活用の重要性**

デジタル庁は教育デジタル化の使命を「誰もが、どこからでも、いつでも、誰とでも、自分らしく学べる社会」と定義し、以下の3つの軸を設定：

- **スコープ（範囲）**: 学習機会の拡大
- **クオリティ（質）**: 個別最適化された学習
- **コンビネーション（組み合わせ）**: 多様な学習リソースの統合活用

これらを実現するためには、校務系と学習系のデータ連携が不可欠であり、クラウドベースのシステム統合が求められています。

### 教育機関特有のセキュリティリスク

教育機関は、その特性上、一般企業とは異なる独特のセキュリティリスクに直面しています。

**学習者・教職員の個人情報保護**

教育機関が扱う個人情報は極めて機密性が高く、以下のような情報が含まれます。

- **基本個人情報**: 氏名、住所、連絡先、生年月日
- **学習履歴**: 成績、出席状況、進路情報
- **健康情報**: 健康診断結果、アレルギー情報、身体的特徴
- **家庭状況**: 保護者情報、家庭の経済状況、特別な配慮事項

これらの情報は、個人情報保護法をはじめとする各種法令により厳格な管理が求められています。

**成績情報・評価データの機密性**

成績や評価に関するデータは、学習者の将来に大きな影響を与える重要な情報です。

- **評価の公平性確保**: 不正な改ざんや漏洩の防止
- **進路指導への影響**: 進学・就職に関わる重要データ
- **法的責任**: 誤った情報による損害賠償リスク

**外部からの不正アクセス対策**

教育機関は、サイバー攻撃者にとって魅力的なターゲットとなっています。

- **研究データの窃取**: 大学・高専等の研究機関における知的財産
- **個人情報の大量取得**: 在籍者数が多い機関ほど狙われやすい
- **ランサムウェア攻撃**: 教育活動を停止させる脅威

[Microsoft Cyber Signals 報告書](https://www.microsoft.com/en-us/security/blog/2024/10/10/cyber-signals-issue-8-education-under-siege-how-cybercriminals-target-our-schools/)によると、教育機関に対するサイバー攻撃は週平均2,507回に及び、教育・研究分野は国家主体による攻撃の標的として2024年に第2位となっています。

## Microsoft 365 A3/A5の概要とライセンス比較

### A3ライセンスのセキュリティ機能

Microsoft 365 A3は、教育機関向けの標準ライセンスとして位置づけられ、基本的なセキュリティ機能が包括的に提供されています。

**Microsoft Entra ID Plan 1**

A3ライセンスには、Microsoft Entra ID（旧Azure Active Directory）Plan 1が含まれており、以下の機能を利用できます。

- **条件付きアクセス**: 基本的なアクセス制御ポリシーの設定
- **多要素認証（MFA）**: セキュリティを強化するための追加認証
- **セルフサービスパスワードリセット**: ユーザーの利便性と管理コストの削減
- **グループベースのアクセス管理**: 効率的な権限管理

**基本的な条件付きアクセス**

A3では、以下の条件に基づいたアクセス制御が可能です。

- **場所ベースの制御**: IPアドレスや地理的位置による制限
- **デバイス準拠性**: 管理されたデバイスからのアクセスのみ許可
- **アプリケーション別制御**: アプリケーションごとの個別アクセス設定
- **ユーザー・グループベース制御**: 役割や部署に応じたアクセス管理

**Microsoft Defender for Office 365 Plan 1**

メールとコラボレーションツールの基本的な脅威保護：

- **Safe Attachments**: 添付ファイルの安全性確認
- **Safe Links**: URLの安全性確認と保護
- **フィッシング対策ポリシー**: スプーフィング・フィッシング攻撃の検出
- **スパム・マルウェア対策**: Exchange Online Protectionによる保護

**データ損失防止（DLP）- 基本機能**

- **メールとファイルのDLP**: 機密情報の外部流出防止
- **基本的な機密情報検出**: 個人情報や機密データの自動検出
- **通知とブロック機能**: 違反行為の自動検出と対処

### A5ライセンスの高度なセキュリティ機能

Microsoft 365 A5は、最高レベルのセキュリティとコンプライアンス機能を提供するプレミアムライセンスです。

**Microsoft Entra ID Plan 2**

A5ライセンスでは、より高度なID管理機能が利用可能です。

- **リスクベース条件付きアクセス**: 行動分析に基づくアクセス制御
- **Identity Protection**: 異常なサインイン検出と自動保護
- **Privileged Identity Management**: 特権アカウントの管理
- **Access Reviews**: 定期的なアクセス権限の見直し
- **Entitlement Management**: アクセス権限の自動化管理

**リスクベース条件付きアクセス**

A5の最も重要な機能の一つは、Microsoft Entra ID Protectionとの統合による高度な脅威検出です。

- **異常なサインイン検出**: 通常と異なるアクセスパターンの識別
- **リスクスコアベース制御**: 動的なリスク評価に基づくアクセス決定
- **自動リスク軽減**: 疑わしい活動の自動ブロックや追加認証要求
- **機械学習による継続的改善**: AIによる脅威検出精度の向上

**Microsoft Defender for Office 365 Plan 2**

より高度な脅威保護とセキュリティ運用機能：

- **Threat Explorer**: 詳細な脅威分析とハンティング機能
- **自動調査・対応（AIR）**: AI による自動的な脅威対処
- **Attack Simulation Training**: フィッシング攻撃のシミュレーション訓練
- **Campaign Views**: 大規模攻撃キャンペーンの可視化

**Advanced Threat Analytics（A3/A5共通）**

Microsoft Learnによると、Advanced Threat AnalyticsはA3とA5の両方に含まれています。

- **行動分析**: ユーザーとエンティティの異常行動検出
- **内部脅威検出**: 内部からの不正アクセス監視
- **高度な脅威インテリジェンス**: グローバルな脅威情報の活用

**Microsoft Defender for Identity（A5のみ）**

Microsoft LearnによるとDefender for IdentityはA5ライセンスでのみ利用可能です。

- **Active Directory環境の監視**: オンプレミス環境への攻撃検出
- **ラテラルムーブメント検出**: 内部ネットワークでの攻撃拡散の監視
- **特権アカウント監視**: 管理者アカウントの不正使用検出

**Microsoft Defender for Endpoint**

A5ライセンスではPlan 2が提供され、エンドポイント保護の最高レベルを実現：

- **行動ベース検出**: 未知の脅威の検出
- **脅威ハンティング**: プロアクティブな脅威調査
- **自動調査・修復**: AI による自動的な脅威対処
- **脆弱性管理**: システムの脆弱性評価と対策推奨

**注意**: A3ライセンスではDefender for Endpoint Plan 1のみが提供されます。

### A3とA5のセキュリティ機能差分の理解

教育機関がセキュリティリスクを効果的に軽減するためには、Microsoft 365 A3とA5の機能差分を正確に理解し、それぞれのライセンスレベルで実装すべきセキュリティ対策を体系的に把握することが重要です。

**本書の目的とアプローチ**

本書は、NIST SP800-207 Zero Trust Architectureに準拠したシステムをMicrosoft 365で構築する方法を解説します。A3とA5の機能差分を明確にし、それぞれのライセンスレベルにおいて：

- **Zero Trust原則の実装方法**: 「何も信頼せず、すべてを検証する」を実現する具体的設定
- **必須で実装すべきセキュリティ設定**: NIST準拠の最低限セキュリティ基準
- **推奨すべきセキュリティ強化策**: より高度なZero Trust保護を実現する追加対策
- **リスクベースの優先順位**: 教育機関特有のリスクに応じたZero Trust実装の優先度

これらを体系的に解説することで、各教育機関が現在のライセンスレベルでNIST準拠のZero Trustアーキテクチャを最大限実現できるよう支援します。

**A3とA5の戦略的な使い分け**

A3とA5では利用可能なセキュリティ機能に大きな差があります。この差分を理解することで、教育機関は

- **現在のライセンスでのZero Trust最適化**: 利用可能な機能でのNIST準拠セキュリティ設計
- **段階的なZero Trust強化計画**: A3からA5への移行を含む中長期的なZero Trust戦略
- **NIST準拠の効率的実現**: 必要最小限の投資で最大のZero Trustセキュリティ効果を実現

# Microsoft 365セキュリティアーキテクチャの理解

## クラウドセキュリティの基本概念

Microsoft 365のセキュリティアーキテクチャは、**多層防御**（Defense in Depth）の原則に基づいて設計されています。この概念は、単一のセキュリティ対策に依存するのではなく、複数の防御層を組み合わせることで、総合的なセキュリティを実現するアプローチです。

### ゼロトラストセキュリティモデル

Microsoft 365は、**ゼロトラストセキュリティモデル**を採用しています。これは、「何も信頼せず、すべてを検証する」という原則に基づくセキュリティフレームワークです。

**ゼロトラストの3つの核心原則**

1. **明示的な検証**: 利用可能なすべてのデータポイントで常に認証・承認
2. **最小限の特権アクセス**: Just-In-Time（JIT）およびJust-Enough-Access（JEA）
3. **侵害の想定**: セグメンテーションと継続的な検証でブラスト半径を最小化

### 教育機関におけるゼロトラストの実装

教育機関でゼロトラストを実装する際の主要な考慮事項：

**アイデンティティの検証**
- すべてのユーザー（教職員、生徒、外部ゲスト）の身元確認
- 多要素認証の必須化
- リスクベースの条件付きアクセス

**デバイスの信頼性確保**
- 管理対象デバイスの登録・監視
- デバイスコンプライアンスポリシーの適用
- 個人デバイス（BYOD）の安全な管理

**アプリケーションセキュリティ**
- アプリケーションごとのアクセス制御
- クラウドアプリセキュリティ（CASB）の活用
- Shadow ITの可視化と制御

**データ保護**
- データ分類と機密ラベリング
- データ損失防止（DLP）ポリシー
- 暗号化による保護

**ネットワークセキュリティ**
- マイクロセグメンテーション
- ネットワークアクセス制御
- トラフィック監視と分析

## セキュリティ統合管理の重要性

教育機関では、限られたIT人材で多様なセキュリティ脅威に対処する必要があります。Microsoft 365の統合管理機能により、効率的なセキュリティ運用が可能となります。

### Microsoft 365 Defenderによる統合セキュリティ

**統合ダッシュボード**
- すべてのセキュリティ情報を一元表示
- リアルタイムの脅威監視
- 優先度に基づくアラート管理

**自動調査・対応（AIR）**
- AI による脅威の自動分析
- 自動的な修復アクションの実行
- 人的介入が必要な場合のエスカレーション

**脅威ハンティング**
- プロアクティブな脅威の探索
- 高度な検索クエリ機能
- カスタム検出ルールの作成

### 教育機関向けセキュリティ運用の特徴

**学期制度への配慮**
- 入試・卒業時期の高負荷対応
- 長期休暇中のメンテナンス計画
- 新年度でのユーザー入れ替え対応

**多様なユーザー層への対応**
- 年齢・IT スキルレベルの多様性
- 学習者の段階的なアクセス権限管理
- 教職員とゲストユーザーの適切な権限分離

**研究・教育活動との両立**
- 学習・研究活動を阻害しないセキュリティ設計
- 必要に応じた柔軟なアクセス許可
- 緊急時対応体制の整備

## 法的要件とコンプライアンス

### 文部科学省の教育情報セキュリティポリシーに関するガイドライン

文部科学省は、[「教育情報セキュリティポリシーに関するガイドライン」](https://www.mext.go.jp/a_menu/shotou/zyouhou/detail/1397369.htm)を策定し、教育委員会が教育情報セキュリティポリシーを策定・改訂する際の参考としています。最新版は令和7年3月（2025年3月）に改訂されました。

**令和7年3月改訂の主要変更点**

2025年3月25日に公表された改訂版では、次世代校務DX環境への移行を見据えた大幅な見直しが行われました：

**1. 情報資産の4段階分類**
- **機密性・完全性・可用性**の観点から情報資産を4段階に分類
- **重要度分類II以上**の情報資産へのアクセスには多要素認証を含む強固なアクセス制御を必須化
- 学習者・保護者が高機密情報（成績・個人情報）にアクセスする際の安全管理措置を強化

**2. Shadow ITの明確な禁止**
- 教育委員会や教育機関が管理・承認していない個人デバイス、ソフトウェア、クラウドサービスの使用を原則禁止
- 情報漏洩や不正アクセスリスクの軽減策として明文化

**3. 多要素認証の段階的実装**
- **教職員**: 機密情報アクセス時の多要素認証を必須化
- **学習者**: ID・パスワードによる単要素認証も許可（パスワード複雑性確保が条件）、ただし多要素認証を推奨

**従来の3層分離モデルからの課題**

改訂前のガイドラインで推奨されていた以下のアプローチは、現在では大きな課題を抱えています。

- **2層分離**（72.7%の学校で実装）: 校務系・学習系の分離
- **3層分離**（22.9%の学校で実装）: 校務系・校務外部接続系・学習系の分離

このアプローチの問題点：

- **教職員の負担増**: 82.1%の教職員が校務用・学習用の別端末を使用
- **運用コストの増大**: 複数端末の管理・保守コスト
- **データ連携の困難**: システム間でのデータ統合活用の制約
- **働き方改革の阻害**: 職員室に固定された校務用端末による制約

**NIST SP800-207 Zero Trust Architectureとの対比**

文部科学省のガイドラインは、従来の3層分離モデルから2025年改訂版でZero Trustアプローチに近づく方向へと転換していますが、**NIST SP800-207 Zero Trust Architectureの完全な要件を満たしているわけではありません**。米国NIST（国立標準技術研究所）が2020年に策定した[SP800-207 Zero Trust Architecture](https://csrc.nist.gov/pubs/sp/800/207/final)との比較：

| 比較項目 | 従来の3層分離モデル | 2025年改訂ガイドライン | NIST Zero Trust | **準拠状況** |
|---------|-----------------|---------------------|-----------------|-------------|
| **基本概念** | ネットワーク境界による防御 | アイデンティティベースセキュリティ | 「何も信頼せず、すべてを検証」 | **部分的** |
| **信頼の前提** | 内部ネットワークは安全 | ユーザー・デバイス認証による信頼 | 内部・外部問わず全て検証 | **不十分** |
| **アクセス制御** | ネットワーク層での制御 | 多要素認証・情報資産分類 | ID・デバイス・アプリ層での制御 | **部分的** |
| **データ保護** | 物理的・論理的分離 | 情報資産4段階分類・暗号化 | 暗号化・認証による保護 | **準拠** |
| **継続的検証** | 一度認証すれば信頼 | 定期的な認証見直し | リアルタイム・継続的検証 | **不十分** |
| **マイクロセグメンテーション** | ネットワーク境界分離 | 承認システム内での統合 | アプリケーション・データレベル分離 | **未対応** |
| **動的ポリシー** | 静的ルールベース | 情報分類ベース | 行動・コンテキスト分析ベース | **未対応** |

**新ガイドラインでのパラダイムシフト**

2025年改訂版では、次世代校務DXに向けた大きな方向転換が示されています。

**Zero Trustアプローチの採用**

**なぜ文科省ガイドラインではNIST Zero Trust要件に不十分なのか**

上記の比較表が示すように、2025年改訂ガイドラインは大幅な改善を示していますが、NIST SP800-207の核心的要件に対して以下の重要な不備があります。

**1. 継続的検証の不備**
- **文科省アプローチ**: 「定期的な認証見直し」に留まる
- **NIST要件**: アクセス要求の度に、リアルタイムでユーザー・デバイス・アプリケーション・データの信頼性を検証
- **問題点**: 一度認証されたユーザーは、次回見直しまで信頼され続けるため、アカウント乗っ取りや内部脅威を検知できない

**2. マイクロセグメンテーションの未実装**
- **文科省アプローチ**: 「承認システム内での統合」で大きな境界を設定
- **NIST要件**: アプリケーション・データごとに最小権限でアクセスを分離
- **問題点**: システム内で横展開攻撃（ラテラルムーブメント）を受けた場合、広範囲のデータにアクセスされるリスク

**3. 動的ポリシーの不在**
- **文科省アプローチ**: 「情報分類ベース」の静的なアクセス制御
- **NIST要件**: ユーザーの行動パターン、アクセス時間・場所、デバイス状態などを動的に分析してリアルタイム判定
- **問題点**: 平日昼間と深夜休日、校内と自宅からのアクセスを同じように扱うため、異常なアクセスを検知・制御できない

**4. 信頼の前提における根本的違い**
- **文科省アプローチ**: 「ユーザー・デバイス認証による信頼」で一定期間の信頼を付与
- **NIST要件**: 「何も信頼せず、すべてを検証」で常に疑いつつアクセス判定
- **問題点**: 認証後の行動変化や環境変化に対応できず、内部脅威や侵害拡大を防げない

現在でも多くの教育機関は従来の分離モデルから移行できておらず、**Microsoft 365を活用した完全なNIST SP800-207準拠Zero Trustアーキテクチャの実装**が急務となっています。

**本人の権利への対応**

# 校務支援システムと学習環境のセキュリティレベル差異

## 校務支援システムと学習環境の根本的な違い

教育機関においてMicrosoft 365を活用する際、**校務支援システム利用**と**学習環境利用**では、求められるセキュリティレベルが根本的に異なります。この違いを理解せずに同一のセキュリティ設定を適用すると、教育効果を阻害したり、逆に重要な校務情報を危険にさらしたりする恐れがあります。

### 扱う情報の機密性の違い

**校務支援システムで扱う情報**

校務支援システムでは、教育機関運営の核心となる高機密情報を扱います。

- **人事・給与情報**: 教職員の個人情報、給与・賞与データ、人事評価、勤務記録
- **財務・会計情報**: 学校予算、支出管理、契約情報、監査資料
- **学籍管理情報**: 児童生徒の基本情報、指導要録、成績、出席状況、進路情報
- **健康管理情報**: 健康診断結果、アレルギー情報、医療機関連携記録
- **要保護児童情報**: 家庭状況、児童相談所連携記録、要配慮事項
- **教育委員会連携情報**: 自治体固有の管理情報、監査対応資料

これらの情報は、**個人情報保護法の要配慮個人情報**に該当し、漏洩時の損害は極めて深刻です。

**学習環境で扱う情報**

一方、学習環境では主に教育活動に直接関わる情報を扱います。

- **学習コンテンツ**: デジタル教材、課題、学習記録、作品
- **コミュニケーション**: 授業内ディスカッション、グループワーク記録
- **学習成果物**: レポート、プレゼンテーション、創作活動の成果
- **学習履歴**: 学習進捗、教材利用履歴、学習時間
- **協働学習データ**: チーム活動記録、共有ドキュメント

これらは教育目的での利用が前提であり、適切な管理は必要ですが、校務情報ほどの厳格な機密性管理は求められません。

### 利用目的と利用者の違い

**校務支援システムの利用特性**

- **利用者**: 教職員、管理職、事務職員（限定された範囲）
- **利用場面**: 成績管理、出席管理、指導要録作成、保護者連絡、教育委員会報告
- **アクセス頻度**: 業務時間内の定期的アクセス
- **データの性質**: 正確性と完全性が法的に要求される公文書レベル
- **責任範囲**: 学校法人・教育委員会としての法的責任

**学習環境の利用特性**

- **利用者**: 児童生徒、教職員（幅広い範囲）
- **利用場面**: 授業、課題提出、協働学習、創作活動、探究学習
- **アクセス頻度**: 授業時間および宿題・自学等での利用
- **データの性質**: 学習過程で生成される成長記録、試行錯誤の痕跡
- **責任範囲**: 教育指導上の配慮と学習者の安全確保

### セキュリティ要件の階層化

**校務支援システムのセキュリティ要件**

文部科学省の教育情報セキュリティポリシーガイドライン（令和7年3月改訂）において、校務支援システムで扱う情報は **「重要度分類II以上」** に分類され、以下の厳格なセキュリティ要件が求められます。

**認証・アクセス制御**
- **多要素認証（MFA）必須**: すべてのアクセスでMFA実装
- **条件付きアクセス**: 場所・時間・デバイスベースの制限
- **特権アクセス管理**: 管理者権限の厳格な制御
- **定期的なアクセス権見直し**: 最低年2回の権限監査

**データ保護**
- **暗号化**: 保存時・転送時の暗号化必須
- **データ分類**: 自動分類による機密ラベル付与
- **アクセスログ**: すべての操作の詳細記録
- **データ保存期間管理**: 法定期間に基づく自動削除

**監査・証跡管理**
- **包括的監査ログ**: 「誰が、いつ、何を、どこから」の完全記録
- **リアルタイム監視**: 異常アクセスの即座検知
- **インシデント対応**: 迅速な脅威対処と影響範囲特定

**学習環境のセキュリティ要件**

学習環境では、教育効果を最大化するために**適切な安全性を保ちつつ、学習の自由度を確保**するバランスが重要です。

**基本的安全の確保**
- **基本認証**: ID・パスワード認証（複雑性要件遵守）
- **多要素認証推奨**: 段階的導入による利用者負担軽減
- **年齢に応じた設定**: 発達段階を考慮したセキュリティレベル調整
- **保護者同意**: 個人情報利用の適切な同意取得

**学習活動の促進**
- **創造性の尊重**: 過度な制限による学習意欲削減の回避
- **協働学習の支援**: 安全な情報共有環境の提供
- **デジタルシティズンシップ教育**: 適切なネット利用スキル育成
- **失敗から学ぶ機会**: セキュリティ教育を通じた実体験学習

**プライバシー保護の配慮**
- **最小限の個人情報収集**: 教育目的に必要最小限のデータのみ
- **学習記録の透明性**: 何がどう記録されるかの明確化
- **削除権の配慮**: 学習者・保護者の削除要求への適切な対応

### Microsoft 365での実装戦略

**校務系と学習系の統合的セキュリティ設計**

Microsoft 365では、単一プラットフォーム内で校務支援システムと学習環境の両方のセキュリティ要件を満たすことができます。

**Identity（アイデンティティ）レベルでの分離**
- **Microsoft Entra ID**: 役割ベースの細やかな権限管理
- **動的グループ**: 職種・学年・クラス別の自動グループ分け
- **条件付きアクセス**: 利用目的に応じたセキュリティレベル自動調整

**Application（アプリケーション）レベルでの制御**
- **校務系アプリ**: 高セキュリティ設定（MFA必須、厳格なアクセス制御）
- **学習系アプリ**: バランス型設定（使いやすさと安全性の両立）
- **SharePointサイト**: 情報分類による自動アクセス制御

**Data（データ）レベルでの保護**
- **Microsoft Purview**: 校務情報と学習情報の自動分類・保護
- **機密ラベル**: 情報種別による自動暗号化とアクセス制限
- **DLP（データ損失防止）**: 機密情報の外部流出防止

**重要なポイント：段階的セキュリティアプローチ**

本書で解説するMicrosoft 365のセキュリティ実装では、**段階的セキュリティアプローチ**を採用します。

1. **基盤セキュリティ**: 全体的な基本セキュリティの確立
2. **用途別最適化**: 校務系・学習系それぞれの特性に応じた調整
3. **継続的改善**: 利用状況と脅威環境の変化に応じた設定見直し

このアプローチにより、校務支援システムでは法的要件を満たす高いセキュリティを確保しながら、学習環境では教育効果を損なわない適切なセキュリティレベルを実現することができます。
