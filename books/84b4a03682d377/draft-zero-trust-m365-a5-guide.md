## はじめに

### ゼロトラスト製品を購入しただけでは、ゼロトラストは実現できない

「Microsoft 365 A5を導入すればゼロトラストが実現できる」——そう考えて高額なライセンスを購入したものの、実際には何をどう設定すればよいのかわからず、結局はデフォルト設定のまま運用している教育委員会は少なくありません。

**本書を執筆した背景**:

クラウド型校務支援システムの導入が全国の教育委員会で進む中、セキュリティ対策として Microsoft 365 A5 のライセンス購入を決定する自治体が増えています。しかし、A5には30以上のセキュリティ製品が含まれており、それぞれが高度な機能を持つ反面、**「どの機能を」「どの順番で」「どう設定すれば」教育現場でゼロトラストが実現できるのか**という実践的な設計ガイドは、ほとんど存在しませんでした。

その結果:
- 🚨 **A5を購入したが、Identity Protectionなどの主要機能が未設定のまま**
- 🚨 **条件付きアクセスポリシーが未構成で、従来型の境界防御に依存**
- 🚨 **パスワードスプレー攻撃によるアカウント侵害が発生しても検知できない**
- 🚨 **高額なライセンス費用に見合う価値を発揮できていない**

このような状況が生まれています。

### この書籍が解決する課題

本書は、**Microsoft 365 A5のライセンスを購入済み、またはこれから購入を検討している教育委員会**が、実際にゼロトラストセキュリティを実現するための実践的な設計・構成・運用ガイドです。

**本書で得られること**:

1. **A5の30以上の製品を、教育現場で使える形に体系化**
   - ID管理、デバイス保護、情報保護、脅威対策の4領域に整理
   - 各製品の役割と導入優先順位を明確化
   - A3との機能差分とA5が必要な理由を理解

2. **教育機関特有の脅威への対策**
   - パスワードスプレー攻撃（教育機関への攻撃の70%）への防御方法
   - 児童生徒の個人情報保護に必要な具体的設定
   - 教職員の限られたITリテラシーでも運用可能な設計

3. **段階的な実装ロードマップ**
   - 最小限の設定で始める「クイックスタート」（1-3ヶ月）
   - 優先度に応じた機能追加（3-12ヶ月）
   - 限られた予算・人材での実装アプローチ

4. **実際に使える設定手順と運用方法**
   - Entra ID、Conditional Access、Intuneの具体的設定手順
   - セキュリティアラートの運用フロー
   - インシデント対応の実践的プロセス

**目的**: A3/A5/SASEの機能差を理解し、教育委員会に最適なライセンス構成を判断する

#### 4.1 Microsoft 365 A3 で実現できることと限界
**目的**: A3ライセンスでのゼロトラスト実装の限界を理解する
**内容**:

##### A3に含まれる機能
- **ID管理・認証**
  - Microsoft Entra ID P1（P2ではない）
  - 多要素認証（MFA）：基本的なMFA可能
  - Conditional Access：限定的（デバイスプラットフォーム、場所のみ）
  - セルフサービスパスワードリセット
  - グループベースアクセス管理

- **デバイス管理**
  - Microsoft Intune：デバイス管理・MDM機能あり
  - Windows Autopilot：自動展開可能
  - デバイスコンプライアンス：基本的なポリシー設定可能

- **情報保護**
  - 基本的な秘密度ラベル：手動適用のみ
  - Exchange Online のメッセージ暗号化
  - 基本的なDLP：Exchange Online、SharePoint、OneDrive、Teamsのみ

- **脅威対策**
  - Microsoft Defender for Office 365 Plan 1：基本的なメール保護
  - Exchange Online Protection（EOP）
  - Microsoft Defender Antivirus（Windows標準）

##### A3で実現**できない**ゼロトラスト機能（教育委員会にとって致命的）
- **❌ 高度なID保護**
  - Identity Protection：リスクベース認証不可（不審なサインインの自動ブロック不可）
  - Privileged Identity Management（PIM）：管理者権限のJust-In-Time付与不可
  - アクセスレビュー：定期的な権限見直しの自動化不可
  - Conditional Accessの高度な条件：リスクレベル、デバイスコンプライアンスベースの制御不可

- **❌ 高度な情報保護（児童生徒の個人情報保護に必須）**
  - 秘密度ラベルの自動適用：児童生徒情報の自動検出・保護不可
  - Endpoint DLP：端末からのUSB持ち出し、私的メール送信のブロック不可
  - トレーニング可能な分類子：成績表・指導要録の自動分類不可
  - Exact Data Match（EDM）：児童生徒氏名・学籍番号の正確な検出不可

- **❌ 内部脅威対策**
  - Insider Risk Management：退職時の情報持ち出し検知不可
  - Communication Compliance：不適切な情報共有の検知不可

- **❌ 高度な脅威対策**
  - Microsoft Defender for Office 365 Plan 2：攻撃シミュレーション訓練不可、自動調査不可
  - Microsoft Defender for Endpoint Plan 2：EDR（高度な脅威検知）不可
  - Microsoft Defender for Cloud Apps：シャドーIT検知、セッション制御不可

- **❌ 高度なコンプライアンス**
  - Microsoft Purview Compliance Manager：リスク評価、改善アクション不可
  - eDiscovery（Advanced）：高度な証拠保全・調査不可
  - 監査ログの長期保存（10年）：個人情報保護条例対応に必要

##### 教育委員会での影響
**A3では実現できない重要なセキュリティ対策**：
- 🚨 児童生徒の個人情報を含むファイルのUSB持ち出しを**止められない**
- 🚨 教職員の不審なサインイン（侵害されたアカウント）を**自動でブロックできない**
- 🚨 成績情報・指導要録を**自動的に検出・保護できない**
- 🚨 退職予定者の大量ダウンロード・情報持ち出しを**検知できない**
- 🚨 管理者権限の不正利用を**防止できない**（永続的な権限付与のリスク）
- 🚨 教職員向けフィッシング対策訓練を**実施できない**

#### 4.2 SASE（Secure Access Service Edge）追加時の検討
**目的**: SASEソリューション追加でA3の不足を補えるか判断する
**概要**: Cloudflare、Zscaler、Palo Alto等のSASE製品を追加した場合の機能カバー範囲を明確にします。

##### SASEで実現できる機能
- **ネットワークセキュリティ**
  - ゼロトラストネットワークアクセス（ZTNA）：アプリケーションへの安全なアクセス
  - セキュアWebゲートウェイ（SWG）：Webアクセスのフィルタリング
  - クラウドファイアウォール（FWaaS）
  - DDoS保護

- **クラウドアプリ保護（CASB機能）**
  - シャドーITの検出：許可されていないクラウドサービス利用の可視化
  - データ損失防止（DLP）：一部のSASE製品で提供
  - セッション制御：リアルタイムでのアクセス制御

##### A3 + SASE でも**できない**こと（A5が必要）
**Microsoft 365固有の機能はSASEでカバー不可**：

- **❌ Microsoft製品との深い統合が不可能**
  - Entra ID Identity Protection：Microsoftのみが提供する脅威インテリジェンス
  - Privileged Identity Management（PIM）：Entra ID管理者権限の制御はMicrosoftのみ
  - Microsoft 365アプリ内での秘密度ラベル自動適用：Word/Excel/PowerPointでの自動保護

- **❌ エンドポイントでの情報保護が不完全**
  - Endpoint DLP：Windows端末でのファイル操作制御（USB、印刷、スクショ）はMicrosoftのみ
  - SASEのDLPはネットワーク境界での制御のみ（端末内部の操作は制御不可）
  - 例：児童生徒情報ファイルをUSBにコピーする操作を**SASEでは止められない**

- **❌ 内部脅威対策が不可能**
  - Insider Risk Management：退職予定者の行動分析、大量ダウンロード検知
  - SASEは外部脅威対策が中心で、内部不正は対象外

- **❌ Microsoft 365固有のコンプライアンス機能**
  - Microsoft Purview全般（Information Protection、DLP、Compliance Manager）
  - Microsoft 365監査ログの長期保存（個人情報保護条例対応）
  - eDiscovery（訴訟対応、証拠保全）

- **❌ Microsoft製品間の統合による高度な脅威対策**
  - Defender for Office 365 + Defender for Endpoint + Defender for Cloud Appsの統合
  - Microsoft Defender ポータルでの一元管理
  - 複数製品からの脅威シグナル統合による高精度検知

### 第5章: Entra ID (Azure AD) による教職員ID基盤の構築

#### 5.1 教育機関を標的としたアカウント侵害の現状とトレンド
**目的**: ID保護の重要性と脅威の実態を理解する
**概要**: 教育機関で急増しているアカウント侵害の手口を知り、適切な対策の必要性を認識します。

##### 教育機関におけるアカウント侵害の深刻化

**統計データ（Microsoft セキュリティレポートより）**:
- 🚨 **アカウント侵害の99.9%はパスワードベース攻撃**
- 🚨 **パスワードスプレー攻撃が全体の70%以上を占める**（最も多い攻撃手法）
- 🚨 **教育機関は全業種で最もアカウント侵害を受けやすい**（金融・医療の2倍以上）
- 🚨 **侵害されたアカウントの平均検知時間: 197日**（約6ヶ月間気づかない）

**教育機関が狙われる理由**:
- 児童生徒の個人情報が大量に保存されている（氏名、住所、成績、家庭環境等）
- セキュリティ予算・人材が不足している
- 教職員のセキュリティ意識にばらつきがある
- 多数の外部連携（保護者、地域、ベンダー等）でアクセスポイントが多い

##### パスワードスプレー攻撃とは

**攻撃の仕組み**:
1. **一般的なパスワードを使用**: 攻撃者は「Password123」「Spring2024」「Welcome123」など、よく使われるパスワードのリストを用意
2. **多数のアカウントに対して試行**: 1つのパスワードを数百～数千のアカウントに試す
3. **アカウントロックアウトを回避**: 1つのアカウントに対する試行回数は少ないため、アカウントロックが発動しない
4. **侵害成功**: 弱いパスワードを使っている教職員のアカウントが侵害される

**従来のブルートフォース攻撃との違い**:

| 攻撃手法 | ブルートフォース攻撃 | パスワードスプレー攻撃 |
|---------|-------------------|---------------------|
| **対象** | 1つのアカウント | 多数のアカウント |
| **試行パスワード** | 多数（数万～数百万） | 少数（10-50個程度） |
| **検知されやすさ** | 検知されやすい | 検知されにくい |
| **アカウントロック** | 発動する | 発動しない |
| **成功率** | 低い | 高い（弱いパスワード使用者がいれば） |

##### 教育現場でのパスワードスプレー攻撃の実例

**シナリオ1: 一般的なパスワードの使用**
- 攻撃者: 「Spring2024」を全教職員アカウント（500名）に試行
- 結果: 5名の教職員が同じパスワードを使用していたため侵害
- 被害: 侵害された教職員が担任する児童生徒の個人情報が流出

**シナリオ2: 組織名を含むパスワード**
- 攻撃者: 「School2024」「City2024」など一般的な組織名を含むパスワードを試行
- 結果: 10名の教職員アカウントが侵害
- 被害: 侵害されたアカウントから校務支援システムにアクセスされ、成績情報が外部に送信

**シナリオ3: 季節・月を含むパスワード**
- 攻撃者: 「April2024」「Summer2024」「Winter2024」など季節や月を含むパスワードを試行
- 結果: パスワード定期変更により、簡単なパターンで変更した教職員が被害
- 被害: メールアカウントが侵害され、保護者を装ったフィッシングメールが送信される

##### パスワードスプレー攻撃が成功する理由

**教育現場特有の脆弱性**:

1. **弱いパスワードの使用**
   - 🚨 「School123」「Welcome2024」など推測しやすいパスワード
   - 🚨 複雑性要件を満たす最低限のパスワード（Password1!等）
   - 🚨 複数のシステムで同じパスワードを使い回し

2. **パスワード定期変更の弊害**
   - 🚨 3ヶ月ごとの強制変更により、教職員は覚えやすいパターンを選択
   - 🚨 「Spring2024」→「Summer2024」→「Autumn2024」のような予測可能な変更
   - 🚨 変更履歴の制限（過去5個まで）を悪用したローテーション

3. **検知の難しさ**
   - 🚨 1つのアカウントへの試行回数が少ないため、ログから異常を発見しにくい
   - 🚨 異なるIPアドレスから分散して攻撃されるため、パターン検知が困難
   - 🚨 正規のサインイン試行と区別がつかない

##### なぜ従来の対策では不十分なのか

**従来の対策の限界**:

❌ **複雑なパスワード要件**
- 要件: 英大小文字、数字、記号を含む8文字以上
- 限界: 「Password1!」のような最低限の要件を満たすだけの弱いパスワード
- 結果: パスワードスプレー攻撃に対して無防備

❌ **パスワード定期変更（3ヶ月ごと等）**
- 要件: 90日ごとにパスワード変更を強制
- 限界: 教職員は覚えやすいパターンで変更（Spring2024→Summer2024）
- 結果: むしろ攻撃者に推測されやすくなる
- **NIST/Microsoftの推奨**: パスワード定期変更は廃止すべき

❌ **アカウントロックアウト（5回失敗でロック）**
- 要件: 同一アカウントへの5回の失敗でロック
- 限界: パスワードスプレー攻撃は1アカウント1-2回しか試行しないためロックされない
- 結果: パスワードスプレー攻撃には効果なし

❌ **IPアドレスブロック**
- 対策: 不審なIPアドレスをブロック
- 限界: 攻撃者は多数のIPアドレスを使用（ボットネット、VPN等）
- 結果: すべてのIPをブロックすることは不可能

##### Microsoft 365 A5が提供する根本的な対策

**A5で実現できるパスワードスプレー攻撃対策**:

✅ **1. Identity Protection（リスクベース認証）**
- 仕組み: Microsoftの脅威インテリジェンスが不審なサインインパターンを自動検知
- 対策:
  - パスワードスプレー攻撃の兆候を検出（複数アカウントへの同時試行）
  - リスクレベルに応じてMFA要求または自動ブロック
  - 侵害されたアカウントを自動検知・保護
- **A3では利用不可**

✅ **2. 多要素認証（MFA）の全教職員展開**
- 仕組み: パスワード+もう1つの認証要素（スマホアプリ、電話、SMS等）
- 対策:
  - パスワードが盗まれても、2つ目の要素がなければアクセス不可
  - パスワードスプレー攻撃が成功してもアカウント侵害を防げる
- **A5/A3どちらでも利用可能**（基本機能）

✅ **3. パスワードレス認証への移行**
- 仕組み: Windows Hello（顔認証・指紋認証）、FIDO2キーでパスワードを廃止
- 対策:
  - パスワード自体が存在しないため、パスワードスプレー攻撃が不可能
  - フィッシング攻撃にも完全耐性
- **A5で推奨、A3でも一部利用可能**

✅ **4. Conditional Access（高度なアクセス制御）**
- 仕組み: サインイン時の状況（場所、デバイス、リスクレベル等）に応じた動的な制御
- 対策:
  - 異常な場所からのサインインをブロック（海外からのアクセス等）
  - 管理外デバイスからのアクセスを制限
  - リスクベースでMFA要求またはブロック
- **A5で高度な条件、A3は基本条件のみ**

##### 本章で実装する対策

第5章では、以下の対策を段階的に実装します：

**第1段階: 全教職員へのMFA展開（必須）**
- セクション 5.4で詳細解説
- パスワードスプレー攻撃が成功してもアカウント侵害を防ぐ
- **展開期間: 1-2ヶ月**

**第2段階: パスワードレス認証への移行（推奨）**
- セクション 5.5で詳細解説
- Windows Hello for Business、FIDO2キーの展開
- **展開期間: 3-6ヶ月**

**第3段階: Identity Protectionによる自動保護（A5必須）**
- セクション 5.6で詳細解説
- リスクベース認証、侵害されたアカウントの自動検知

これらの対策により、**パスワードスプレー攻撃の成功率を99%以上削減**できます。

#### 5.5 パスワードレス認証の段階的導入
**目的**: より安全で利便性の高いパスワードレス環境を構築する
**概要**: パスワード依存からの脱却により、フィッシング攻撃への耐性を高め、教職員の利便性も向上させます。

##### なぜパスワードレス認証が教育委員会に必要か

**パスワードの課題**:
- 🚨 **フィッシング攻撃に脆弱**: パスワードは盗まれる、教職員が偽サイトに入力してしまう
- 🚨 **使い回しのリスク**: 私的サービスと同じパスワードを校務システムで使用
- 🚨 **忘却・紛失**: パスワードリセット依頼がヘルプデスクの負担に
- 🚨 **複雑性要件の限界**: 複雑なパスワードでも漏洩すれば無意味

**パスワードレス認証の利点**:
- ✅ **フィッシング攻撃に強い**: 生体認証やFIDO2キーは盗めない、偽サイトでは使えない
- ✅ **利便性の向上**: 顔認証・指紋認証で素早くサインイン
- ✅ **ヘルプデスク負荷軽減**: パスワードリセット依頼が激減
- ✅ **セキュリティと利便性の両立**: より安全で、より簡単に

##### パスワードレス認証の3つの方式

**1. Windows Hello for Business（推奨：校務用PC）**
- **概要**: Windows PCの顔認証・指紋認証・PINを利用
- **適用対象**: 教育委員会・学校の校務用Windows PC
- **メリット**:
  - 追加デバイス不要（PC内蔵カメラ・指紋リーダー活用）
  - Windowsサインインと統合（シームレスな体験）
  - オフラインでも使用可能（PIN認証）
- **デメリット**:
  - デバイスごとに登録が必要
  - カメラ・指紋リーダー非搭載端末では利用不可

**2. FIDO2 セキュリティキー（推奨：共有端末・管理者）**
- **概要**: USB/NFC/Bluetoothで接続する物理的なセキュリティキー
- **適用対象**:
  - 共有端末を使う教職員（職員室の共有PC等）
  - 管理者アカウント（特権アカウント保護）
  - カメラ非搭載の端末ユーザー
- **メリット**:
  - 最高レベルのセキュリティ（物理キーが必要）
  - 複数端末で同じキーを使用可能
  - フィッシング完全耐性
- **デメリット**:
  - 追加費用（1個3,000-10,000円）
  - 紛失リスク（予備キーの登録推奨）
  - USB Type-Cなど端末の接続口に依存
- **推奨製品**:
  - YubiKey 5 シリーズ（USB-A/USB-C/NFC）
  - Thales（旧Gemalto）FIDO2キー

**3. Microsoft Authenticator アプリ（補完的利用）**
- **概要**: スマートフォンアプリで承認
- **適用対象**:
  - 自宅・外出先からアクセスする教職員
  - 私物スマートフォンの業務利用を許可する場合
- **メリット**:
  - 追加費用なし（無料アプリ）
  - 番号マッチングによるフィッシング対策
  - 場所を問わず利用可能
- **デメリット**:
  - スマートフォン必須（私物利用の是非）
  - ネットワーク接続必要
  - 紛失時の対応が必要
- **教育委員会での検討ポイント**:
  - 私物スマートフォンの業務利用ポリシー
  - 公務用スマートフォン支給の予算
  - BYOD（私物端末の業務利用）の可否

##### Windows Hello for Business の実装手順

**前提条件**:
- Windows 10/11 Pro以上（教育機関向けライセンス）
- Entra ID（Azure AD）参加済み端末
- Microsoft Intune登録済み
- 端末にカメラまたは指紋リーダー搭載

**Intuneでの構成手順**:

1. **Intuneポリシーの作成**
   - デバイス構成 > プロファイル > 作成
   - プラットフォーム: Windows 10以降
   - プロファイルの種類: ID保護

2. **設定項目**:
   - **Windows Hello for Business を構成する**: 有効
   - **PIN の最小文字数**: 6文字（教育現場では覚えやすさも考慮）
   - **PIN の複雑さ**: 数字のみ（または英数字）
   - **PIN の有効期限**: 無制限（または180日）
   - **生体認証を使用する**: 有効（顔認証・指紋認証）
   - **セキュリティ キーを使用したサインインを許可する**: 有効（FIDO2対応）

3. **ポリシーの割り当て**:
   - 対象: 教職員グループ
   - 展開モード: 段階的（パイロット→拡大→全体）

4. **ユーザー登録プロセス**:
   - 端末にサインイン後、初回セットアップ時にWindows Hello登録を促す
   - 顔認証または指紋をスキャン
   - バックアップPINを設定（6桁以上）

**トラブルシューティング**:
- **カメラが認識されない**: デバイスマネージャーでドライバー確認
- **顔認証が機能しない**: 照明条件の確認、メガネ・マスク着用の影響
- **指紋認証が機能しない**: 指紋リーダーのクリーニング、別の指で登録
- **PINを忘れた**: ヘルプデスクでリセット（Entra ID管理者権限で対応）

##### FIDO2 セキュリティキーの実装手順

**FIDO2キーの調達**:
- **数量**: 管理者数 + 共有端末利用者数 + 予備（10-20%）
- **推奨仕様**:
  - USB-AまたはUSB-C（端末の接続口に合わせる）
  - NFC対応（スマートフォン認証にも使える）
  - FIDO2認証
- **予算**: 1個あたり3,000-10,000円

**Entra IDでの有効化**:
1. **認証方法の有効化**:
   - Entra ID管理センター > セキュリティ > 認証方法
   - FIDO2セキュリティキー: 有効
   - 対象: すべてのユーザー（または特定グループ）

2. **ユーザー登録手順**:
   - https://aka.ms/mysecurityinfo にアクセス
   - 「方法の追加」→「セキュリティ キー」を選択
   - FIDO2キーを端末に接続
   - キーのPIN設定（初回のみ）
   - キーのボタンをタッチして登録完了

3. **複数キーの登録（推奨）**:
   - メインキー + 予備キーの2個登録を推奨
   - 予備キーは安全な場所に保管

**使用方法**:
- サインイン画面で「その他のオプション」→「セキュリティ キーでサインイン」
- キーを接続してボタンをタッチ
- キーのPIN入力
- 認証完了

2. **データアセスメントの実施**

#### 13.4 Insider Risk Management - Risky AI usageポリシーテンプレート
**目的**: 教職員の不適切なAI利用を検知する
**概要**: A5に含まれるInsider Risk Managementの「Risky AI usage」テンプレートを活用します。

##### Risky AI usage ポリシーテンプレートとは
- **定義**: 生成AIツールへの不適切なデータ入力・利用を検知するポリシー
- **検知対象の行動**:
  - 大量の機密ファイルをAIツールにアップロード
  - 児童生徒の個人情報を含むテキストをAIツールに入力
  - 退職予定者による大量のAI利用
  - 深夜・休日の異常なAI利用

##### リスク指標（Indicators）の設定
- **データ流出指標**:
  - 秘密度ラベル「高度要配慮個人情報」を含むファイルのAIツールへのアップロード
  - 一定量以上のテキストデータのコピー＆ペースト
  - 児童生徒氏名を含むプロンプトの入力

- **行動異常指標**:
  - 通常と異なる時間帯のAI利用
  - 過去の平均を大幅に上回るAI利用頻度

##### アダプティブ保護（Adaptive Protection）との連携
- **定義**: ユーザーのリスクレベルに応じて、DLPポリシーを自動調整
- **仕組み**:
  1. Insider Risk ManagementがユーザーをHigh/Medium/Lowリスクに分類
  2. Highリスクユーザーには、より厳格なDLPポリシーを自動適用
  3. AIツールへのアクセスを制限

**シナリオ**: 退職予定の教職員がChatGPTに大量の児童生徒情報を入力

#### 13.6 Microsoft Copilot for Microsoft 365 の安全な利用
**目的**: Microsoft Copilotを安全に展開し、児童生徒情報を保護する
**概要**: Copilotは強力なツールですが、適切な設定なしでは情報漏洩のリスクがあります。

**目的**: SharePointでの過剰共有を検出・制限する

- **過剰共有とは**:

- **SharePoint Advanced Managementの機能**:
  - 過剰共有サイトの自動検出
  - 「全社公開」設定の制限
  - 外部共有の制御

- **実装手順**:
  1. SharePoint Advanced Management の有効化（A5に含まれる）
  2. 過剰共有ポリシーの設定
  3. 既存の過剰共有サイトの修正

##### Copilot監査ログの活用

  - 秘密度ラベルの情報
  - アクセス日時・ユーザー

- **監査ログの確認方法**:
  - Microsoft Purview コンプライアンスポータル
  - 統合監査ログ検索
  - eDiscoveryでのキーワード検索

##### Copilot利用のベストプラクティス（教育委員会向け）

  - Copilotの仕組み（アクセス権に基づく動作）

  - 各段階で利用状況を監視・評価

#### 13.7 Data Lifecycle Management による不要データの削除

##### Data Lifecycle Managementとは
- **定義**: データの保存期間を管理し、不要になったデータを自動削除
- **A5での利用可否**: A5に含まれる

##### 教育委員会での活用
- **保存期間の定義**:
  - 卒業生の成績情報: 卒業後5年保存、その後削除
  - 指導要録: 法定保存期間に従う
  - 一時的な連絡文書: 1年後削除

- **保持ラベル（Retention Labels）の設定**:
  - ラベル: 「成績情報 - 5年保存」
  - 自動適用: 成績情報を含むファイルに自動適用

##### AIツールへの過剰露出防止

- **対策**: Data Lifecycle Managementで保存期間を過ぎたデータを自動削除
- **効果**: Copilotがアクセスできるデータの範囲を限定

#### 13.8 Priva Privacy Risk Management による個人データの過剰露出検知

#### 16.3 Microsoft Secure Score の活用

**目的**: セキュリティ態勢を可視化・改善する

##### Microsoft Secure Score とは

**Secure Scoreの概要**:
- Microsoftが提供するセキュリティ態勢の可視化ツール
- 0～100%のスコアで組織のセキュリティレベルを数値化
- セキュリティ設定の実装状況を自動評価
- 改善アクションを優先度付きで提示
- **無料で利用可能**（Microsoft 365 E3/A3以上）

**Secure Scoreが評価する領域**:
1. **ID（Identity）**: 35ポイント
   - MFA、条件付きアクセス、Identity Protection
2. **デバイス（Device）**: 25ポイント
   - Intune登録、コンプライアンスポリシー、Defender for Endpoint
3. **データ（Data）**: 20ポイント
   - Information Protection、DLP、暗号化
4. **アプリ（Apps）**: 15ポイント
   - Defender for Office 365、Defender for Cloud Apps
5. **インフラ（Infrastructure）**: 5ポイント
   - 特権アクセス管理、PIM

##### Secure Score の見方

**スコアの構成要素**:

```
現在のスコア: 45% (225ポイント / 500ポイント)
├─ 達成済み: 225ポイント（実装済みの対策）
├─ 計画中: 150ポイント（計画済みだが未実装）
└─ 未対応: 125ポイント（対応していない項目）
```

**スコアの意味**:
- **70%以上**: 優良（多くの企業・教育機関の目標）
- **50-70%**: 標準的（基本的な対策は実施済み）
- **30-50%**: 改善が必要（重要な対策が不足）
- **30%未満**: 危険（早急な対策が必要）

**教育機関の平均スコア**:
- 🚨 **日本の教育機関平均: 約35-40%**（一般企業より低い）
- 🎯 **目標: 60%以上**（A5導入後6か月以内）
- 🎯 **理想: 70%以上**（A5導入後12か月以内）

##### スコア向上を妨げる要因と対策

**よくある課題と解決策**:

**課題1: スコアが上がらない**
- 原因: 改善アクション実施後に「完了」マークを付けていない
- 対策: 実装後、Secure Score画面で「実装済み」をクリック
- 反映時間: 24-48時間

**課題2: 実装できない改善アクションがある**
- 原因: 教育現場の運用と合わない（例: 全デバイスの暗号化必須等）
- 対策: 「リスク受容」として記録し、代替策を実施
- 手順: 改善アクション → ... → 「リスクを受容」

**課題3: スコアは上がったがインシデントが減らない**
- 原因: ポイント稼ぎに走り、本質的な対策が抜けている
- 対策: インシデント発生箇所の改善アクションを優先
- 例: ID侵害が多い → ID関連アクション（MFA、Identity Protection）を最優先

**課題4: 改善アクションが多すぎて何から手を付けるべきか分からない**
- 原因: 100以上の改善アクションがリストされる
- 対策: 本セクションの「Top 10」を優先実施
- フィルター: 「推奨アクション」タブを使用

##### Secure Score と他のセキュリティ指標の関連

**KPIダッシュボード例**:

| 指標 | 現在値 | 目標値 | 関連Secure Scoreアクション |
|------|--------|--------|---------------------------|
| Secure Score | 67% | 70% | 全般 |
| MFA有効率 | 95% | 100% | MFA必須化（+15pt） |
| デバイス登録率 | 100% | 100% | Intune登録（+10pt） |
| コンプライアンス準拠率 | 98% | 100% | コンプライアンスポリシー（+12pt） |
| アカウント侵害インシデント | 0件/月 | 0件/月 | Identity Protection（+18pt） |
| マルウェア検知件数 | 2件/月 | 0件/月 | Defender for Endpoint（+15pt） |
| DLP違反件数 | 5件/月 | 3件/月 | DLPポリシー（+12pt） |

**改善の可視化**:
- Secure Scoreは「入力」指標（対策の実装状況）
- インシデント件数は「出力」指標（セキュリティ効果）
- 両方を追跡することで、対策の有効性を検証

##### まとめ: Secure Score を活用した継続的改善

**Secure Score活用の3つのポイント**:

1. **スコアそのものが目的ではない**
   - スコア向上は手段、目的は「セキュリティリスクの低減」
   - インシデント件数、侵害検知時間、復旧時間も併せて追跡

2. **優先順位を明確にする**
   - 影響度（ポイント）と実装難易度のバランス
   - 教育現場の実情に合わない対策は無理に実施しない
   - 本セクションのTop 10を参考に段階的実施

3. **組織全体で取り組む**
   - セキュリティ担当者だけでなく、管理職・教職員の理解と協力が必要
   - 四半期レポートで経営層に報告し、リソース確保
   - スコア向上を組織目標（KPI）に設定

## 執筆上の注意事項

### 技術的な正確性
- Microsoft 365 A5 for Educationで実際に利用可能な機能のみを記載
- スクリーンショットは最新のポータルUIを使用
- 構成手順は教育委員会のICT担当者でも実施できるレベルで記載
- 専門用語は必ず平易な言葉で補足説明

### 読者（教育委員会）への配慮
- 教育現場の文脈で解説（一般企業向けの説明を避ける）
- 児童生徒の個人情報保護を最優先事項として強調
- 限られた予算・人員での実装を前提とした現実的な提案
- 教育長・校長等の意思決定者にも理解できる平易な表現
- 教職員の負担を考慮した段階的展開アプローチ

### 教育機関特有の配慮
- 個人情報保護法・教育情報セキュリティポリシーガイドラインへの準拠
- 児童生徒の個人情報（成績・健康情報・家庭環境等）の特別な保護
- 学校現場の業務フロー（学期・長期休業等）を考慮した展開計画
- 保護者・地域への説明責任
- 教職員の働き方改革との両立

### 構成上の工夫
- 各章の冒頭に「この章で学ぶこと」「対象読者」を明示
- 各章の末尾に「まとめ」「チェックリスト」「次章への導入」を記載
- 重要なポイントは「重要」「注意」「教育現場のポイント」ボックスで強調
- 実装手順は画面キャプチャ付きで番号付きリストで明確に
- 用語解説は初出時に必ず行い、巻末用語集にも収録

### Zenn特有の機能活用
- メッセージブロックで重要な注意事項・教育現場特有の注意点を強調
- アコーディオンで詳細な設定手順・技術的な補足を格納（読み飛ばし可能に）
- リンクカードでMicrosoft公式ドキュメント・文科省ガイドラインを参照
- Mermaid図でアーキテクチャ・処理フロー・組織体制を視覚化
- 表を活用した比較・チェックリスト

### 実務での使いやすさ
- 各章を独立して読めるようにする（辞書的な使い方にも対応）
- チェックリストを豊富に用意（導入・運用の実務で使える）
- トラブルシューティングを充実させる
- 教職員向け説明資料のテンプレートを提供
