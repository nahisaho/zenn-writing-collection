# Microsoft 365 A5に含まれる30以上の製品を体系的に理解する

Microsoft 365 A5 for Educationには、30以上のセキュリティ製品とコンプライアンス製品が含まれています。しかし、これらの製品が「どのように連携してゼロトラストを実現するのか」を理解している教育委員会は多くありません。

本章では、A5に含まれる製品群を5つの領域に分類し、それぞれの役割とゼロトラストアーキテクチャにおける位置付けを明確にします。

# 3.1 Microsoft 365 A5 for Education ライセンス概要

## A5 for Educationの構成要素

Microsoft 365 A5 for Educationは、以下の3つの主要コンポーネントから構成されています。

### 1. Office 365 A5

**含まれるアプリケーション**:
- Word、Excel、PowerPoint、Outlook、Teams、OneNote
- Exchange Online（メールボックス100GB）
- SharePoint Online（1TB + ユーザーあたり10GB）
- OneDrive for Business（ユーザーあたり1TB）
- Microsoft Stream（動画配信）

### 2. Windows 11 Enterprise A5

**含まれる機能**:
- Windows 11 Education（Enterprise相当）
- Windows Autopilot（端末展開の自動化）
- Windows Update for Business（更新管理）
- Universal Print（クラウド印刷）

### 3. Enterprise Mobility + Security A5（EMS A5）

**含まれるセキュリティ製品**:
- Microsoft Entra ID P2（旧Azure AD Premium P2）
- Microsoft Intune（モバイルデバイス管理）
- Microsoft Defender for Endpoint P2（エンドポイント保護）
- Microsoft Purview Information Protection（旧Azure Information Protection P2）

### 4. Microsoft 365 A5セキュリティ・コンプライアンス機能

**含まれる高度な機能**:
- Microsoft Defender for Office 365 Plan 2（メール・コラボレーション保護）
- Microsoft Defender for Cloud Apps（クラウドアプリ保護）
- Microsoft Purview（情報保護・コンプライアンス）
- Advanced eDiscovery（電子証拠開示）

## A3とA5の主要な違い

### A3に含まれる機能（基本レベル）

| 領域 | A3の機能 | 制限事項 |
|------|----------|----------|
| **ID管理** | Entra ID P1 | リスクベース認証不可、PIM不可 |
| **条件付きアクセス** | 基本的な条件のみ | 場所・デバイスプラットフォームのみ |
| **情報保護** | 秘密度ラベル（手動） | 自動適用不可、Endpoint DLP不可 |
| **DLP** | Exchange/SharePoint/Teams | エンドポイント（USB等）は対象外 |
| **脅威対策** | Defender for Office 365 P1 | 自動調査不可、攻撃シミュレーション不可 |
| **エンドポイント保護** | Defender Antivirus | EDR（高度な脅威検知）不可 |

### A5で追加される機能（ゼロトラストに必須）

| 領域 | A5の追加機能 | ゼロトラストへの貢献 |
|------|--------------|---------------------|
| **ID管理** | Entra ID P2 | Identity Protection、PIM、高度なCA |
| **条件付きアクセス** | リスクベース制御 | 不審なサインインの自動ブロック |
| **情報保護** | 秘密度ラベル自動適用 | 児童生徒情報の自動検出・保護 |
| **DLP** | Endpoint DLP | USB持ち出し、印刷、スクショの制御 |
| **脅威対策** | Defender for Office 365 P2 | 自動調査、攻撃シミュレーション訓練 |
| **エンドポイント保護** | Defender for Endpoint P2 | EDR、脅威ハンティング |
| **内部脅威対策** | Insider Risk Management | 退職時の情報持ち出し検知 |
| **クラウドアプリ保護** | Defender for Cloud Apps | シャドーIT検知、セッション制御 |

## 教職員用と児童生徒用ライセンスの違い

### 教職員用ライセンス（必須: A5）

**対象者**:
- 教育委員会職員
- 学校教職員（教員、事務職員、管理職）
- 非常勤講師（校務システムアクセスが必要な場合）

**A5が必要な理由**:
- 児童生徒の個人情報（成績、指導要録、家庭環境等）を扱う
- 情報漏洩・アカウント侵害のリスクが高い
- 文部科学省ガイドラインの厳格なセキュリティ要件
- 管理者権限を持つユーザーの厳格な管理が必要

### 児童生徒用ライセンス（A3で十分な場合が多い）

**対象者**:
- 小学生、中学生、高校生

**A3で十分なケース**:
- 学習目的のみ（Teams、OneNote、Word/Excel/PowerPoint）
- 個人情報を扱わない
- 管理者権限を持たない

**A5が必要になるケース**:
- 高校生が研究で機密性の高いデータを扱う
- 生徒会活動で個人情報を扱う
- プログラミング教育で高度なセキュリティ機能が必要

:::message
**推奨ライセンス割り当て**:
- **教職員**: Microsoft 365 A5 for Education（全員）
- **児童生徒**: Microsoft 365 A3 for Education（基本）+ 必要に応じてA5

本書では、教職員向けのゼロトラスト実装に焦点を当てます。
:::

:::message alert
**Student Use Benefitの機能制限**:

児童生徒用のA5ライセンスには「Student Use Benefit」が適用され、一部の機能に制限があります。

**制限がある機能**:
- **Defender for Office 365**: Plan 1相当の機能のみ（Plan 2の自動調査・修復、Threat Explorerは利用不可）
- **Defender for Endpoint**: 一部の高度な機能に制限あり

**教職員には必ずフルのA5ライセンスを割り当ててください**。児童生徒の個人情報を扱う教職員には、Student Use Benefitではなく、フル機能のA5が必要です。
:::

## ライセンス割り当ての考え方

### 校務用と学習用の管理方法

文部科学省ガイドラインでは「校務系システムと学習系システムの分離」が求められています。Microsoft 365でこれを実現する方法は、主に2つのアプローチがあります。

**アプローチ1: アカウント分離型**

校務用と学習用で別々のアカウントを作成:

- **校務用アカウント（教職員専用）**:
  - ドメイン: `@board.city-example.ed.jp`（教育委員会ドメイン）
  - ライセンス: Microsoft 365 A5 for Education
  - 用途: 校務支援システム、成績管理、個人情報を含むデータ
  - セキュリティ: 厳格（MFA必須、条件付きアクセス、DLP、監視）

- **学習用アカウント（教職員・児童生徒）**:
  - ドメイン: `@school.city-example.ed.jp`（学校ドメイン）
  - ライセンス: Microsoft 365 A3 for Education
  - 用途: 授業、Teams会議、課題提出、協働学習
  - セキュリティ: 基本的な保護（年齢に応じた制限）

**メリット**: セキュリティポリシーの設計が明確、校務と学習の完全な分離
**デメリット**: 教職員が2つのアカウントを使い分ける必要がある、管理コストの増加

**アプローチ2: 単一アカウント型**

教職員は1つのアカウントで校務と学習の両方を実施:

- **教職員アカウント**:
  - ライセンス: Microsoft 365 A5 for Education
  - 用途: 校務と学習の両方
  - セキュリティ: 条件付きアクセスとDLPで、アプリケーションやデータの種類に応じた制御

**メリット**: 教職員の利便性が高い、管理が単純
**デメリット**: セキュリティポリシーの設計が複雑、誤操作のリスク

:::message
**本書の前提**: 本書では、アプローチ2（単一アカウント型）を前提に解説します。教職員の利便性を重視しつつ、条件付きアクセスやDLPポリシーで校務データと学習データを適切に保護する設計を示します。アプローチ1（アカウント分離型）を採用する場合も、本書で解説するセキュリティ機能は同様に適用できます。
:::

## アドオンライセンスとの関係

Microsoft 365 A5には、ほとんどのセキュリティ機能が含まれていますが、一部の高度な機能は追加ライセンスが必要です。

### A5に含まれる機能（追加費用なし）

- Microsoft Defender for Endpoint P2
- Microsoft Defender for Office 365 Plan 2
- Microsoft Defender for Cloud Apps
- **Microsoft Defender for Identity**（オンプレミスActive Directory保護）
- Microsoft Purview（Information Protection、DLP、Insider Risk Management）
- Advanced eDiscovery
- Audit (Premium)（1年保持）

### 追加ライセンスが必要な機能

| 製品 | 用途 | 教育機関での必要性 |
|------|------|-------------------|
| **10-year audit log retention** | 監査ログの10年保持 | ★★★★☆（個人情報保護条例対応） |
| **Microsoft Purview Data Lifecycle Management** | データの自動削除・アーカイブ | ★★☆☆☆（大規模校のみ） |
| **Microsoft Priva** | プライバシー管理の高度な自動化 | ★☆☆☆☆（現時点では不要） |

:::message
**教育委員会の判断指針**:
- **Defender for Identity**: A5に含まれています。オンプレミスActive Directoryを使用するハイブリッド環境で有効化してください
- **10年監査ログ保持**: 自治体の個人情報保護条例で長期保管が要求される場合は、アドオンライセンスの購入を検討してください

ほとんどの教育委員会では、Microsoft 365 A5のみで必要なゼロトラスト機能をカバーできます。
:::

# 3.2 ID管理・アクセス制御製品群

ID管理は、ゼロトラストアーキテクチャの中核です。Microsoft 365 A5には、Entra ID P2を中心とした強力なID管理・アクセス制御製品が含まれています。

## Microsoft Entra ID P2（旧 Azure AD Premium P2）

### 概要

Microsoft Entra ID P2は、クラウド型のID・アクセス管理サービスです。教職員のアカウント、認証、アクセス制御を一元管理します。

### A3（Entra ID P1）との違い

| 機能 | Entra ID P1（A3） | Entra ID P2（A5） |
|------|------------------|------------------|
| **基本的なID管理** | ○ | ○ |
| **MFA** | ○（基本的な方法） | ○（高度な方法） |
| **条件付きアクセス** | ○（場所・デバイスのみ） | ○（リスクベース含む） |
| **セルフサービスパスワードリセット** | ○ | ○ |
| **Identity Protection** | ✗ | ○（リスク検知・自動対応） |
| **Privileged Identity Management（PIM）** | ✗ | ○（管理者権限のJIT） |
| **アクセスレビュー** | ✗ | ○（権限の定期見直し） |
| **Entra ID Governance** | 一部 | 完全 |

### 教育機関でのEntra ID P2の役割

**1. すべての教職員IDを一元管理**

従来の課題:
- オンプレミスActive Directoryで管理
- クラウドサービスごとに異なるID
- パスワード管理の煩雑さ

Entra ID P2による解決:
- クラウド型の一元管理
- シングルサインオン（SSO）で各種サービスに1つのIDでアクセス
- パスワードレス認証（Windows Hello、FIDO2）への移行

**2. リスクベース認証（Identity Protection）**

通常のサインイン:
```
教職員A: 学校のPCから、勤務時間内にサインイン
→ リスク: 低
→ 対応: MFAのみで許可
```

不審なサインイン:
```
教職員A: 海外のIPアドレスから、深夜にサインイン
→ リスク: 高
→ 対応: パスワード変更を要求、または自動ブロック
```

**3. 管理者権限の適切な管理（PIM）**

従来の問題:
- 管理者に永続的な権限を付与
- 不要な権限の放置
- 権限の不正利用リスク

PIMによる解決:
- 必要な時だけ管理者権限を有効化（Just-In-Time）
- 承認プロセスの導入
- すべての管理操作を監査ログに記録

## Conditional Access（条件付きアクセス）

### 概要

条件付きアクセスは、「誰が」「どこから」「どのデバイスで」「どのアプリに」アクセスするかに応じて、アクセス可否や追加の認証を要求する仕組みです。

### ゼロトラストにおける役割

条件付きアクセスは、ゼロトラストの原則「明示的な検証」を実現する中核技術です。

**検証する要素**:
1. **ユーザー**: 誰がアクセスしているか
2. **場所**: どこからアクセスしているか（IP、国）
3. **デバイス**: 管理された端末か、コンプライアンス準拠か
4. **アプリ**: 何にアクセスしようとしているか
5. **リスク**: サインインリスク、ユーザーリスク

### 教育機関での実装例

**ポリシー1: 校務支援システムへのアクセス**

```
条件:
- アプリ: 校務支援システム
- ユーザー: 全教職員

制御:
- MFA必須
- 管理されたデバイスのみ許可
- 日本国外からのアクセスをブロック
```

**ポリシー2: 管理者アカウントの保護**

```
条件:
- ユーザー: 管理者ロール
- アプリ: すべて

制御:
- MFA必須
- 教育委員会ネットワークからのみ許可
- サインインリスクが「高」の場合ブロック
```

**ポリシー3: BYODデバイスからのアクセス制限**

```
条件:
- デバイス: 非管理デバイス
- アプリ: すべて

制御:
- Webブラウザのみ許可（アプリダウンロード不可）
- ファイルダウンロード禁止
- アクセス頻度の監視
```

## Multi-Factor Authentication（多要素認証、MFA）

### MFAの重要性

パスワードのみの認証は、フィッシング攻撃で簡単に突破されます。MFAを有効にすると、アカウント侵害のリスクが**99.9%減少**します（Microsoft調べ）。

### A5で利用可能なMFA方法

| 方法 | 利便性 | セキュリティ | 教育機関での推奨度 |
|------|--------|------------|------------------|
| **Microsoft Authenticatorアプリ（番号の一致）** | ★★★★☆ | ★★★★★ | ★★★★★（最推奨） |
| **FIDO2セキュリティキー** | ★★★★★ | ★★★★★ | ★★★★☆（管理者向け） |
| **Windows Hello for Business** | ★★★★★ | ★★★★★ | ★★★★★（端末配布済みなら最適） |
| **SMS/音声通話** | ★★★☆☆ | ★★☆☆☆ | ★☆☆☆☆（非推奨） |

:::message alert
**重要**: SMS/音声通話によるMFAは、SIMスワップ攻撃で突破される可能性があります。Microsoft Authenticatorアプリ、またはWindows Hello for Businessの使用を強く推奨します。
:::

### 教育機関での展開アプローチ

**フェーズ1: 管理者への展開（1か月）**

- 対象: 教育委員会のシステム管理者、学校管理職
- 方法: Microsoft Authenticatorアプリ + FIDO2セキュリティキー（バックアップ）
- サポート: 1対1での設定支援

**フェーズ2: 全教職員への展開（3か月）**

- 対象: すべての教職員
- 方法: Microsoft Authenticatorアプリ
- サポート: 説明会、マニュアル、ヘルプデスク

**フェーズ3: パスワードレス認証への移行（6〜12か月）**

- Windows Hello for Businessの展開
- FIDO2セキュリティキーの配布（希望者）
- パスワード入力の削減

## Privileged Identity Management（PIM）

### PIMとは

Privileged Identity Management（PIM）は、管理者権限を「必要な時だけ有効化する」仕組みです。永続的な管理者権限の付与を避け、権限の不正利用や侵害時の被害を最小化します。

### 従来の管理者権限の問題

**永続的な権限付与のリスク**:

```
シナリオ: 教育委員会の情報担当者Aさんに「全体管理者」権限を付与

リスク:
- Aさんのアカウントが侵害された場合、攻撃者も全体管理者権限を取得
- Aさんが日常業務で管理者権限を使い続ける（不要な場面でも）
- 退職時に権限削除を忘れる
- 権限の不正利用（内部不正）
```

### PIMによる解決

**Just-In-Time（JIT）アクセス**:

```
1. 通常時: Aさんは一般ユーザー権限のみ

2. 管理作業が必要になった時:
   - Aさんが「全体管理者」権限を要求
   - 承認者（教育長または情報セキュリティ責任者）が承認
   - 権限が8時間だけ有効化

3. 8時間後: 自動的に一般ユーザー権限に戻る

4. すべての操作が監査ログに記録
```

### 教育機関でのPIM実装例

**対象ロール**:
- 全体管理者（Global Administrator）
- Exchange管理者
- SharePoint管理者
- Intune管理者
- セキュリティ管理者

**設定例**:

| ロール | 有効化時間 | 承認 | MFA | 理由記入 |
|--------|----------|------|-----|---------|
| **全体管理者** | 最大8時間 | 必須 | 必須 | 必須 |
| **Exchange管理者** | 最大4時間 | 必須 | 必須 | 必須 |
| **Intune管理者** | 最大8時間 | 不要 | 必須 | 必須 |

## Identity Protection

### Identity Protectionとは

Identity Protectionは、Microsoftの脅威インテリジェンスを活用し、不審なサインインやアカウント侵害のリスクを自動検知する機能です。

### 検知するリスク

**サインインリスク（リアルタイム）**:
- 匿名IPアドレスからのサインイン
- 通常と異なる場所からのサインイン（Impossible Travel）
- マルウェア感染したデバイスからのサインイン
- 漏洩した認証情報の使用

**ユーザーリスク（累積）**:
- ダークウェブで漏洩した認証情報
- 過去の異常なサインインパターン
- 他のMicrosoft顧客で検知された脅威インテリジェンス

### リスクレベルと自動対応

| リスクレベル | 検知例 | 自動対応（推奨） |
|------------|--------|----------------|
| **低** | はじめての場所からのサインイン | MFAを要求 |
| **中** | 匿名IPアドレスからのサインイン | MFAを要求 + 通知 |
| **高** | 漏洩した認証情報の使用 | パスワード変更を強制 + 管理者に通知 |

### 教育機関での実装例

**条件付きアクセスとの連携**:

```
ポリシー: サインインリスクベースの制御

条件:
- サインインリスク: 中以上

制御:
- MFAを要求
- リスクが高の場合: アクセスをブロック + 管理者に通知
```

**自動修復の設定**:

```
ユーザーリスクポリシー:

条件:
- ユーザーリスク: 高

制御:
- パスワード変更を強制
- 管理者に通知（セキュリティ担当者）
- アカウントを一時的に無効化（オプション）
```

## Identity Governance

### Identity Governanceとは

Identity Governanceは、「誰が」「どのリソースに」「どの権限で」アクセスできるかを管理し、定期的に見直す仕組みです。

### 主要機能

**1. アクセスレビュー**

定期的に、付与された権限が適切かどうかを確認:

```
四半期ごとのレビュー:

対象:
- 校務支援システムへのアクセス権
- 管理者ロール
- 機密情報へのアクセス権

レビュー担当者:
- 直属の上司
- 情報セキュリティ責任者

アクション:
- 不要な権限を自動削除
- 承認されなかった権限を削除
```

**2. エンタイトルメント管理**

アクセス権の要求・承認プロセスを自動化:

```
例: 新任教職員のオンボーディング

1. 人事部門が新任教職員を登録
2. 自動的に基本アクセス権を付与（メール、Teams、OneDrive）
3. 校務支援システムへのアクセスは上司の承認が必要
4. 承認後、自動的にアクセス権を付与
5. 期限付きアクセス（例: 1年後に自動失効）
```

**3. ライフサイクル管理**

教職員の異動・退職時のアカウント管理を自動化:

```
退職時の自動処理:

1. 人事システムで「退職」ステータスに変更
2. 自動的にアカウントを無効化（退職日）
3. 30日後にすべてのアクセス権を削除
4. 90日後にアカウントを削除（データは別途保管）
```

# 3.3 デバイス管理・保護製品群

校務用端末のセキュリティは、児童生徒の個人情報保護に直結します。Microsoft 365 A5には、端末の統合管理と高度な脅威対策機能が含まれています。

## Microsoft Intune

### Intuneとは

Microsoft Intuneは、Windows、iOS、Android、macOSデバイスを一元管理するクラウド型MDM（モバイルデバイス管理）/MAM（モバイルアプリ管理）サービスです。

### ゼロトラストにおける役割

デバイスを「信頼できる状態」に保つことで、条件付きアクセスの「デバイスコンプライアンス」条件を満たします。

**デバイスコンプライアンスの例**:
- OSが最新バージョンに更新されている
- ウイルス対策ソフトが有効
- BitLockerでディスクが暗号化されている
- デバイスが脱獄（Jailbreak）されていない

### 教育機関でのIntune実装内容

**1. デバイス登録**

```
Windows Autopilotによる自動登録:

1. ベンダーからデバイスを購入時にAutopilotプロファイル登録
2. 教職員が初回起動時にEntra IDでサインイン
3. 自動的にIntuneに登録、設定が適用される
4. 手動設定作業なし（ゼロタッチ展開）
```

**2. コンプライアンスポリシー**

| 設定項目 | 要件 | 非準拠時の対応 |
|---------|------|--------------|
| **OSバージョン** | Windows 11 22H2以降 | 30日以内に更新、更新しない場合アクセスブロック |
| **ウイルス対策** | Defender有効、定義ファイル最新 | 即座にアクセスブロック |
| **暗号化** | BitLocker有効 | 7日以内に有効化、しない場合アクセスブロック |
| **ファイアウォール** | 有効 | 即座にアクセスブロック |
| **パスワード** | 複雑さの要件を満たす | 次回サインイン時に変更要求 |

**3. 構成プロファイル**

教育委員会の標準設定を一括展開:

- Wi-Fi設定（校務ネットワークへの自動接続）
- VPN設定（教育委員会ネットワークへの接続）
- メール設定（Exchange Onlineの自動構成）
- ブラウザ設定（信頼済みサイト、ポップアップブロック例外）
- プリンター設定（Universal Print）

**4. アプリケーション展開**

必要なアプリを自動インストール:

- Microsoft 365 Apps（Word、Excel等）
- 校務支援システムクライアント
- PDF閲覧ソフト
- セキュリティソフト（Defender以外に追加する場合）

**5. セキュリティベースライン**

Microsoftが推奨するセキュリティ設定を一括適用:

- Windows Defender Firewall設定
- BitLocker暗号化設定
- ローカル管理者権限の制限
- USBデバイスの制限（DLP連携）

## Microsoft Defender for Endpoint P2

### Defender for Endpointとは

Microsoft Defender for Endpoint P2は、エンドポイント（PC、スマートフォン、タブレット）に対する高度な脅威検知・対応（EDR: Endpoint Detection and Response）機能を提供します。

### A3（Defender Antivirus）との違い

| 機能 | Defender Antivirus（A3） | Defender for Endpoint P2（A5） |
|------|------------------------|------------------------------|
| **ウイルス検知** | ○（シグネチャベース） | ○（AI活用） |
| **リアルタイム保護** | ○ | ○ |
| **自動更新** | ○ | ○ |
| **EDR（高度な脅威検知）** | ✗ | ○（行動分析） |
| **自動調査・修復** | ✗ | ○ |
| **脅威ハンティング** | ✗ | ○ |
| **攻撃面の削減** | 一部 | ○（ASR規則） |
| **デバイス隔離** | ✗ | ○（リモート隔離） |

### 教育機関での脅威対策

**1. ランサムウェア対策**

ランサムウェアは、教育機関への攻撃の中でもっとも被害が大きい脅威です。

**Defender for Endpoint P2の対策**:

```
検知:
- ファイルの大量暗号化を検知（行動分析）
- ランサムウェア特有の動作パターンを識別

対応:
1. 該当デバイスを自動的にネットワークから隔離
2. セキュリティ担当者に即座にアラート
3. 暗号化される前のファイルをOneDriveで復元
4. 攻撃の詳細を自動調査
```

**2. フィッシング攻撃後のマルウェア検知**

```
シナリオ:
教職員がフィッシングメールの添付ファイル（悪意のあるExcel）を開いた

Defender for Endpointの対応:
1. Excelファイルが不審なPowerShellコマンドを実行しようとする動作を検知
2. 実行を自動的にブロック
3. ファイルをクラウドサンドボックスで詳細分析
4. マルウェアと判定し、該当ファイルを隔離
5. セキュリティ担当者に通知
```

**3. 攻撃面の削減（ASR規則）**

Attack Surface Reduction（ASR）規則で、一般的な攻撃手法を事前にブロック:

| ASR規則 | 内容 | 教育機関での効果 |
|---------|------|----------------|
| **Office製品からの実行可能ファイル作成をブロック** | Word/ExcelマクロからEXE作成を防止 | マクロを使ったマルウェア配布を防止 |
| **Officeアプリの子プロセス作成をブロック** | Word/ExcelからPowerShell実行を防止 | フィッシングメール経由の攻撃を防止 |
| **資格情報の窃取をブロック** | lsass.exeへのアクセスをブロック | パスワード窃取ツールを無効化 |
| **USBから実行可能ファイルの起動をブロック** | USB経由のマルウェア実行を防止 | 外部デバイス経由の感染を防止 |

## Windows Autopilot

### Windows Autopilotとは

Windows Autopilotは、新しいデバイスの初期設定を自動化し、教育委員会の標準設定を適用する仕組みです。

### 従来のデバイス展開の課題

**手動セットアップの問題**:

```
1. デバイスを開封
2. Windows初期セットアップを手動実行
3. Windowsアップデートを適用（数時間）
4. ドメイン参加（オンプレミスAD）または Entra ID参加
5. セキュリティソフトをインストール
6. 必要なアプリをインストール
7. Wi-Fi、VPN、プリンター設定を手動構成

→ 1台あたり2〜4時間の作業、設定ミスのリスク
```

### Windows Autopilotによる自動化

**ゼロタッチ展開**:

```
1. ベンダーに Autopilot 登録を依頼（購入時）
2. デバイスが教育委員会に配送される
3. 教職員が初回起動時に Entra ID でサインイン
4. 自動的に設定が適用される:
   - Intuneに登録
   - コンプライアンスポリシー適用
   - アプリ自動インストール
   - Wi-Fi、VPN、メール設定
5. 10〜30分で使用可能

→ IT管理者の作業時間ゼロ、設定の一貫性確保
```

### 教育機関でのAutopilot展開シナリオ

**シナリオ1: 新規端末の一括配布**

```
状況: 100台の新規Windows PCを教職員に配布

Autopilot手順:
1. ベンダーにAutopilot登録を依頼（CSV形式のハードウェアIDを提供）
2. Intune管理センターでAutopilotプロファイルを作成
   - デバイス名: 自動（例: EDU-W11-00001）
   - ユーザー割り当て: 初回サインインユーザーに割り当て
   - プライバシー設定、リージョン、キーボード設定
3. デバイスを各学校に配送
4. 教職員が初回起動、Entra IDでサインイン
5. 自動的にすべての設定が適用される
```

**シナリオ2: 故障時の端末交換**

```
状況: 教職員Aの端末が故障、代替機を提供

Autopilot手順:
1. 代替機を用意（事前にAutopilot登録済み）
2. 教職員Aが初回サインイン
3. 自動的に以前と同じ設定が適用される
4. OneDriveからファイルを復元
5. 10分で業務再開可能
```

## BitLocker管理

### BitLockerとは

BitLockerは、Windowsのディスク暗号化機能です。端末の紛失・盗難時に、第三者がデータを読み取ることを防ぎます。

### 教育機関でのBitLocker必須化

**文部科学省ガイドラインの要件**:

> 「校務用端末には、ディスク全体を暗号化する機能を導入すること」

**Intuneによる一括管理**:

```
BitLocker設定の展開:

1. Intuneでエンドポイント保護プロファイル作成
2. BitLocker設定:
   - 暗号化方式: XTS-AES 256ビット
   - 起動認証: TPM + PIN（オプション）
   - 回復キーの保管: Entra IDに自動バックアップ
3. すべてのWindows 11端末に適用

結果:
- 自動的にディスク暗号化が有効化
- 端末紛失時、回復キーをEntra IDから取得可能
```

### 端末紛失時の対応フロー

```
1. 教職員から端末紛失の報告
2. IT管理者がIntuneで該当デバイスを特定
3. リモートワイプ（全データ消去）を実行
4. Entra IDから回復キーを取得（端末が見つかった場合に備えて）
5. 新しい端末をAutopilotで展開
6. OneDriveからファイルを復元

→ データ漏洩なし、業務への影響を最小化
```

# 3.4 情報保護・コンプライアンス製品群

児童生徒の個人情報保護は、教育委員会の最重要課題です。Microsoft 365 A5には、Microsoft Purviewを中心とした包括的な情報保護・コンプライアンス機能が含まれています。

## Microsoft Purview Information Protection

### Information Protectionとは

Microsoft Purview Information Protectionは、データの機密性に応じて「秘密度ラベル」を付与し、暗号化・アクセス制御・透かし表示などの保護を自動適用する仕組みです。

### 秘密度ラベルの例

| ラベル | 対象データ | 保護設定 |
|--------|----------|---------|
| **公開** | 一般的な業務連絡、公開資料 | 保護なし |
| **内部** | 内部文書、会議資料 | 外部共有禁止 |
| **機密** | 成績情報、指導要録、家庭環境調査 | 暗号化、外部共有禁止、透かし表示 |
| **高機密** | 児童虐待関連、要保護児童情報 | 暗号化、外部共有禁止、印刷禁止、コピー禁止、アクセス記録 |

### 自動ラベル付けの仕組み

**A3との違い**:
- **A3**: 秘密度ラベルの手動適用のみ（ユーザーが選択）
- **A5**: 秘密度ラベルの自動適用（AIが内容を分析して自動分類）

**自動ラベル付けの例**:

```
1. トレーニング可能な分類子で「成績表」パターンを学習
2. 新しいExcelファイルが作成される
3. Information Protectionが内容を分析:
   - 「氏名」「国語」「算数」「評価」などの列を検出
   - 「成績表」パターンに一致と判定
4. 自動的に「機密」ラベルを適用
5. 暗号化、外部共有禁止、透かし「機密」を表示
```

**Exact Data Match（EDM）の活用**:

```
1. 児童生徒の氏名・学籍番号のマスターデータをアップロード
2. ファイルにこれらの情報が含まれているかを正確に検知
3. 含まれている場合、自動的に「機密」ラベルを適用
```

### 暗号化の仕組み

**ラベル適用時の動作**:

```
1. 「機密」ラベルが適用される
2. Azure Rights Management（Azure RMS）で暗号化
3. アクセス権の設定:
   - 作成者: すべての権限
   - 同じ学校の教職員: 閲覧・編集可能
   - 外部ユーザー: アクセス不可
4. ファイルがメールで外部送信されても、外部ユーザーは開けない
5. ラベルとアクセス権はファイルに埋め込まれる（ファイルを移動しても保護は維持）
```

## Data Loss Prevention（DLP）

### DLPとは

Data Loss Prevention（DLP）は、機密情報の意図しない共有・外部送信・USB持ち出しを自動的に検知・ブロックする機能です。

### A3とA5のDLP機能比較

| 対象場所 | A3 | A5 |
|---------|----|----|
| **Exchange Online（メール）** | ○ | ○ |
| **SharePoint Online** | ○ | ○ |
| **OneDrive for Business** | ○ | ○ |
| **Microsoft Teams** | ○ | ○ |
| **エンドポイント（Windows/Mac）** | ✗ | ○（Endpoint DLP） |
| **オンプレミス** | ✗ | ○（オプション） |

### Endpoint DLPの重要性

**A3で防げない情報漏洩**:

```
教職員が成績情報ファイルを開く
→ USBメモリにコピー
→ A3では検知・ブロックできない（Exchange、SharePoint等のクラウドサービス外の操作）
```

**A5（Endpoint DLP）で防げる**:

```
教職員が成績情報ファイル（「機密」ラベル付き）を開く
→ USBメモリにコピーしようとする
→ Endpoint DLPが検知・ブロック
→ 「このファイルはUSBデバイスにコピーできません」と表示
→ 操作ログを記録、管理者に通知
```

### 教育機関でのDLPポリシー例

**ポリシー1: 児童生徒の個人情報の外部送信防止**

```
条件:
- 内容に個人情報（氏名、学籍番号、住所等）が含まれる
- または「機密」「高機密」ラベルが付与されている

アクション:
- 外部メールアドレスへの送信をブロック
- 個人のGmail、Yahoo!メールへの送信をブロック
- 外部共有リンクの作成をブロック
- ユーザーに警告を表示
- 管理者に通知
```

**ポリシー2: USBデバイスへの書き込み制限**

```
条件:
- 「機密」または「高機密」ラベルが付与されたファイル

アクション:
- USBデバイスへのコピーをブロック
- 印刷を制限（承認が必要）
- スクリーンショットをブロック
- クラウドストレージアプリ（Dropbox等）へのアップロードをブロック
```

**ポリシー3: 許可されていないクラウドサービスへのアップロード防止**

```
条件:
- すべてのファイル

アクション:
- Google Drive、Dropbox、Box等の個人クラウドストレージへのアップロードをブロック
- 業務で利用する例外サービスを許可リストに登録
```

## Insider Risk Management

### Insider Risk Managementとは

Insider Risk Managementは、内部不正や意図しない情報漏洩のリスクがある行動パターンを検知し、早期に対処する機能です。

### A3にはない機能（A5専用）

Insider Risk Managementは、A5専用の機能です。教育機関での内部脅威対策に不可欠です。

### 検知する行動パターン

**1. 退職予定者の情報持ち出し**

```
シナリオ:
- 人事システムで教職員Aの退職が登録される（退職日: 30日後）
- 退職登録後、教職員Aの行動に変化:
  - 過去にアクセスしたことのないSharePointフォルダを閲覧
  - 大量のファイルをOneDriveにダウンロード（過去30日間の10倍）
  - 私的メールアドレス(Gmail)にファイルを送信しようとする

Insider Risk Managementの対応:
1. リスクスコアを自動的に上昇
2. セキュリティ担当者にアラート
3. 詳細な操作ログを表示
4. 必要に応じてアクセス権を制限、上司に通知
```

**2. 機密情報への異常なアクセス**

```
シナリオ:
- 教職員Bが通常アクセスしないフォルダ（他学年の成績情報）を閲覧
- 短時間に大量のファイルを開く
- 勤務時間外に機密情報にアクセス

Insider Risk Managementの対応:
1. 異常なアクセスパターンを検知
2. リスクスコアを上昇
3. セキュリティ担当者にアラート
4. 行動の継続を監視
```

**3. データ流出の兆候**

```
シナリオ:
- 教職員Cが個人のクラウドストレージに大量のファイルをアップロード
- または、大量の印刷を実行
- または、USBデバイスに頻繁にファイルをコピー

Insider Risk Managementの対応:
1. データ流出の可能性を検知
2. 即座にアラート
3. DLPポリシーと連携してブロック
```

### プライバシー保護との両立

**匿名化による調査**:

```
初期段階:
- アラートは「ユーザー1」「ユーザー2」と匿名表示
- リスクスコアと行動パターンのみ表示

調査が必要と判断した場合:
- セキュリティ管理者が承認
- 実名を開示
- 詳細な操作ログを確認
```

## eDiscovery（電子証拠開示）

### eDiscoveryとは

eDiscoveryは、訴訟や内部調査の際に、関連するメール・ファイル・Teams会話を検索・保全・エクスポートする機能です。

### A3とA5の違い

| **基本的な検索** | ○ | ○ |
| **法的情報保留** | ○ | ○ |
| **エクスポート** | ○ | ○ |
| **AI支援レビュー** | ✗ | ○（関連性予測） |
| **会話スレッド分析** | ✗ | ○ |
| **重複削除** | ✗ | ○ |
| **監査ログの高度な検索** | ✗ | ○ |

### 教育機関でのeDiscovery活用例

**シナリオ1: ハラスメント調査**

```
状況: ハラスメントの申し立て、関連するメール・Teams会話を調査

eDiscoveryの手順:
1. 調査ケースを作成
2. 関係者のメールボックス・OneDrive・Teamsを法的情報保留
3. キーワード検索（関係者名、特定の言葉）

6. 調査担当者がレビュー

```

**シナリオ2: 情報漏洩インシデント調査**

```
状況: 児童生徒の個人情報が外部に漏洩、経緯を調査

eDiscoveryの手順:
1. 該当ファイルの作成者・アクセス者を特定
2. 関係者のメール・OneDrive・SharePointアクセスログを検索
3. ファイルがいつ、誰に、どのように共有されたかを追跡
4. 外部送信されたメール、共有リンクを特定
5. 調査結果をレポートとしてエクスポート
```

## 監査ログ（Audit Log）

### 監査ログとは

監査ログは、Microsoft 365内のすべてのユーザー操作・管理者操作を記録する機能です。個人情報保護法、自治体の情報セキュリティ条例への対応に不可欠です。

### A3とA5の違い

| 項目 | A3（Audit Standard） | A5（Audit Premium） |
|------|----|----|
| **監査ログの保持期間** | 180日（デフォルト）※1 | 1年（デフォルト）、最大10年※2 |
| **高度な監査イベント** | 一部 | すべて（メールアクセス、ファイルアクセス等） |
| **高速検索** | 標準 | 高速 |
| **長期保持ポリシー** | ✗ | ○（カスタマイズ可能） |

※1 2023年10月17日以降に作成された監査ログは180日保持。それ以前のログは90日保持。
※2 Exchange、SharePoint、OneDrive、Entra IDのログを1年間自動保持。10年保持には「10-year audit log retention」アドオンライセンスが必要。

### 監査ログで記録される操作

**ユーザー操作**:
- ファイルのアクセス、ダウンロード、削除
- メールの送受信、削除
- SharePointでの共有設定変更
- Teamsでのファイル共有、会話

**管理者操作**:
- ユーザーアカウントの作成・削除
- 権限の変更
- セキュリティ設定の変更
- DLPポリシーの変更

### 個人情報保護条例への対応

多くの自治体の個人情報保護条例では、「個人情報へのアクセス記録を保管すること」が要求されています。

**A5のAudit (Premium)による対応**:

```
要件: 個人情報へのアクセスログを10年間保管

A5の設定:
1. Audit (Premium)を有効化（A5ライセンスで自動的に有効）
2. 10年保持が必要な場合:
   - 「10-year audit log retention」アドオンライセンスを購入
   - 監査ログ保持ポリシーを作成し、10年保持を設定
3. 保持ポリシーの適用:
   - SharePoint、OneDrive、Exchange、Entra IDのアクセスログを対象
4. 定期的なログのエクスポートと外部バックアップ（推奨）

結果:
- 「誰が」「いつ」「どのファイルに」アクセスしたかを10年間追跡可能
- 個人情報保護条例に準拠
```

:::message alert
**重要**: 10年間の監査ログ保持には、Microsoft 365 A5に加えて「10-year audit log retention」アドオンライセンスが必要です。A5のデフォルトは1年保持です。長期保管要件がある場合は、追加ライセンスの予算を確保してください。
:::

# 3.5 脅威対策・監視製品群

教育機関は、フィッシング攻撃、ランサムウェア、マルウェアの標的になりやすい組織です。Microsoft 365 A5には、Microsoft Defenderブランドの統合脅威対策製品が含まれています。

## Microsoft Defender for Office 365 Plan 2

### Defender for Office 365とは

Microsoft Defender for Office 365は、メール・Teams・SharePoint・OneDriveにおける脅威（フィッシング、マルウェア、悪意のあるリンク等）を検知・ブロックする機能です。

### Plan 1（A3）とPlan 2（A5）の違い

| 機能 | Plan 1（A3） | Plan 2（A5） |
|------|------------|------------|
| **Safe Attachments（添付ファイル保護）** | ○ | ○ |
| **Safe Links（リンク保護）** | ○ | ○ |
| **スプーフィング対策** | ○ | ○ |
| **フィッシング対策ポリシー** | ○ | ○（高度） |
| **自動調査・修復（AIR）** | ✗ | ○ |
| **脅威ハンティング（Threat Explorer）** | ✗ | ○ |
| **攻撃シミュレーション訓練** | ✗ | ○ |
| **キャンペーンビュー** | ✗ | ○ |

### 自動調査・修復（AIR: Automated Investigation and Response）

**Plan 1では手動対応が必要**:

```
1. フィッシングメールが10人の教職員に配信される
2. セキュリティ担当者にアラート
3. 担当者が手動で各ユーザーのメールボックスを確認
4. 該当メールを手動で削除
5. 1〜2時間の作業時間
```

**Plan 2では自動対応**:

```
1. フィッシングメールが10人の教職員に配信される
2. Defender for Office 365が自動的にフィッシングと判定
3. 自動調査開始:
   - 同じ送信者からのメールを検索
   - 類似の件名・本文のメールを検索
   - メール内のリンクをクリックしたユーザーを特定
4. 自動修復:
   - すべてのメールボックスから該当メールを削除
   - リンクをクリックしたユーザーにパスワード変更を要求
   - 関連するメールを隔離
5. セキュリティ担当者に結果を報告

→ 5〜10分で完了、担当者の作業時間ゼロ
```

### 攻撃シミュレーション訓練

**教職員のセキュリティ意識向上に不可欠**:

```
攻撃シミュレーション訓練の実施:

1. Defender for Office 365で訓練キャンペーンを作成
   - テンプレート: 「偽の給与明細通知」「Amazonからの不審な購入通知」等
   - 対象: 全教職員
   - スケジュール: 毎月1回

2. 訓練メールを自動送信

3. 結果を自動集計:
   - メールを開いた人数
   - リンクをクリックした人数
   - 認証情報を入力した人数

4. クリックしたユーザーに即座にトレーニングを提供:
   - 「このメールはフィッシング訓練でした」
   - フィッシングの見分け方を学習

5. 管理者レポート:
   - 部署別のクリック率
   - リスクの高いユーザーの特定
   - 改善傾向の可視化
```

### Threat Explorer（脅威エクスプローラー）

**高度な脅威分析ツール**:

```
使用例: 特定の教職員を狙ったフィッシング攻撃の調査

1. Threat Explorerで「受信者: 教職員A」で検索
2. 過去30日間のメールを分析:
   - フィッシングと判定されたメール: 5件
   - マルウェア添付ファイル: 2件
   - スプーフィング: 3件
3. 攻撃の傾向を可視化:
   - 送信者のドメイン
   - 件名のパターン
   - リンク先のURL
4. 組織全体で同じ攻撃を検索
5. 予防策を実施（送信者ドメインをブロック等）
```

## Microsoft Defender for Cloud Apps

### Defender for Cloud Appsとは

Microsoft Defender for Cloud Apps（旧Cloud App Security）は、クラウドアプリケーションの使用状況を可視化し、シャドーIT検知、脅威対策、データ保護を提供するCASB（Cloud Access Security Broker）です。

### A3にはない機能（A5専用）

Defender for Cloud Appsは、A5専用の機能です。

### 主要機能

**1. シャドーITの検知**

教育委員会で許可されていないクラウドサービスの使用を検知:

```
検知例:
- 教職員が個人のDropboxアカウントに校務ファイルをアップロード
- 許可されていないファイル共有サービスの使用
- 私的なGoogle Driveへのアクセス

Defender for Cloud Appsの対応:
1. ネットワークログ（ファイアウォール、プロキシ）を分析
2. 使用されているクラウドアプリを一覧化
3. リスクスコアを表示（データ暗号化、コンプライアンス認証等に基づく）
4. 許可・ブロック・監視の判断を支援
```

**2. Microsoft 365の異常検知**

通常と異なるクラウドアプリの使用パターンを検知:

```
検知例:
- 教職員Aが過去にアクセスしたことのない国からSharePointにアクセス
- 短時間に大量のファイルをダウンロード
- 通常と異なる時間帯にアクセス

Defender for Cloud Appsの対応:
1. 機械学習で通常の行動パターンを学習
2. 異常を検知し、リスクスコアを上昇
3. セキュリティ担当者にアラート
4. 自動対応:
   - セッションを終了
   - アカウントを一時停止
   - MFAを再要求
```

**3. セッション制御（Conditional Access App Control）**

条件付きアクセスと連携し、リアルタイムでセッションを監視・制御:

```
ポリシー例: BYODデバイスからのアクセス制限

条件:
- デバイス: 非管理デバイス
- アプリ: SharePoint、OneDrive

制御:
1. セッション制御を有効化
2. ファイルのダウンロードを禁止
3. コピー&ペーストを禁止
4. 閲覧のみ許可
5. すべての操作をログに記録

結果:
- BYODデバイスから情報を持ち出せない
- 閲覧は可能（業務の柔軟性を維持）
```

**4. アプリの接続とAPI制御**

サードパーティアプリのMicrosoft 365へのアクセスを制御:

```
検知例:
- 許可されていないサードパーティアプリがMicrosoft 365にアクセス
- アプリが過剰な権限を要求（メール読み取り、ファイル削除等）

Defender for Cloud Appsの対応:
1. 接続されているすべてのアプリを一覧表示
2. 各アプリの権限を確認
3. リスクの高いアプリを検知
4. 管理者が承認していないアプリをブロック
```

## Microsoft Defenderポータル

### Defenderポータルとは

Microsoft Defenderポータル（https://security.microsoft.com）は、すべてのDefender製品を統合管理する画面です。

### 統合される製品

- Microsoft Defender for Endpoint（エンドポイント保護）
- Microsoft Defender for Office 365（メール・コラボレーション保護）
- Microsoft Defender for Cloud Apps（クラウドアプリ保護）
- Microsoft Defender for Identity（オンプレミスAD保護）※別途ライセンス
- Microsoft Entra ID Protection（ID保護）

### 主要機能

**1. インシデント管理**

複数の製品からのアラートを自動的に関連付け、1つのインシデントとして表示:

```
例: フィッシング攻撃のインシデント

関連アラート:
1. Defender for Office 365: フィッシングメール検知
2. Defender for Endpoint: メール内リンクをクリック後、マルウェアダウンロードを検知
3. Entra ID Protection: 不審なサインイン検知
4. Defender for Cloud Apps: 大量のファイルダウンロードを検知

Defenderポータルの対応:
- これらのアラートを1つのインシデントとして統合
- 攻撃のタイムラインを可視化
- 推奨される対応アクションを表示
- ワンクリックで自動修復
```

**2. 高度なハンティング（Advanced Hunting）**

KQLクエリで過去30日間のログを横断検索:

**例: 特定のファイルへのアクセス履歴を調査**

```kusto
CloudAppEvents
| where Timestamp > ago(30d)
| where FileName == "成績一覧.xlsx"
| project Timestamp, AccountDisplayName, IPAddress, ActionType
| order by Timestamp desc
```

**結果**: 誰が、いつ、どこから、このファイルにアクセスしたかを一覧表示

**3. セキュリティスコア（Microsoft Secure Score）**

組織のセキュリティ状況を0〜100点でスコア化し、改善アクションを提示:

```
セキュリティスコアの例:

現在のスコア: 65/100

改善アクション（優先度順）:
1. すべてのユーザーにMFAを要求（+15点）
2. 管理者アカウントにPIMを設定（+10点）
3. Defender for Endpointの攻撃面削減規則を有効化（+8点）
4. 秘密度ラベルの自動適用を設定（+7点）
5. 監査ログを10年間保持（+5点）

各アクションをクリック:
- 詳細な説明
- 設定手順へのリンク
- 影響を受けるユーザー数
```

**4. レポート**

定期的なセキュリティレポートを自動生成:

- 脅威分析レポート（検知された脅威の傾向）
- デバイスコンプライアンスレポート
- ID保護レポート（リスクの高いユーザー）
- データ保護レポート（DLPインシデント）

## Microsoft Secure Score

### Secure Scoreとは

Microsoft Secure Scoreは、組織のセキュリティ態勢を測定し、改善策を推奨するツールです。Defenderポータルに統合されています。

### スコア計算の仕組み

**スコア = (達成したポイント) / (達成可能な最大ポイント) × 100**

各改善アクションには、重要度に応じてポイントが割り当てられています。

### 教育委員会のセキュリティ成熟度の測定

| スコア | セキュリティレベル | 状態 |
|-------|---------------|------|
| **0〜30** | 非常に低い | 基本的なセキュリティ設定が未実施 |
| **31〜50** | 低い | 一部の設定のみ実施 |
| **51〜70** | 中程度 | 基本的な設定は完了、高度な機能は未設定 |
| **71〜85** | 高い | ゼロトラストの主要機能を実装済み |
| **86〜100** | 非常に高い | 高度なセキュリティ機能をすべて実装 |

### 改善アクションの優先順位

Secure Scoreは、各アクションに優先度を割り当てます。

**高優先度（すぐに実施すべき）**:
- すべてのユーザーにMFAを要求
- 管理者アカウントの保護
- レガシー認証のブロック
- デバイスのBitLocker暗号化

**中優先度（3〜6か月以内に実施）**:
- 秘密度ラベルの自動適用
- DLPポリシーの展開
- 攻撃シミュレーション訓練の実施

**低優先度（将来的に検討）**:
- 高度な監査ログ分析
- カスタムアラートルールの作成

# まとめ: A5製品群とゼロトラストの関係

本章では、Microsoft 365 A5 for Educationに含まれる30以上の製品を5つの領域に分類して解説しました。

## 5つの領域とゼロトラストの原則

| 領域 | 主要製品 | ゼロトラストへの貢献 |
|------|---------|---------------------|
| **ID管理・アクセス制御** | Entra ID P2、Conditional Access、MFA、PIM、Identity Protection | 「明示的な検証」「最小権限アクセス」を実現 |
| **デバイス管理・保護** | Intune、Defender for Endpoint、Autopilot、BitLocker | 「信頼できるデバイス」からのアクセスを保証 |
| **情報保護・コンプライアンス** | Information Protection、DLP、Insider Risk Management、eDiscovery | 「侵害の想定」「データ保護」を実現 |
| **脅威対策** | Defender for Office 365 Plan 2、Defender for Endpoint | 「侵害の想定」「継続的監視」を実現 |
| **統合監視** | Defenderポータル、Secure Score | 「継続的監視」「改善」を実現 |

## A3とA5の決定的な違い

教育委員会がゼロトラストを実現するには、A5が不可欠です。A3では以下の重要機能が欠けています。

- Identity Protection（リスクベース認証）
- Privileged Identity Management（管理者権限のJIT）
- 秘密度ラベルの自動適用
- Endpoint DLP（USB持ち出し防止）
- Insider Risk Management（内部脅威対策）
- Defender for Office 365 Plan 2（自動調査、攻撃シミュレーション）
- Defender for Endpoint P2（EDR、脅威ハンティング）
- Defender for Cloud Apps（シャドーIT検知）
