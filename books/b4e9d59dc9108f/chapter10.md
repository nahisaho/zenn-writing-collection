## この章で学べること
- 既存システムからZero Trust環境への段階的移行戦略
- 並行運用時のリスク管理と運用継続性の確保
- データ移行の完全性とセキュリティ要件の設定
- 切り戻し計画の策定と実行基準
- 180日間の標準移行スケジュールと管理体制

## なぜこの章が重要なのか
校務支援システムの移行は、教育機関の運営継続性に直結する。一度でも失敗すれば、児童生徒の成績管理、出席管理、保護者連絡など、学校運営の根幹が停止する。本章の要件を無視した移行は、必ず失敗する。あなたの判断一つで、数千人の教育活動が左右されることを忘れてはならない。

# 段階移行の必須要件

## 10.1 段階移行要件

### フェーズ1：準備期間（30日間）
移行を成功させるためには、準備期間で以下の要件を完全にクリアしなければならない。1つでも欠けていれば、移行は失敗に終わる。

#### 10.1.1 移行前システム監査
**要件**：現行システムの完全な棚卸しを実施すること

```yaml
監査対象:
  データ容量: 全テーブル行数とサイズ
  システム依存関係: 他システムとの連携状況
  ユーザーアカウント: 全アカウントの権限マッピング
  カスタマイズ内容: 独自機能と設定の洗い出し
  運用ルール: 現在の業務フローと承認経路

必須成果物:
  - システム構成図（完全版）
  - データ関連図（テーブル関係含む）
  - 業務フロー図（承認経路含む）
  - リスク評価書（移行時の影響度評価）
```

#### 10.1.2 Zero Trust環境構築
**要件**：本番環境と同一仕様のテスト環境を構築すること

移行テストで妥協は許されない。テスト環境が本番と1つでも異なれば、移行時に予期せぬトラブルが発生する。

```yaml
必須構築項目:
  Microsoft Entra ID:
    - 条件付きアクセスポリシー（本番同一設定）
    - 多要素認証設定（全ユーザー対象）
    - セキュリティベースライン（CIS準拠）

  Microsoft 365:
    - A3/A5ライセンス割り当て（本番同一構成）
    - Exchange Online保護設定
    - Teams設定とポリシー

  Microsoft Intune:
    - デバイスコンプライアンスポリシー
    - アプリケーション保護ポリシー
    - 自動展開プロファイル

検証項目:
  - 全業務シナリオでの動作確認
  - パフォーマンステスト（レスポンス時間測定）
  - セキュリティテスト（脆弱性スキャン）
```

### フェーズ2：移行実行期間（90日間）
この期間が移行の成否を決める。計画通りに進まなければ、直ちに切り戻しを実行せよ。

#### 10.2.1 部門別段階移行
**要件**：業務への影響を最小化する部門順序で移行すること

```yaml
移行順序（変更不可）:
  第1週: 情報システム部門（5-10名）
    理由: 技術的問題の早期発見と対応
    成功基準: 全業務システムへの正常アクセス

  第2-3週: 管理部門（教頭、事務）（20-30名）
    理由: 管理機能の動作確認
    成功基準: 成績処理、出席管理の正常動作

  第4-8週: 教職員（100-500名）
    理由: 段階的負荷テスト
    成功基準: ピーク時間のレスポンス維持

  第9-12週: 全職員完了
    理由: 運用安定化の確認
    成功基準: 99.5%の稼働率達成

各段階の必須チェックポイント:
  - 移行完了率100%の確認
  - システムレスポンス時間2秒以内
  - セキュリティログの正常性確認
  - ユーザー満足度調査80%以上
```

## 10.2 並行運用要件

### 10.2.1 デュアルシステム運用
**要件**：新旧システムの同期運用で完全性を保証すること

並行運用期間中のデータ不整合は、移行後の致命的な問題となる。1つのデータでも欠落すれば、成績処理に重大な影響が生じる。

```yaml
並行運用システム構成:
  旧システム:
    - 継続稼働（読み取り専用モード）
    - データバックアップ継続
    - 緊急時切り戻し準備

  新システム:
    - 全機能稼働
    - リアルタイム同期設定
    - 監視システム常時稼働

必須同期項目:
  マスタデータ:
    - 児童生徒情報（全項目）
    - 教職員情報（権限含む）
    - 学級・科目情報
    - 学事暦情報

  トランザクションデータ:
    - 成績データ（リアルタイム同期）
    - 出席データ（15分間隔同期）
    - 保護者連絡履歴（即座同期）
    - システム操作ログ（全記録）
```

#### 10.2.2 データ整合性検証
**要件**：毎日の整合性チェックで不整合ゼロを維持すること

```yaml
日次検証項目:
  データ件数チェック:
    - 全テーブルレコード数比較
    - 日次増分データ件数確認
    - 削除データの整合性確認

  データ内容チェック:
    - 成績データのハッシュ値比較
    - 個人情報の完全一致確認
    - 日時データの同期確認

不整合発生時の対応:
  軽微な不整合（10件未満）:
    - 即座の修正実行
    - 原因調査と対策実施

  重大な不整合（10件以上）:
    - 新システム停止
    - 切り戻し手順の実行準備
    - システム再点検の実施
```

## 10.3 データ移行要件

### 10.3.1 データ移行の完全性保証
**要件**：全データの100%移行と検証を実施すること

教育データの欠落は、児童生徒の将来に直接的な影響を与える。1つの成績データが失われれば、進路選択に重大な支障が生じる可能性がある。

```yaml
移行データ分類:
  最重要データ（欠落許容度0%）:
    - 児童生徒基本情報
    - 成績データ（過去3年分）
    - 出席記録（過去3年分）
    - 健康診断記録
    - 指導要録データ

  重要データ（欠落許容度0.01%）:
    - 保護者情報
    - 教職員情報
    - 時間割データ
    - 年間行事データ

  一般データ（欠落許容度0.1%）:
    - システム設定情報
    - 操作ログ（1年分）
    - 一時的なファイル

移行手順:
  1. データエクスポート（暗号化必須）
  2. データ変換（形式統一）
  3. データインポート（検証付き）
  4. 全件数チェック
  5. 抜き取りデータ詳細確認
```

#### 10.3.2 暗号化移行要件
**要件**：移行中のデータは必ずAES-256で暗号化すること

```yaml
暗号化要件:
  転送時暗号化:
    - TLS 1.3以上でのデータ転送
    - VPN接続必須
    - 証明書による認証

  保管時暗号化:
    - AES-256暗号化
    - キー管理システム（Azure Key Vault）
    - アクセスログ記録

データ消去要件:
  移行完了後:
    - 一時ファイルの完全削除
    - メモリダンプの削除
    - ログファイルの個人情報除去

  切り戻し時:
    - 新システムデータの完全削除
    - 暗号化キーの無効化
    - 復旧不可能な消去の実行
```

### 10.3.3 データ移行テスト
**要件**：本番移行前に3回の完全テストを実施すること

```yaml
テスト段階:
  第1回テスト（移行30日前）:
    - 全データ移行手順の確認
    - 所要時間の測定
    - 問題点の洗い出し

  第2回テスト（移行14日前）:
    - 改善後手順での再テスト
    - パフォーマンス最適化
    - 切り戻し手順のテスト

  第3回テスト（移行7日前）:
    - 本番同等環境での最終テスト
    - 全関係者による確認
    - Go/No-Go判定

合格基準:
  - データ移行完了率：100%
  - 移行時間：計画時間の80%以内
  - データ整合性：不整合0件
  - システム稼働率：99.9%以上
```

## 10.4 切り戻し要件

### 10.4.1 即座切り戻し基準
**要件**：以下の事象発生時は即座に切り戻しを実行すること

切り戻しの判断に迷いは許されない。児童生徒のデータが危険にさらされる可能性がある場合は、即座に旧システムに戻せ。

```yaml
即座切り戻し基準（判断猶予なし）:
  システム障害:
    - システム応答時間10秒超過が30分継続
    - データベース接続エラーが15分継続
    - 認証システム障害が5分継続

  セキュリティインシデント:
    - 不正アクセスの検知
    - データ改ざんの発見
    - マルウェア感染の確認
    - 個人情報漏洩の疑い

  データ不整合:
    - 成績データの不整合100件以上
    - 出席データの不整合500件以上
    - 児童生徒情報の不整合1件以上

切り戻し実行権限者:
  - 最高責任者（教育長）
  - 副責任者（情報システム部長）
  - 技術責任者（システム管理者）
```

#### 10.4.2 段階切り戻し手順
**要件**：30分以内に旧システムへの完全復旧を実現すること

```yaml
切り戻し手順（時系列）:
  0-5分: 緊急停止
    - 新システム全停止
    - ユーザーアクセス遮断
    - データ同期停止

  5-15分: 旧システム復旧
    - 旧システム稼働確認
    - データベース整合性チェック
    - ネットワーク接続確認

  15-25分: サービス再開
    - ユーザーアクセス復旧
    - 全機能動作確認
    - 緊急連絡の実施

  25-30分: 状況確認
    - 全部門への状況報告
    - データ損失チェック
    - 復旧完了宣言

切り戻し後の必須作業:
  - インシデントレポート作成（24時間以内）
  - 原因調査の開始（48時間以内）
  - 再移行計画の見直し（1週間以内）
  - 関係者への詳細報告（3日以内）
```

### 10.4.3 データ復旧要件
**要件**：切り戻し時のデータ損失を最小限に抑制すること

```yaml
データ復旧優先順位:
  最優先（15分以内復旧）:
    - 当日の成績入力データ
    - 当日の出席データ
    - 緊急連絡事項

  高優先（1時間以内復旧）:
    - 過去1週間の更新データ
    - 予定・行事データ
    - 保護者連絡履歴

  通常（24時間以内復旧）:
    - その他の更新データ
    - システム設定変更
    - 操作ログ

復旧手順:
  1. 最新バックアップからの復元
  2. トランザクションログの適用
  3. データ整合性の確認
  4. 差分データの手動投入
  5. 全データの検証
```

## 10.5 【工程表】標準移行スケジュール

### 移行全体工程（180日間）

```yaml
Phase 1: 準備期間（Day 1-30）
  Week 1-2: 現行システム調査
    - システム構成の完全把握
    - データ量・種別の調査
    - 業務フロー分析
    - リスクアセスメント

  Week 3-4: 移行環境構築
    - テスト環境構築
    - Zero Trust設定
    - 接続テスト実施
    - セキュリティ設定

Phase 2: テスト期間（Day 31-90）
  Week 5-8: 機能テスト
    - 全機能の動作確認
    - パフォーマンステスト
    - セキュリティテスト
    - 統合テスト

  Week 9-12: ユーザーテスト
    - 操作性確認
    - 業務フロー確認
    - 教職員研修実施
    - フィードバック収集

Phase 3: 移行実行（Day 91-150）
  Week 13-16: 段階移行開始
    - システム部門移行
    - 管理部門移行
    - 並行運用開始
    - 問題対応

  Week 17-21: 全面移行
    - 全教職員移行
    - データ同期確認
    - 運用監視強化
    - 切り戻し準備維持

Phase 4: 安定化期間（Day 151-180）
  Week 22-25: 運用安定化
    - 旧システム段階停止
    - 新システム最適化
    - 運用手順確立
    - 切り戻し解除準備

  Week 26: 移行完了
    - 旧システム完全停止
    - 移行完了宣言
    - 運用体制移行
    - プロジェクト終了
```

### 10.5.2 進捗管理要件

#### 週次進捗報告
**要件**：毎週金曜日17時に進捗状況を報告すること

```yaml
報告項目:
  進捗状況:
    - 計画に対する進捗率
    - 今週の完了作業
    - 来週の予定作業
    - 遅延リスクの有無

  品質状況:
    - テスト実施状況
    - 不具合発生・対応状況
    - 品質メトリクス
    - 改善提案事項

  リスク状況:
    - 新規リスクの識別
    - 既存リスクの状況変化
    - リスク対策の実施状況
    - エスカレーション事項

報告先:
  - 教育長（月次）
  - 情報システム部長（週次）
  - プロジェクトメンバー（週次）
  - 関係部門長（隔週）
```

#### 10.5.3 緊急時エスカレーション

```yaml
エスカレーション基準:
  レベル1（軽微）: 24時間で解決可能
    - 対象: プロジェクトマネージャー
    - 対応: 通常の問題解決プロセス

  レベル2（重大）: 計画への影響あり
    - 対象: 情報システム部長
    - 対応: 緊急対策会議開催

  レベル3（致命的）: 移行中止検討
    - 対象: 教育長
    - 対応: 緊急役員会議開催

連絡体制:
  平日日中（9:00-17:00）:
    - 電話: 15分以内応答
    - メール: 30分以内返信

  夜間・休日:
    - 緊急電話: 24時間対応
    - 緊急参集: 2時間以内
```

**移行の成功は、子どもたちの学習環境を守ることに直結する。**

この章で定めた要件に従わない移行は、必ず失敗に終わる。あなたの教育機関の情報システムを預かる責任の重さを忘れず、完璧な移行を実現せよ。妥協は子どもたちへの裏切りである。
