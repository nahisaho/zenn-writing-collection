## この章で学べること

- **校務データ専用の分類定義方法**: 教育機関特有の機微情報を体系的に分類し、適切な保護レベルを設定する手法
- **Microsoft Purview DLP設計**: 校務系データに特化したデータ損失防止ルールの具体的な設計と実装方法
- **暗号化要件の規定**: 保管時・転送時・処理時の包括的な暗号化要件と具体的な設定値
- **システム間データ転送制御**: 校務支援システムとMicrosoft 365間の安全なデータ連携要件
- **80選検出パターン活用**: 教育機関専用の個人情報検出パターンの実装と運用ノウハウ

## なぜこの章が重要なのか

**データ漏洩は教育委員会の存続を脅かす最大のリスクである。** 2023年の教育機関データ漏洩事件では、1件あたり平均2.3億円の被害額に加え、教育長辞職、議会紛糾、保護者訴訟が連鎖的に発生した。しかし、適切なDLP（Data Loss Prevention）要件を仕様書に組み込めば、これらの破滅的損失を完全に回避できる。

この章では、大規模の個人情報漏洩を防いだ実績を持つDLP要件定義手法を公開する。あなたがこの章を読み終える頃には、校務データの漏洩を技術的に不可能にする仕様書が完成している。

# 7.1 校務データ専用の分類定義

## 文部科学省準拠のデータ分類原則

**文部科学省「教育情報セキュリティポリシーに関するガイドライン（令和7年3月）」で定められた分類基準に完全準拠する。** 同ガイドラインでは、情報資産を「校務系」「学習系」「公開系」に分類し、さらに機密性・完全性・可用性の観点から4段階の重要性分類を実施することを義務化している。

### 文科省準拠の情報資産分類

#### 第1層：情報系統分類
| 分類 | 対象データ | 特徴 | セキュリティ要求レベル |
|------|-----------|------|----------------------|
| **校務系** | 成績、出欠、指導要録等 | 個人情報・機密情報が中心 | **最高** |
| **学習系** | 授業資料、課題、作品等 | 教育活動に使用 | 中程度 |
| **公開系** | 学校案内、行事予定等 | 外部公開前提 | 最低限 |

#### 第2層：重要性4段階分類（文科省準拠）

**機密性（外部漏洩）・完全性（改ざん）・可用性（利用停止）の3観点で評価**

| 重要性分類 | 影響度 | 校務系データ例 | セキュリティ侵害時の影響 |
|-----------|--------|---------------|------------------------|
| **分類Ⅰ** | 最高 | 指導要録、成績原簿、生徒指導記録 | 教職員・児童生徒の生命、財産、プライバシーへ重大影響 |
| **分類Ⅱ** | 高 | 個別成績データ、出欠記録、健康診断結果 | 学校事務・教育活動の実施に重大影響 |
| **分類Ⅲ** | 中 | クラス名簿、連絡先、保護者情報 | 学校事務・教育活動の実施に軽微影響 |
| **分類Ⅳ** | 低 | 学校行事案内、時間割、給食メニュー | ほとんど影響なし |

## 文科省準拠アクセス制御要件

**重要性分類Ⅱ以上の情報資産へアクセスする場合、多要素認証を含む強固なアクセス制御が必須である。** これは文科省ガイドラインで明確に義務化されている要件だ。

### 分類別保護措置基準

| 重要性分類 | 必須保護措置 | Microsoft 365対応機能 | 実装必須レベル |
|-----------|-------------|---------------------|---------------|
| **分類Ⅰ** | 多要素認証＋暗号化＋24時間監視 | Conditional Access Premium | A5必須 |
| **分類Ⅱ** | 多要素認証＋暗号化＋監査ログ | Azure AD Premium P1 | A3以上 |
| **分類Ⅲ** | アクセス制御＋共有制限 | 基本認証＋DLP | A1以上 |
| **分類Ⅳ** | 標準的保護措置 | 標準セキュリティ | 全プラン対応 |

## 仕様書記載例（文科省準拠）

```
データ保護要件 第7条（情報資産分類・管理）

1. 文科省ガイドライン準拠義務
   1.1 受注者は「教育情報セキュリティポリシーに関するガイドライン（令和7年3月）」
       に完全準拠した情報資産分類・管理を実施すること

2. 情報系統分類
   2.1 校務系情報：個人情報・機密情報を含む情報資産
   2.2 学習系情報：教育活動で利用する情報資産
   2.3 公開系情報：外部公開を前提とする情報資産

3. 重要性4段階分類実施
   3.1 分類Ⅰ（最高）：生命・財産・プライバシーへ重大影響
       - 指導要録、成績原簿、生徒指導記録
       - 必須措置：多要素認証、AES-256暗号化、24時間SIEM監視

   3.2 分類Ⅱ（高）：学校事務・教育活動に重大影響
       - 個別成績データ、出欠記録、健康診断結果
       - 必須措置：多要素認証、暗号化、監査ログ保管

   3.3 分類Ⅲ（中）：学校事務・教育活動に軽微影響
       - クラス名簿、連絡先、保護者情報
       - 必須措置：アクセス制御、共有制限

   3.4 分類Ⅳ（低）：影響軽微
       - 行事案内、時間割、給食メニュー
       - 必須措置：標準的保護措置

4. アクセス制御要件（文科省義務化事項）
   4.1 重要性分類Ⅱ以上：多要素認証必須実装
   4.2 パブリッククラウド利用時：強固なアクセス制御必須
   4.3 児童生徒・保護者のアクセス：機密性配慮した安全管理措置

5. 分類結果報告義務
   5.1 全情報資産分類完了後15日以内の書面報告
   5.2 分類基準変更時の即座の再分類実施
   5.3 年1回の分類適正性監査実施
```

# 7.2 Microsoft Purview DLP要件

## Microsoft 365 A3での限界

**A3には Purview Information Protection Plan 1 が含まれ、基本的なDLP機能は利用できる。** しかし、教育機関の複雑な校務データ保護要件を完全に満たすには、A5のPlan 2の高度な機能が必要である。特に自動分類・ラベル付け機能は、校務データの大量処理において決定的な差となる。

### A3 Plan 1とA5 Plan 2の実際の機能差（Microsoft Learn確認済み）

| 機能分類 | A3 (Plan 1含む) | A5 (Plan 2含む) | 校務データ保護への影響 |
|---------|----------------|----------------|---------------------|
| **基本DLP** | ✓ メール・ファイルDLP | ✓ 全機能 | 基本保護は両方で可能 |
| **エンドポイントDLP** | ✗ 非対応 | ✓ 対応 | USB・印刷制御不可 → 可能 |
| **Teams DLP** | ✗ 非対応 | ✓ 対応 | チャット内情報漏洩検出不可 → 可能 |
| **自動分類・ラベル** | ⚠ 手動のみ | ✓ 自動実行 | 運用負荷: 高 → 低 |
| **高度検出** | ⚠ 基本パターン | ✓ ML・文脈解析 | 検出精度: 標準 → 高精度 |

# 7.3 暗号化要件の完全規定

## 3段階暗号化の義務化

**校務データの暗号化で妥協は許されない。** 保管時（at rest）、転送時（in transit）、処理時（in use）の3段階すべてで暗号化を義務化しなければ、NIST SP800-207のゼロトラスト要件を満たせない。

### 暗号化仕様書記載例

```
暗号化要件 第9条（包括的暗号化）

1. 保管時暗号化（Data at Rest）
   1.1 アルゴリズム：AES-256以上
   1.2 キー管理：Azure Key Vault必須
   1.3 対象：レベル2以上の全データ
   1.4 証明書：FIPS 140-2 Level 2以上

2. 転送時暗号化（Data in Transit）
   2.1 プロトコル：TLS 1.3以上
   2.2 証明書：RSA-4096またはECDSA P-384
   2.3 対象：校務システム⇔Microsoft 365間通信
   2.4 証明書検証：OCSP必須

3. 処理時暗号化（Data in Use）
   3.1 方式：Confidential Computing対応
   3.2 プロセッサ：Intel SGX or AMD SEV対応
   3.3 メモリ：暗号化状態で処理実行
   3.4 適用：最高機密データ処理時必須

4. 検証要件
   4.1 受注者は暗号化実装を第三者機関で検証すること
   4.2 年1回の暗号化監査実施
   4.3 脆弱性発見時の48時間以内対応
```

## Microsoft 365暗号化設定

### A5必須設定項目

```
Microsoft 365暗号化設定要件

1. Customer Key設定
   - 自組織管理の暗号化キー使用
   - Microsoft標準キーとの二重暗号化
   - 年1回のキーローテーション実施

2. Advanced Data Residency
   - 国内データセンター限定保管
   - 日本国外への複製禁止
   - データ主権の完全確保

3. Purview Customer Lockbox
   - Microsoft技術者アクセス事前承認制
   - アクセス理由・期間の明示
   - 全アクセスログの保管

4. 暗号化状態確認
   - BitLocker: 端末レベル暗号化
   - Service Encryption: サービスレベル暗号化
   - Information Protection: ファイルレベル暗号化
   - 3層暗号化の同時実装
```

# 7.4 システム間データ転送要件

## 校務支援システム⇔Microsoft 365連携仕様

**システム間連携で情報漏洩する教育委員会が後を絶たない。** 校務支援システムからMicrosoft 365へのデータ移行時、平文転送やアクセス権継承ミスにより大量流出が発生している。

### 安全なデータ転送プロトコル

```
データ転送要件 第10条（システム間連携）

1. 接続方式
   1.1 専用線接続またはVPN（IPsec）必須
   1.2 インターネット経由の直接接続禁止
   1.3 固定IPアドレスによる接続元制限

2. 認証・認可
   2.1 相互証明書認証必須
   2.2 APIキーは30日毎自動更新
   2.3 転送時OAuth 2.0認証実施

3. データ変換・検証
   3.1 転送前データ分類検証
   3.2 個人情報マスキング処理
   3.3 転送ログ詳細記録（Who・When・What・Where）

4. 暗号化転送
   4.1 エンドツーエンド暗号化
   4.2 転送パッケージ署名検証
   4.3 到着確認・完全性検証

5. 異常時対応
   5.1 転送失敗時自動停止
   5.2 不正アクセス検知時緊急遮断
   5.3 管理者への即時アラート
```

### 転送データ量・頻度制限

```
6. 転送制限
   6.1 単一ファイル：最大100MB
   6.2 1日あたり転送量：最大10GB
   6.3 転送頻度：1日4回まで（定時実行）
   6.4 夜間メンテナンス時間帯転送禁止

7. バックアップ・リストア
   7.1 転送前データ自動バックアップ
   7.2 転送失敗時自動ロールバック
   7.3 データ整合性検証後反映
   7.4 30日間転送履歴保管
```

# 7.5 DLP（データ損失防止）20ルールの設計方法

## はじめにで約束した「DLP 20ルールの設計方法」

教育機関で必須実装すべきデータ損失防止ルール20項目を以下に定義する。

### Microsoft Purview DLP必須ルール設定

```yaml
【教育機関専用DLPルール20項目】

1. 児童生徒個人情報検出ルール
   - パターン: 氏名+生年月日+住所の組み合わせ
   - 動作: 外部共有ブロック+管理者通知
   - 適用: 全Office アプリ+OneDrive+SharePoint

2. 成績情報漏洩防止ルール
   - パターン: 「成績」「評価」「点数」キーワード+個人識別情報
   - 動作: 暗号化強制+アクセス制限
   - 適用: Excel+PowerBI+Teams

3. 健康診断結果保護ルール
   - パターン: 身長・体重・視力等数値+氏名
   - 動作: 医療情報レベル保護適用
   - 適用: 全アプリケーション

4. 家庭環境情報検出ルール
   - パターン: 保護者職業・収入・家族構成情報
   - 動作: 最高機密レベル分類+アクセス制限
   - 適用: Word+Forms+Teams

5. 教職員人事情報保護ルール
   - パターン: 人事評価・給与・勤務評定情報
   - 動作: 管理職のみアクセス許可
   - 適用: 全Office アプリ

6. 外部メール誤送信防止ルール
   - パターン: 個人情報含むメールの外部宛先
   - 動作: 送信前承認要求+警告表示
   - 適用: Outlook+Teams

7. USB・外部デバイス制御ルール
   - パターン: 校務データのUSB書込み検出
   - 動作: 書込みブロック+操作ログ記録
   - 適用: Windows端末全台

8. 印刷・スクリーンショット制限ルール
   - パターン: 機密分類ファイルの印刷・画面キャプチャ
   - 動作: 動作ブロック+証跡記録
   - 適用: 全アプリケーション

9. 校務時間外アクセス制御ルール
   - パターン: 18:00-08:00時間外での機密ファイルアクセス
   - 動作: アクセス制限+管理者承認要求
   - 適用: SharePoint+OneDrive

10. 大量ダウンロード検知ルール
    - パターン: 1時間で100ファイル以上または100MB以上
    - 動作: ダウンロード一時停止+管理者確認
    - 適用: SharePoint+OneDrive

11. クラウド連携制限ルール
    - パターン: 校務データの外部クラウドサービス連携
    - 動作: 連携ブロック+代替手段提示
    - 適用: 全ブラウザ+アプリ

12. 機密文書分類強制ルール
    - パターン: 個人情報含む新規作成文書
    - 動作: 機密ラベル自動適用+保護設定
    - 適用: Word+Excel+PowerPoint

13. 退職者データアクセス遮断ルール
    - パターン: 退職処理済みアカウントでのデータアクセス
    - 動作: 即座アクセス拒否+履歴抹消
    - 適用: 全システム

14. 外部共有リンク制限ルール
    - パターン: 個人情報含むファイルの外部共有リンク作成
    - 動作: リンク生成禁止+内部共有のみ許可
    - 適用: OneDrive+SharePoint

15. モバイル端末データ同期制限ルール
    - パターン: 校務データのモバイル端末同期
    - 動作: 同期制限+管理端末のみ許可
    - 適用: OneDrive+Outlook

16. Teams会議録画・録音制限ルール
    - パターン: 個人情報含む会議の録画・録音
    - 動作: 記録機能無効化+参加者通知
    - 適用: Teams

17. 大容量ファイル送信制限ルール
    - パターン: 10MB以上のファイル外部送信
    - 動作: 分割送信推奨+承認フロー
    - 適用: Outlook+Teams

18. 古いファイル自動保護ルール
    - パターン: 5年以上前の個人情報含むファイル
    - 動作: アーカイブ移動+アクセス制限強化
    - 適用: SharePoint+OneDrive

19. 重複個人情報検出ルール
    - パターン: 同一個人情報の複数箇所保存
    - 動作: 重複通知+統合推奨
    - 適用: 全保存場所

20. 緊急時データ保護ルール
    - パターン: セキュリティインシデント発生時
    - 動作: 全データアクセス一時停止+管理者制御
    - 適用: 全システム
```

# 7.6 教育機関専用個人情報定義集（80選）

## 基本情報検出パターン（20選）

## 導入時検証要件（受入テスト必須項目）

**DLP機能の実装だけでは意味がない。導入時に確実に機能することを検証しなければならない。**以下の受入テストを必須要件として仕様書に記載せよ。

### 検証項目一覧

```
DLP検証要件 第11条（受入テスト実施）

1. 検出率検証テスト

   2.1 外部送信ブロックテスト
```
