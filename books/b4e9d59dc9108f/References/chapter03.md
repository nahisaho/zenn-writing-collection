# NIST SP800-207 準拠データ保護の実現

Zero Trust Architecture において、「データが主たる保護対象」は根幹となる原則です。従来のネットワーク境界防御では、内部にいる限りデータへの自由なアクセスが可能でしたが、Zero Trust ではデータそのものを保護の中心に据え、どこからアクセスしても一貫したセキュリティを提供します。

教育機関では、校務支援システムで扱う教職員・保護者の個人情報、成績データ、人事情報など、極めて機密性の高いデータを適切に保護する必要があります。本章では、Microsoft 365 A3/A5 を活用し、NIST SP800-207 に準拠したデータ保護戦略を解説します。

## NIST Zero Trust データ保護の基本原則

### データ中心セキュリティの実現

Zero Trust では、従来の「ネットワーク境界内は安全」という前提を完全に放棄し、「データそのものが保護対象」という考え方に転換します。校務支援システムでは、データがどこに保存され、どこからアクセスされても、常に一貫したセキュリティが提供される必要があります。

**データを保護の中心に置く考え方**

- **データの価値に応じた分類**: 機密度・重要度による段階的保護
- **データライフサイクル全体の保護**: 作成・保存・共有・廃棄の全段階での一貫した保護
- **場所に依存しない保護**: オンプレミス・クラウド・モバイル・持ち帰り業務での統一保護
- **アクセス制御の統合**: データアクセス権とユーザー権限の動的連携

**暗号化による包括的保護**
- **保存時暗号化**: SharePoint、OneDrive、Exchange でのデータ保存時の自動暗号化
- **転送時暗号化**: すべての通信経路での TLS/SSL による暗号化保護
- **使用時暗号化**: アプリケーション使用中でのデータ保護継続
- **エンドツーエンド暗号化**: データ作成者から受信者まで一貫した暗号化

### 教育機関特有のデータ分類戦略

文部科学省の「教育情報セキュリティポリシーに関するガイドライン（令和7年3月）」では、情報漏洩・改ざん・利用不可の観点から情報資産を4段階に分類し、重要度に応じたセキュリティ対策を求めています。

**重要度分類Ⅰ（最高重要度）**
- **影響レベル**: 「極めて重大な影響」が生じる情報
- **セキュリティ要件**: 最高水準の暗号化・アクセス制御・監査証跡
- **対象データ例**:
  - 教職員の人事評価・懲戒・健康診断結果
  - 要配慮個人情報（障がい・疾病・家庭環境等）
  - 学校運営の機密事項（人事異動・予算策定・法的問題）

**重要度分類Ⅱ（高重要度）**
- **影響レベル**: 「重大な影響」が生じる情報
- **セキュリティ要件**: 多要素認証・強固なアクセス制御必須
- **対象データ例**:
  - 成績・通知表・進路指導記録
  - 教職員・保護者の個人情報
  - 学校経営・教育委員会連絡事項

**重要度分類Ⅲ（中重要度）**
- **影響レベル**: 「不利益」が生じる情報  
- **セキュリティ要件**: 基本的暗号化・アクセス管理
- **対象データ例**:
  - 出席記録・学習記録・指導案
  - 教材・カリキュラム・授業資料
  - 学校行事・会議資料・業務連絡

**重要度分類Ⅳ（低重要度）**
- **影響レベル**: 軽微な影響または影響なし
- **セキュリティ要件**: 標準的保護措置
- **対象データ例**:
  - 学校案内・ホームページ掲載情報
  - 一般配布資料・お知らせ・広報材料

:::message
**文部科学省ガイドライン準拠の重要性**

令和7年改訂版では、次世代校務DX環境への移行に向けた具体的要件が明記されています。

**法的要件への対応**
- 重要度分類Ⅱ以上：多要素認証・強固なアクセス制御が必須要件
- 暗号化消去機能：データ廃棄時の技術的安全管理措置強化
- 監査証跡：アクセス記録・操作履歴の完全保存・検索可能性

**実装上の配慮事項**
- 分類基準の明確化：各学校での判断基準統一・教職員への周知徹底
- 段階的実装：重要度の高いデータから優先的セキュリティ強化
- 継続的見直し：データ重要度・利用状況変化に応じた分類見直し
:::

**Zero Trust視点での分類活用**
- **動的分類**: アクセス状況・利用コンテキストに応じた動的重要度判定
- **統合管理**: Microsoft Purview による分類ラベルと文科省分類の連携
- **自動適用**: AI分析による自動分類・ラベル付けの精度向上
- **継続監視**: 分類変更・アクセスパターン変化の継続的監視

## A3/A5 でのデータ保護実現能力の差異

### A3 でのベーシックデータ保護戦略

A3 環境では、Microsoft Purview の基本機能を活用した標準的なデータ保護を実現できます。

**機密ラベルによる基本分類**
- **手動ラベル付け**: ユーザーによるデータ分類・ラベル付け
- **基本ポリシー適用**: ラベルに基づく共有制限・外部送信制御
- **視覚的マーキング**: ヘッダー・フッター・透かしによる機密度表示
- **基本的暗号化**: ラベル付きファイルの自動暗号化

**基本DLP（データ損失防止）機能**
- **定義済みテンプレート**: 一般的な個人情報・機密情報パターンの検出
- **メール・SharePoint・OneDrive**: 主要サービスでの流出防止
- **通知・ブロック**: 違反行為の検出と基本的な対処
- **レポート機能**: 基本的な違反状況・利用統計の確認

**標準暗号化機能**
- **サービス暗号化**: Microsoft 365サービスでの標準暗号化
- **メッセージ暗号化**: 基本的な外部メール送信時の暗号化
- **BitLocker統合**: Windows端末でのディスク暗号化連携
- **Transport Layer Security**: すべての通信での暗号化保護

**A3の制約と対処**
- **自動分類制限**: AI による自動分類機能なし → 手動分類ルールの徹底とトレーニング強化
- **エンドポイント保護不足**: デバイス上でのDLP機能制限 → デバイス管理ポリシーと物理的セキュリティで補完
- **高度分析機能なし**: AI駆動の異常検出不可 → 定期的な手動レビューとログ分析で補完
- **Customer Key 非対応**: 暗号化キー自主管理不可 → Microsoft 標準暗号化での運用

### A5 でのエンタープライズデータ保護戦略
 
A5 環境では、AI 駆動の高度な自動分類と包括的な保護機能を実現できます。

**AI駆動自動分類・ラベリング**
- **機械学習分析**: コンテンツ・コンテキスト分析による自動分類
- **トレーニング可能分類子**: 教育機関特有のデータパターン学習
- **自動ラベル適用**: 大量ファイルへの一括自動ラベル付け
- **継続的改善**: 分類精度の継続的向上と調整

**エンドポイントDLP（データ損失防止）**
- **デバイス上保護**: Windows、Mac、モバイルでのローカルファイル保護
- **USB・プリンタ制御**: 外部デバイスへのデータ転送制御
- **アプリケーション制御**: Webブラウザ、サードパーティアプリでの流出防止
- **リアルタイム監視**: デバイス上でのファイル操作リアルタイム制御

**通信コンプライアンス**
- **Teams・メール監視**: すべてのコミュニケーションでの包括的監視
- **不適切コンテンツ検出**: AI による機密情報・不適切発言の自動検出
- **コンテキスト分析**: 発言者・受信者・時間・場所を考慮した総合判断
- **自動エスカレーション**: 重要度に応じた管理者・担当者への自動通知

**高度暗号化・キー管理**
- **Customer Key**: 教育機関による暗号化キーの完全自主管理
- **Customer Lockbox**: Microsoft サポートアクセスの厳格制御
- **高度メッセージ暗号化**: より強固な外部共有時の保護
- **データ主権確保**: 暗号化・アクセス制御の完全な自主管理

## データ損失防止（DLP）によるZero Trust境界防御

### Zero Trust DLP 戦略の基本原則

従来のネットワーク境界防御では、「内部ネットワークにいる限り安全」という前提でしたが、Zero Trust DLPでは「データがどこにあっても、誰がアクセスしても一貫した保護」を実現します。

**データ自体の保護メカニズム**
- **コンテンツベース保護**: データの内容そのものを分析・保護
- **メタデータ活用**: ファイル作成者・アクセス履歴・編集状況の総合判断
- **動的ポリシー適用**: アクセス状況・リスクレベルに応じた動的制御
- **ゼロトラスト原則**: 内部ユーザーでも必要最小限のアクセスのみ許可

**コンテキスト分析による高度判断**
- **ユーザー行動分析**: 通常パターンからの逸脱検出
- **時間・場所分析**: 異常な時間帯・場所からのアクセス検出
- **デバイス信頼度**: アクセス元デバイスの管理状況・セキュリティレベル評価
- **データ機密度**: アクセス対象データの重要度・機密レベル考慮

### A3 での基本的DLP戦略

A3 環境では、定義済みのパターンマッチングによる基本的なDLP機能を活用します。

**コンテンツベース検出機能**
- **定義済みテンプレート活用**: 
  - 個人番号（マイナンバー）検出パターン
  - クレジットカード番号・銀行口座情報
  - 運転免許証・パスポート番号
  - 教育機関固有のID・コード体系
- **カスタムパターン作成**: 学校独自のデータ形式に対応
- **キーワード検出**: 機密文書・重要プロジェクト名等の検索
- **正規表現対応**: 複雑なデータパターンの柔軟な定義

**基本的流出経路での保護**
- **Exchange Online**: メール送信時の自動スキャン・制御
- **SharePoint Online**: ファイル共有・外部リンク作成時の制御
- **OneDrive for Business**: 個人ファイル共有時の監視・制限
- **Microsoft Teams**: チャット・ファイル添付での流出防止

**違反検出時の基本対処**
- **ユーザー通知**: 違反行為の即座通知とガイダンス表示
- **管理者アラート**: 重要違反の管理者・担当者への即座通知
- **アクション制御**: 送信ブロック・アクセス制限・隔離処理
- **証跡記録**: 違反内容・対処結果の詳細ログ保存

**A3でのDLP制約と運用対処**

:::message alert
**A3 DLP 制約への現実的対処戦略**

A3では高度なDLP機能に制約があるため、運用的対策との組み合わせが重要です。

**エンドポイント保護の制約**
- **制約**: Windows・Mac・モバイル端末でのローカルファイル制御不可
- **対処**: デバイス管理ポリシーによる USB制御・アプリケーション制限・定期監査

**AI分析機能の不足**
- **制約**: 機械学習による異常パターン検出・自動改善なし  
- **対処**: 定期的な手動ログレビュー・パターン見直し・教職員教育強化

**高度分類機能の制限**
- **制約**: コンテキスト分析・自動分類の機能制限
- **対処**: 手動分類ルールの明確化・定期的な分類見直し・教職員トレーニング

**統合監視の制約** 
- **制約**: Teams・サードパーティアプリでの包括監視不可
- **対処**: 利用アプリケーション制限・定期的利用状況確認・セキュリティ教育
:::

:::message alert
**A3 環境で発生しうるセキュリティインシデント事例**

A3の機能制約により、以下のようなデータ保護インシデントが発生する可能性があります。実際の教育現場で想定されるリスクシナリオを理解し、適切な対策を講じることが重要です。

**事例1: 大量ファイルの自動分類ミスによる機密情報流出**
- **発生状況**: 年度末の大量成績処理時、手動分類の負荷により機密度の低い分類でファイル処理、外部共有フォルダに誤配置
- **A3制約**: AI自動分類機能がないため、大量ファイル処理時の手動分類ミス・負荷による分類品質低下を防止できない
- **被害規模**: 複数学年の成績・評価・進路指導記録（約2,000名分）が外部委託業者に流出
- **法的影響**: 個人情報保護法違反、教育委員会への報告義務、保護者への謝罪・対応が必要

**事例2: Teamsチャットでの機密情報共有による漏洩**
- **発生状況**: 教員がTeamsチャットで保護者対応の相談中、要配慮個人情報を含む詳細情報を誤って外部ゲストユーザーを含むチャットに投稿
- **A3制約**: Communications DLP (Teams chat)機能がないため、チャット・メッセージ内容の機密情報検出・制御ができない
- **被害規模**: 児童生徒の家庭環境・健康状況・学習困難等の要配慮個人情報が外部に流出
- **経営影響**: 差別・偏見につながる情報流出、保護者との信頼関係破綻、人権問題への発展

**事例3: 機密度分類ミスによる外部共有事故**
- **発生状況**: 保護者対応記録を「一般文書」として誤分類、外部委託業者との共有フォルダに誤アップロード
- **A3制約**: AI自動分類機能がないため、手動分類での人為的ミスを技術的に防止できない
- **被害規模**: 要配慮個人情報を含む家庭環境・健康情報等が委託業者に流出
- **社会的影響**: 差別・偏見につながる機微な情報の流出、深刻な人権問題への発展

**事例4: 退職教職員による過去データアクセス継続**
- **発生状況**: 退職した教員のアカウント無効化遅延により、退職後も校務システムにアクセス可能な状態が継続
- **A3制約**: 高度な監視・異常検出機能不足により、異常なアクセスパターンを自動検知できない
- **被害規模**: 過去担当クラスの児童生徒情報・同僚教員情報への不正アクセスが数カ月継続
- **組織的影響**: 内部統制の欠陥露呈、信頼関係の破綻、再発防止体制の根本的見直しが必要

**事例5: 第三者アプリケーション連携による情報漏洩**
- **発生状況**: 教育効果測定のため外部学習アプリと連携、データ提供範囲の理解不足により想定外の情報が流出
- **A3制約**: 統合監視・サードパーティアプリ制御機能不足により、外部連携でのデータ移転を適切に制御・監視できない
- **被害規模**: 学習履歴・行動パターン・成績推移等の詳細な教育データが外部企業に蓄積
- **長期的影響**: 児童生徒の将来的な不利益（就職・進学での差別）、教育データの商業利用

これらの事例は、A3環境の技術的制約を理解し、運用面での補完対策を強化することの重要性を示しています。完全な技術的防御が困難な場合でも、適切な運用ルール・教育・監視体制により、リスクを大幅に低減することが可能です。
:::

:::message
**A3での運用によるリスク軽減戦略**

技術的制約があるA3環境でも、体系的な運用対策により効果的なデータ保護を実現できます。

**組織的対策による予防**
- **分類ルール標準化**: 文部科学省4段階分類に基づく明確な判断基準作成・全教職員への徹底周知
- **ダブルチェック体制**: 重要度分類Ⅰ・Ⅱのファイル処理時の複数人確認制度導入
- **定期的分類見直し**: 四半期毎の分類状況監査・不適切分類の早期発見・修正
- **アクセス権限管理**: 最小権限原則に基づく定期的な権限見直し・不要アクセス権の即座削除

**教育・啓発による人的リスク軽減**
- **実例ベース研修**: 実際のインシデント事例を活用した具体的リスク理解促進
- **情報取扱い実習**: 手動分類・共有設定・Teams利用での実践的スキル向上
- **チェックリスト活用**: ファイル共有前・メッセージ送信前の確認項目標準化
- **継続的意識向上**: 月次セキュリティ通信・成功事例共有での継続的教育

**技術的補完策による監視強化**
- **ログ分析体制**: 月次での手動ログレビュー・異常パターン検出手順の確立
- **アラート設定最適化**: A3標準機能での通知設定強化・重要違反の即座検知
- **バックアップ・復旧**: 分類ミス・誤削除時の迅速なデータ復旧体制構築
- **外部ツール連携**: 必要に応じた補完的セキュリティツールの選択的導入

**インシデント対応体制の確立**
- **即座対応手順**: 発見から30分以内の初期対応・影響範囲特定・関係者通知
- **エスカレーション体制**: 重要度・影響範囲に応じた報告ルート・意思決定プロセス
- **事後改善**: インシデント原因分析・再発防止策実施・教職員フィードバック
- **法的対応準備**: 教育委員会報告・保護者説明・監督官庁対応の手順標準化

**効果測定と継続改善**
- **KPI設定**: 分類精度・違反件数・教職員理解度・対応時間の定量評価
- **定期評価**: 半年毎の運用効果測定・課題識別・改善計画策定
- **ベストプラクティス共有**: 成功事例・効果的手法の教育機関間での情報交換
- **段階的A5移行検討**: 運用負荷・コスト・リスクレベルを考慮したA5移行判断

これらの運用対策により、A3環境でもZero Trustデータ保護の基本原則を実現し、教育機関に求められるセキュリティレベルを確保できます。
:::

### A5 での AI 駆動高度 DLP 戦略

A5環境では、AI・機械学習を活用した高度で自動化されたDLP保護を実現できます。

**エンドポイント DLP による包括的保護**
- **デバイス上リアルタイム制御**: ファイル作成・編集・コピー・移動の即座制御

## 暗号化によるZero Trust Data Security

### Zero Trust 暗号化の戦略的アプローチ

Zero Trust では「すべてのデータを暗号化する」ことが基本原則です。教育機関では、特に個人情報保護法への対応として、暗号化による技術的安全管理措置が法的要件となっています。

**エンドツーエンド暗号化の実現**
- **データ作成時**: ファイル作成・メール作成時の自動暗号化
- **保存時**: SharePoint・OneDrive・Exchange での保存データ暗号化
- **転送時**: すべての通信経路での暗号化（TLS 1.2/1.3）
- **使用時**: アプリケーション使用中での暗号化状態維持
- **バックアップ時**: データバックアップ・アーカイブ時の暗号化継続

**キー管理戦略による統制確保**
- **キー生成**: 強固な暗号化キー自動生成・ローテーション
- **キー保存**: HSM（Hardware Security Module）での安全なキー保管
- **アクセス制御**: キーへのアクセス権限の厳格管理
- **監査証跡**: キー使用履歴の完全記録・監査対応

**データ主権確保による自主管理**
- **暗号化制御**: 教育機関による暗号化ポリシーの完全制御
- **アクセス管理**: データアクセス権限の独自基準による管理
- **地理的制御**: データ保存場所・処理場所の明確管理
- **法的要件対応**: 個人情報保護法・教育関連法令への完全準拠

### A3 でのベーシック暗号化戦略

A3 環境では、Microsoft 365 の標準暗号化機能を活用した基本的な保護を実現：

**サービス暗号化による標準保護**
- **Exchange Online 暗号化**: メールボックス・メッセージの自動暗号化（AES-256）
- **SharePoint/OneDrive 暗号化**: ファイル・ライブラリの保存時暗号化
- **Microsoft Teams 暗号化**: チャット・ファイル・通話記録の暗号化
- **暗号化キー管理**: Microsoft による自動キーローテーション・管理

**メッセージ暗号化による外部共有保護**
- **基本メッセージ暗号化**: 
  - 外部メール送信時の自動暗号化オプション
  - 受信者認証による安全な開封制御
  - 転送・印刷・コピー制限の基本機能
  - 有効期限設定による時限的アクセス制御

**Transport Layer Security による通信保護**
- **TLS 1.2/1.3**: すべての Microsoft 365 通信での強制暗号化
- **証明書検証**: 通信相手の正当性確認・中間者攻撃防止
- **Perfect Forward Secrecy**: セッション毎のキー生成による過去データ保護
- **HSTS対応**: HTTP Strict Transport Security による通信強制暗号化

**デバイス暗号化統合**
- **BitLocker統合**: Windows端末での自動ディスク暗号化
- **モバイル暗号化**: iOS・Android デバイスでのデータ暗号化連携
- **紛失時保護**: デバイス紛失・盗難時の遠隔データ消去
- **オフライン保護**: ネットワーク切断時での暗号化継続

### A5でのエンタープライズ暗号化戦略

A5環境では、教育機関による完全な暗号化制御と高度な保護機能を実現できます。

**Customer Key による完全自主管理**

Customer Keyは、教育機関が暗号化キーを完全に所有・管理することで、Microsoft でもアクセス不可能な真のゼロトラストデータ保護を実現するA5限定の高度機能です。

- **暗号化キー所有**: 教育機関による暗号化キーの完全所有・管理
- **Microsoft アクセス制御**: Microsoft による暗号化データアクセスの完全遮断
- **キーローテーション**: 教育機関主導でのキー更新・管理
- **地理的制御**: キー保存場所・処理場所の明確指定・管理

**Customer Lockbox による監査統制**

Customer Lockboxは、Microsoft サポート担当者がデータにアクセスする際に、教育機関の明示的承認を必須とすることで、外部アクセスを完全に統制するA5の監査強化機能です。

- **Microsoft サポートアクセス制御**: 
  - サポート要請時の教育機関による明示的承認必須
  - アクセス内容・期間・担当者の事前明示と承認
  - アクセス作業のリアルタイム監視・記録
  - 作業完了後の詳細レポート・証跡提供

**高度メッセージ暗号化による外部連携強化**

高度メッセージ暗号化（Advanced Message Encryption）は、A3の基本暗号化を大幅に強化し、教育機関独自のブランディングと詳細なアクセス制御を可能にするA5の外部共有セキュリティ機能です。

- **ブランド統合**: 教育機関ロゴ・色調でのメール暗号化インターフェース
- **カスタム有効期限**: データ重要度に応じた柔軟な期限設定
- **取消機能**: 送信後のメール取消・アクセス停止
- **受信者制限**: IP・地域・デバイスによる受信者制限

**統合データガバナンス**

統合データガバナンスは、機密ラベル・DLP・暗号化・エンドポイント保護などの個別セキュリティ機能を統合し、一元的なポリシー適用と自動化されたコンプライアンス管理を実現するA5の包括的データ統制機能です。

- **ラベル暗号化統合**: 機密ラベルと暗号化レベルの自動連携
- **DLP 暗号化連携**: データ損失防止と暗号化の統合制御
- **エンドポイント暗号化統合**: デバイス・クラウド・通信の一元暗号化管理
- **コンプライアンス自動化**: 暗号化状況の自動レポート・監査証跡生成
