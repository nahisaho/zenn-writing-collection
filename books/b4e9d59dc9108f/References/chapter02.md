# NIST Zero Trust Identity 実現のための戦略的アプローチ

## Zero Trust Identity の基本原則と教育機関での適用

### NIST Zero Trust Identity 要件の理解

NIST SP800-207では、Zero Trust Architecture の中核としてIdentityを位置づけ、「何も信頼せず、すべてを検証する（Never Trust, Always Verify）」原則に基づく包括的なアイデンティティ管理を求めています。教育機関においてこの原則を実現するためには、以下の3つの基本要件を理解する必要があります。

**明示的な検証（Verify Explicitly）**

従来の「内部は安全」という前提を完全に放棄し、すべてのアクセス要求において利用可能なデータポイントを活用した検証を行います。

- **ユーザーアイデンティティ**: 教職員・管理者・外部ユーザーの確実な身元確認
- **デバイス情報**: 管理状態・コンプライアンス・セキュリティ状況の継続的評価
- **アクセスコンテキスト**: 時間・場所・ネットワーク・過去の行動パターン分析
- **アプリケーション・データ**: アクセス対象の機密度・重要度に応じた動的判断

**最小限の特権アクセス（Least Privilege Access）**

Just-In-Time（JIT）および Just-Enough-Access（JEA） 原則により、必要最小限の権限のみを必要な期間だけ付与します。

- **役割ベースアクセス制御**: 教職員・管理者の職責に応じた権限設定
- **動的権限調整**: 学年進行・人事異動・プロジェクト参加に応じた自動権限変更
- **時限付きアクセス**: 重要業務・システム管理での一時的特権昇格
- **リスクベース制御**: アクセス状況に応じた権限の動的制限・拡張

**侵害の想定（Assume Breach）**

内部・外部問わずセキュリティ侵害が発生することを前提とし、被害の局限化と迅速な検知・対処を実現します。

- **継続的検証**: アクセス後も継続的な行動監視・異常検知
- **マイクロセグメンテーション**: 校務系・学習系・管理系の論理的分離
- **ブラスト半径最小化**: 侵害発生時の影響範囲を最小限に抑制
- **証跡・フォレンジック**: すべての活動記録による事後分析・改善

### 教育機関特有の Zero Trust Identity 要件

教育機関では、一般企業とは異なる特有の要件に対応した Zero Trust Identity 戦略が必要です。

**多様なユーザー層への対応**

- **教職員**: 校務系での適切なセキュリティレベルに応じたアクセス制御
- **管理者**: 高度な特権を必要とする管理業務での厳格な認証・監査
- **外部ユーザー**: 非常勤職員・研究協力者・外部委託業者等の安全な招待管理

**教育特有のデータ機密性要件**

- **校務系データ**: 個人情報保護法要配慮個人情報レベルでの厳格な管理
- **研究データ**: 知的財産保護と学術的公開のバランス
- **管理データ**: 法定保存義務・監査要件への対応

**教育カレンダーとの整合性**

- **学年・学期制度**: 進級・卒業・入学に応じた自動的アクセス権変更
- **長期休暇対応**: 夏休み・冬休み期間での適切なアクセス継続・制限
- **入試・行事期間**: 特別な業務要件に応じた一時的アクセス拡張
- **緊急時対応**: 災害・感染症等での業務継続性確保

## Microsoft Entra ID による Zero Trust Identity 基盤

### 統合アイデンティティ管理の戦略的設計

Microsoft Entra ID は、Zero Trust Identity 実現の中核基盤として、教育機関の複雑なID管理要件に対応する包括的な機能を提供します。効果的な戦略実現のためには、以下の設計原則に基づく統合的アプローチが重要です。

**ハイブリッドID統合戦略**

教育機関では、Microsoft Entra ID と校務支援システムとの統合が重要な要件となります。

- **クラウドファーストID管理**: Microsoft Entra IDを中核とした統合ID基盤
- **校務支援システム連携**: SCIM/SAMLプロトコルによる自動プロビジョニング
- **フェデレーション認証**: シングルサインオン実現による利便性向上
- **ハイブリッド対応**: 既存オンプレミス Active Directory がある場合は Entra ID Connect による統合

**動的グループ管理による自動化**

動的グループとは、ユーザーの属性（部署、役職、学年など）に基づいて自動的にメンバーシップが更新されるグループ機能です。従来の手動でメンバーを追加・削除する静的グループとは異なり、設定したルールに基づいてMicrosoft Entra IDが自動的にグループメンバーを管理します。

教育機関における動的グループの効果：

- **運用負荷の大幅削減**: 年度替わりの数千人規模の学年更新・卒業処理が自動化
- **人的ミスの排除**: 手動でのグループメンバー管理によるミス・漏れを完全に防止
- **即時性の確保**: 属性変更と同時にアクセス権限が自動的に適切に更新
- **情報漏洩リスクの根本的防止**: 卒業・退職・異動後のグループからのアカウント消し忘れによる不正アクセス・情報漏洩を完全に防止
- **コンプライアンス強化**: 退職・異動時の権限剥奪漏れによるセキュリティリスクを回避
- **スケーラビリティ**: 組織規模に関わらず一定の管理コストで運用可能

```
学年ベースグループ例:
- dynamic_students_grade1: user.extensionAttribute1 -eq "Grade1"
- dynamic_students_grade2: user.extensionAttribute1 -eq "Grade2"

職種ベースグループ例:
- dynamic_teachers: user.department -eq "Teaching"
- dynamic_admin: user.department -eq "Administration"

権限レベルベースグループ例:
- dynamic_koumu_access: user.extensionAttribute2 -eq "KoumuSystem"
- dynamic_learning_only: user.extensionAttribute2 -eq "LearningOnly"
```

**ライフサイクル管理の自動化**

教職員のライフサイクル変化に対応した自動的な権限管理：

- **新規採用時**: 自動アカウント作成・初期グループ配属・基本権限付与
- **異動・昇進時**: グループメンバーシップ・権限レベルの自動更新
- **退職時**: アカウント無効化・データアーカイブ・アクセス権剥奪
- **一時的変更**: 留学・休職・復職等での柔軟な権限調整

### A3 と A5 での Zero Trust Identity 実現能力の差異

Microsoft 365 A3 と A5 では、Zero Trust Identity 実現において重要な機能差があります。教育機関は、この差異を理解した上で戦略的なライセンス選択を行う必要があります。

:::message alert
**A3 環境で発生しうるセキュリティインシデント事例**

以下は、A3の静的ルールベース制御では防げない、またはリアルタイムで検知できない実際のインシデント事例です。

**1. パスワードスプレー攻撃による侵害**
- **攻撃手法**: 攻撃者が複数のアカウントに対して一般的なパスワードで低頻度でログイン試行
- **A3 の限界**: 静的なログイン失敗回数の閾値では、複数アカウントへの分散攻撃を検知できない
- **実際の被害**: 「password2024」等の推測可能なパスワードを使用していた教職員アカウントが侵害され、成績データベースに不正アクセス
- **A5なら防げた理由**: Identity Protectionが異常なサインインパターンをAIで検知し、自動的にアカウントをブロック

**2. 退職教員による内部不正アクセス**
- **攻撃手法**: 退職後も有効なアカウントを使用して、深夜に校務データを継続的にダウンロード
- **A3 の限界**: 時間帯・場所制限は設定できるが、正規の認証情報による異常な行動パターン（大量ダウンロード、通常と異なるアクセス頻度）は静的ルールでは検知不可能
- **実際の被害**: 3か月にわたり個人情報を含む校務データ約10万件が外部流出
- **A5 なら防げた理由**: Identity Protectionが異常な行動パターンをAIで検知し、リスクベース評価により動的にアクセスを制限

**3. フィッシングによる資格情報窃取後の不正アクセス**
- **攻撃手法**: 巧妙なフィッシングメールで教員の認証情報を窃取し、海外IPから校務システムにアクセス
- **A3 の限界**: 地理的ブロックを設定していても、VPN経由で国内IPを偽装されると防げない
- **実際の被害**: 教職員の個人情報・成績情報が改ざんされ、学校運営に重大な影響
- **A5なら防げた理由**: 不可能移動検出（物理的に移動不可能な場所からのアクセス）とダークウェブでの漏洩資格情報検出により事前にブロック

:::

これらの事例は、静的ルールでは対応できない高度な攻撃に対して、A5のAI駆動型動的制御がいかに重要かを示しています。

**A3 でのベーシック Zero Trust Identity 戦略**

A3 ライセンスでは、Microsoft Entra ID Plan 1 を基盤とした基本的な Zero Trust 機能を利用できます。

**基本的条件付きアクセス制御**
- **場所ベースアクセス制御**: IPアドレス・地理的位置による制限
- **デバイス基準制御**: 管理デバイス・準拠デバイスからのアクセス許可
- **アプリケーション制御**: 校務系・学習系アプリケーション別の差異化制御
- **時間ベース制御**: 業務時間・学習時間に応じたアクセス制限

**静的多要素認証**
- **Microsoft Authenticator**: スマートフォンアプリによる二要素認証
- **SMS/音声認証**: 基本的な追加認証方式
- **FIDO2セキュリティキー**: パスワードレス認証の基本実装
- **アプリパスワード**: レガシーアプリケーションとの互換性確保

**A3の限界と制約**
- **静的ルールベース**: 事前定義されたルールによる画一的制御
- **リスク分析不足**: ユーザー行動・異常パターンの動的分析機能なし
- **自動化制限**: AI・機械学習による自動判断・対処の不足
- **高度機能制限**: Privileged Identity Management 等のエンタープライズ機能なし

:::message 
**A3 環境での運用によるセキュリティリスク低減策**

A3 の技術的制約を補完するため、以下の運用的対策によりセキュリティリスクを大幅に低減できます。

**1. パスワードスプレー攻撃対策**
- **定期的パスワード監査**: PowerShell スクリプトによる弱いパスワードの検出・強制変更
- **アカウントロックアウト最適化**: 短時間での複数失敗を厳格に制御（例：5分間で3回失敗でロックアウト）
- **ログ分析の自動化**: 複数アカウントへの同時ログイン試行をPower BIダッシュボードで可視化・アラート
- **教職員向け意識向上**: 月次でのパスワード強度チェックとセキュリティ教育実施

**2. 内部不正アクセス対策**
- **アクセス権限の定期レビュー**: 四半期ごとの全アカウント権限棚卸しと自動無効化
- **異常行動の手動監視**: 勤務時間外・大量データダウンロードの定期確認
- **退職時プロセス**: 退職予定日の2週間前からのアクセス権限段階的削除
- **データ分類とアクセス制限**: 機密度別のファイル分離とダウンロード制限

**3. フィッシング対策**
- **多層防御の実装**: Defender for Office 365 P1 + 外部セキュリティソリューション
- **定期的訓練**: 月次フィッシング模擬訓練とクリック率分析
- **インシデント対応手順**: 資格情報漏洩疑いの際の即座パスワード強制リセット
- **VPN/地理的制限強化**: 海外IPからのアクセス完全ブロック + 必要時のみ例外申請

**4. アカウント乗っ取り対策**
- **パスワード使い回し監視**: HaveIBeenPwned 等外部サービスとの定期照合
- **異常ログイン監視**: 通常と異なる時間・場所からのアクセスの手動チェック
- **アカウント定期管理**: 年度末の一括パスワードリセットと新年度の再設定
- **メール送信監視**: 大量メール送信の検知とアカウント一時停止

これらの運用的対策により、A3 環境でも相当程度のセキュリティレベルを維持できますが、人的リソースと継続的な管理コストが必要となります。
:::

**A5 でのエンタープライズ Zero Trust Identity 戦略**

A5ライセンスでは、Microsoft Entra ID Plan 2による高度なZero Trust機能を活用できます。

**リスクベース動的アクセス制御**
- **Identity Protection**: AI駆動によるリアルタイムリスク評価
- **行動分析**: 正常行動パターンからの逸脱検知
- **匿名IP・不可能移動検出**: 地理的に不可能なアクセス試行の自動検知
- **リークされた資格情報検出**: ダークウェブ等で発見された資格情報の自動無効化

**高度な特権アクセス管理**
- **Privileged Identity Management (PIM)**: Just-In-Time管理者権限の実現
- **Access Reviews**: 定期的なアクセス権限の自動レビュー・承認ワークフロー
- **Entitlement Management**: アクセス権限の申請・承認・自動付与
- **Admin Unit管理**: 管理権限の細分化・委任

**AI・機械学習による自動化**
- **Conditional Access 継続評価**: セッション中の継続的リスク評価
- **異常アクセス検出**: 過去のパターンとの差異分析による自動アラート
- **自動修復アクション**: リスク検出時の自動パスワードリセット・アカウント制限
- **インテリジェントレポート**: セキュリティ状況の自動分析・改善提案

### 教育機関向けアイデンティティアーキテクチャ設計

**校務支援システムとの統合連携**

現代の教育機関では、校務支援システムと Microsoft 365 の統合により、効率的でセキュアな ID 管理を実現する必要があります。

**統合認証基盤の構築**
- **SAML Federation**: 校務支援システムと Microsoft Entra IDの 連携
- **プロビジョニング自動化**: ユーザー情報の自動同期・更新
- **権限マッピング**: 校務システムの役割と Microsoft 365グループの対応
- **監査証跡統合**: 両システム間でのアクセス記録統合管理

**データ整合性とセキュリティ確保**
- **マスターデータ管理**: 校務支援システムを権威ソースとしたデータ管理
- **暗号化通信**: システム間通信の暗号化による情報保護
- **エラーハンドリング**: 同期失敗・不整合時の自動復旧メカニズム
- **バックアップ・復旧**: ID 情報の安全な保存・復旧体制

**外部ユーザー招待管理の戦略**

教育機関では、研究協力者・外部委託業者等の外部ユーザーとの安全な連携が重要です。

**B2B招待管理プロセス**
- **承認ワークフロー**: 外部ユーザー招待の適切な承認プロセス
- **時限付きアクセス**: 必要期間に限定された外部アクセス権
- **ドメイン制限**: 許可された組織・ドメインからのユーザーのみ招待許可
- **リスクベース制御**: 外部ユーザーに対する追加的セキュリティ要件

**プライバシー・コンプライアンス対応**
- **最小限の情報収集**: 業務に必要最小限の外部ユーザー情報のみ取得
- **同意管理**: 個人情報利用・保存に対する明示的同意取得
- **削除権対応**: 外部ユーザーからの削除要求への適切な対応
- **越境データ対応**: 国外ユーザーとの連携時のデータ主権配慮

## 条件付きアクセスによる Zero Trust 実現戦略

### A3 での基本的 Zero Trustアクセス 制御戦略

A3 環境での条件付きアクセスは、静的ルールベースながらも Zero Trust の基本原則を実現する重要な機能です。教育機関の特性を考慮した効果的な設定戦略を理解することが重要です。

**場所・時間ベースアクセス制御**

教育機関の物理的・時間的特性に応じた段階的アクセス制御：

**校内アクセス戦略**
- **信頼できる場所定義**: 校内 IP アドレス範囲の正確な設定
- **フルアクセス許可**: 校内からのすべてのアプリケーション・データアクセス
- **デバイス制限軽減**: 校内では管理デバイス要件の柔軟化
- **高速認証**: 校内では認証手順の簡素化による利便性向上

:::message alert
**WPA2-Enterprise活用による校内セキュリティ強化戦略**

校内からのアクセスでパスワード認証のみに簡素化する場合、ネットワークレベルでの厳格なセキュリティ対策が必要不可欠です。

**WPA2-Enterprise 必須要件**
- **個別ユーザー認証**: WPA2-Personal（共有キー）ではなく、WPA2-Enterprise（個別認証）による接続制御
- **RADIUSサーバー統合**: Microsoft Entra ID・Active Directoryとの認証連携
- **証明書ベース認証**: 各デバイスへの固有証明書配布による強固な認証
- **MACアドレス制御**: 許可デバイスのみの接続許可（補完的対策）

**ネットワーク分離戦略**
- **VLAN分離**: 校務系・来客用・管理系ネットワークの完全分離
- **802.1X認証**: ポート認証による有線接続制御
- **動的VLAN割当**: 認証結果に基づく自動ネットワーク配置
- **ネットワークアクセス制御（NAC）**: 接続デバイスの自動評価・制御

**追加セキュリティ要件**
- **IDS/IPS導入**: 校内ネットワークでの異常通信検知
- **トラフィック監視**: 校務系アクセスの継続的監視・ログ記録
- **定期的認証更新**: 証明書・認証情報の定期更新
- **物理セキュリティ**: ネットワーク機器・配線への物理的アクセス制御

**制約・リスク認識**
- **設定複雑化**: WPA2-Enterprise導入・運用の技術的難易度
- **コスト増**: RADIUSサーバー・証明書管理の追加コスト
- **単一障害点**: 認証基盤障害時の全校ネットワーク停止リスク
- **運用負荷**: 証明書配布・更新・トラブル対応の継続的負担

WPA2-Enterprise　による厳格なネットワーク制御により、校内でのパスワード認証のみでも相当程度の安全性確保は可能ですが、完全な保護ではなく、MFAと比較して以下のリスクが残存します。
- パスワード漏洩時の即座侵害可能性
- 内部者による不正アクセス検知困難
- フィッシング攻撃への脆弱性継続
:::

**リモートアクセス制御**
- **多要素認証必須**: 校外からのアクセスでは必ず追加認証要求
- **アプリケーション制限**: 機密性の高い校務系アプリの利用制限
- **セッション時間制限**: 長時間セッションの自動切断による安全性確保
- **VPN統合**: 必要に応じたVPN経由アクセスの義務化

**時間ベースアクセス管理**
- **業務時間**: 平日日中での標準的アクセス権限

## 多要素認証によるZero Trust基盤強化

### Zero Trust 視点での MFA 戦略設計

多要素認証は、Zero Trust の「明示的検証」原則を実現する最も重要な技術的基盤の一つです。教育機関では、利用者の多様性を考慮した包括的なMFA戦略が必要です。

**多層認証による強固な身元確認**

「知識・所有・生体」の3要素を組み合わせた堅牢な認証基盤：

**知識要素（Something You Know）**
- **複雑なパスワード**: 文部科学省ガイドラインに準拠した強度要件
- **パスワード定期変更**: 90日サイクルでの強制変更（重要アカウント）
- **パスワード履歴管理**: 過去12回のパスワード再利用防止
- **辞書攻撃対策**: 一般的単語・個人情報利用の禁止

**所有要素（Something You Have）**
- **Microsoft Authenticator**: プッシュ通知・TOTP・パスワードレス認証
- **FIDO2セキュリティキー**: 物理キーによる高セキュリティ認証
- **SMS・音声認証**: 基本的な追加認証方式（バックアップ用途）
- **ハードウェアトークン**: 高セキュリティ要件での物理トークン利用

**生体要素（Something You Are）**
- **Windows Hello**: 指紋・顔認証による端末レベル認証
- **FIDO2生体認証**: 生体情報とセキュリティキーの組み合わせ
- **スマートフォン生体認証**: Authenticatorアプリでの指紋・顔認証
- **将来技術対応**: 虹彩・静脈等の新技術への準備

**リスク適応認証による動的制御**

アクセス状況・リスクレベルに応じた認証強度の動的調整：

**低リスク状況での認証簡素化**
- **校内・管理デバイス**: 単一要素または簡易追加認証
- **通常業務時間**: 標準的な認証フロー
- **既知デバイス・場所**: 学習済み環境での認証軽減
- **定期利用者**: 行動パターン学習による信頼度向上

**高リスク状況での認証強化**
- **校外・未知デバイス**: 複数要素での厳格な認証要求
- **時間外・休日アクセス**: 追加認証・管理者承認要求
- **異常行動検出時**: 段階的な認証強化・アカウント一時停止
- **機密データアクセス**: 必須多要素認証・時間制限設定

**コスト制約を考慮したMFA実装優先順位**

予算制約がある教育機関では、以下の優先順位でMFA実装を検討することを推奨します。

**第1段階: 無償・低コストソリューション（年間追加コスト: ほぼゼロ）**
- **Microsoft Authenticator**: A3ライセンスに含まれる無料アプリ
  - **QRコード認証**: アプリでQRコードスキャンによる簡単認証
  - **プッシュ通知**: スマートフォンへの通知タップによる認証
  - **TOTPコード**: インターネット不要の時間ベースワンタイムパスワード
- **パスワードレス認証（基本）**: A3ライセンス内でのパスワード依存軽減
  - **Authenticatorアプリパスワードレス**: スマートフォンのみでの認証完結
  - **Windows Hello（基本）**: 既存PCの内蔵カメラ・指紋センサー活用
  - **電話認証**: 音声・SMSによるパスワード補完認証
- **SMS認証**: 既存携帯電話契約での追加料金なし（通信料のみ）
- **音声認証**: 固定電話活用による追加コストなし
- **条件付きアクセス**: A3ライセンス内の基本機能活用

**第2段階: 中コストハードウェア（年間追加コスト: 1人あたり500-2000円）**
- **基本FIDOキー**: YubiKey 5C NFC等の低価格セキュリティキー
- **共用FIDOキー**: 教職員用共有セキュリティキー（教室配置）
- **Windows Hello**: 既存PCのカメラ・指紋認証機能活用
- **NFCカード**: 職員証への認証機能統合

**第3段階: 高コストエンタープライズソリューション（年間追加コスト: 1人あたり3000-10000円）**
- **A5ライセンス**: AI機能・高度リスク評価が必要な場合のみ
- **高機能FIDOキー**: YubiKey 5 Series、複数プロトコル対応
- **PKI証明書**: 専用CA構築・HSM導入が必要な高セキュリティ環境
- **専用MFAソリューション**: サードパーティ製高機能認証システム

**予算ゼロでも開始可能な実装パターン**
```
Step 1: Microsoft Authenticator を全教職員に展開
Step 2: SMS認証をバックアップ認証として設定
Step 3: 条件付きアクセスで校外からの認証強化
Step 4: Windows Hello（内蔵カメラ・指紋）の活用推進
```
:::

**教職員向けコスト効率化戦略**

教育機関では予算制約が厳しく、教職員の技術的スキルも多様です。MFA導入にあたっては、追加コストを最小限に抑えながら、技術的ハードルも下げることが成功の鍵となります。既存のリソースを最大限活用し、段階的に導入することで、全ての教職員が無理なく利用できるMFA環境を構築する戦略を以下に示す。

**低コスト認証手段の確保**
- **既存デバイス活用**: 教職員の個人スマートフォンでの Authenticator 利用
- **固定電話活用**: 職員室・教室固定電話での音声認証
- **学校端末での事前設定**: 設定困難を回避する学校 IT 担当者によるサポート

**段階的コスト負担軽減策**
- **教育委員会一括購入**: セキュリティキー等のボリュームディスカウント活用
- **補助金活用**: 文科省・自治体補助金でのセキュリティ強化予算確保
- **段階的導入**: 重要度に応じた優先順位付けによる予算平準化

**運用コスト最小化戦略**
- **自動化推進**: 手動管理コスト削減のための設定自動化
- **セルフサービス**: ユーザー主導での MFA 設定・復旧によるサポート負荷軽減
- **教職員トレーニング**: 外部委託削減のための内部専門知識蓄積
- **段階的展開**: 一斉展開リスク回避と予算平準化
