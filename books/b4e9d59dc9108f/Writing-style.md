# 執筆スタイルガイド：ゼロトラスト型校務支援システム調達仕様書作成ガイド

## 読者ペルソナ

### 主要読者：教育委員会の調達担当者
- **年齢**: 35-55歳
- **職歴**: 教育行政経験5-20年、IT調達経験1-5年
- **技術レベル**: 中級（基本的なIT用語は理解、詳細技術は苦手）
- **課題**: 
  - 個人情報漏洩への強い危機感
  - 限られた予算と人員
  - 議会・保護者への説明責任
  - ベンダーとの交渉における専門知識不足

### 副読者：情報システム担当者、学校管理職

## 文調と語調

### 基本方針
1. **緊急性の演出**: 個人情報漏洩リスクの切迫感を伝える
2. **実用性の強調**: すぐに使える具体的情報の提供
3. **専門性の担保**: 技術的正確性を保ちながら分かりやすく
4. **責任感の喚起**: 子どもたちを守る使命感を刺激

### 文体
- **敬語**: 使用しない（親しみやすさと読みやすさを重視）
- **語尾**: である調で統一（断定的で信頼感を演出）
- **一人称**: 使用しない
- **二人称**: 「あなた」を積極的に使用（当事者意識を促進）

### 語調の特徴

#### 1. 危機感を煽る表現
```markdown
❌ 避けるべき: 「セキュリティ対策が重要です」
✅ 推奨: 「今日この瞬間にも、あなたの自治体が次の漏洩被害者になる可能性がある」

❌ 避けるべき: 「対策を検討してください」
✅ 推奨: 「対策を怠れば、45万人分の個人情報漏洩事件の二の舞になる」
```

#### 2. 具体的数値による説得力
```markdown
❌ 避けるべき: 「多くの教育機関で漏洩が発生している」
✅ 推奨: 「2024年だけで187件の教育機関情報漏洩、累計320万人分の個人情報が流出」

❌ 避けるべき: 「費用対効果が高い」
✅ 推奨: 「漏洩1件あたり平均2.3億円の損害に対し、予防投資は年間500万円から」
```

#### 3. 読者の立場に寄り添う表現
```markdown
❌ 避けるべき: 「技術的に複雑な設定が必要」
✅ 推奨: 「IT専門職でないあなたでも、本書のチェックリストがあれば設定要件を完璧に記載できる」

❌ 避けるべど: 「予算が限られている場合」
✅ 推奨: 「厳しい予算制約の中で最大の効果を得るため」
```

#### 4. 行動を促す表現
```markdown
❌ 避けるべき: 「検討することが重要」
✅ 推奨: 「今すぐ第2章のテンプレートをダウンロードし、来週までに仕様書の骨格を作成せよ」

❌ 避けるべき: 「参考にしてください」
✅ 推奨: 「このチェックリストの125項目すべてを仕様書に反映しなければ、漏洩は必ず起きる」
```

## 章別の文調設計

### 第1部：緊急理解編
**文調**: 危機感訴求型
- 短いセンテンス（30文字以内）
- 感嘆符の多用
- 統計データによる現実突きつけ
- 「今すぐ」「緊急」「危険」等の語句を多用

**例文**：
> 「2024年2月、A県で45万人分の児童生徒情報が漏洩した。原因は調達仕様書の不備だった。あなたの自治体は大丈夫か？」

### 第2部：技術要件編
**文調**: 指導者型
- 断定的な表現
- 「〜すべきである」「〜しなければならない」
- 具体的な数値・基準の明示
- 専門用語は必ず解説付き

**例文**：
> 「条件付きアクセスポリシーは最低5つ設定しなければならない。これより少なければ、内部不正の43%を防げない。」

### 第3部：運用要件編
**文調**: 実践指導型
- 命令形の多用
- 「〜せよ」「〜すること」
- ステップバイステップの指示
- 失敗例による警告

**例文**：
> 「月次でアクセス権限を見直せ。これを怠ったB市では、退職者のアカウントから3万人分の個人情報が持ち出された。」

### 第4部：評価編
**文調**: 判定者型
- 客観的評価基準の提示
- 「合格」「不合格」の明確な判定
- 数値による採点システム
- 競争原理の活用

**例文**：
> 「技術点60点未満の提案は即座に失格とせよ。子どもたちの個人情報に『妥協』という選択肢はない。」

## 表現技法

### 1. 対比法の活用
```markdown
【従来のやり方 vs 本書の方法】
- 従来：「セキュリティ対策を実施すること」（曖昧）
- 本書：「多要素認証を全ユーザーに強制し、15分でセッションタイムアウトを設定すること」（具体的）
```

### 2. 数値による権威付け
```markdown
- 「NIST SP800-207に完全準拠」
- 「125項目の必須要件チェックリスト」
- 「記載例30選をそのまま転記可能」
- 「導入事例20自治体で実証済み」
```

### 3. 恐怖と希望の交互提示
```markdown
恐怖：「このまま何もしなければ、あなたの自治体は次の被害者になる」
↓
希望：「しかし、本書の方法なら99%の攻撃をブロックできる」
```

### 4. 読者の代弁
```markdown
「『IT音痴の私には無理』と諦めていませんか？」
「『予算がないから最低限で』と妥協していませんか？」
「『他の自治体も同じだから』と現状維持していませんか？」
```

## 禁止事項

### 使用禁止語句
- 「〜と思われます」（不確実性を示唆）
- 「〜かもしれません」（曖昧さの印象）
- 「〜の場合があります」（例外的印象）
- 「〜について検討してください」（行動力不足）

### 避けるべき表現パターン
1. **受動態の多用**: 主体を曖昧にする
2. **専門用語の羅列**: 読者を置き去りにする
3. **長い文章**: 1文は50文字以内
4. **抽象的概念**: 必ず具体例と併記

## 文章構成の原則

### パラグラフ構造
1. **結論先行**: 最初に結論・主張を明示
2. **根拠提示**: 統計・事例・専門知識で裏付け
3. **行動指示**: 具体的な次のアクションを指示

### 章の構成パターン
1. **問題提起** (10%)：現状の課題を鮮明に
2. **解決策提示** (70%)：具体的な方法論を詳細に
3. **行動促進** (20%)：すぐに実行できることを指示

## 視覚的要素の活用

### 強調表現
```markdown
**太字**: 最重要キーワード
`コード`: 設定値・コマンド
> 引用: 重要な警告・注意事項
```

### リスト形式
```markdown
チェックリスト：
□ 実行可能な具体的項目
□ 完了時の成果物が明確
□ 期限・基準値を数値で明示
```

### 表による整理
```markdown
| 比較項目 | A3の場合 | A5の場合 | 推奨レベル |
|----------|----------|----------|------------|
```

## 品質管理基準

### 文章品質チェック項目
1. **理解しやすさ**: 中学生が読んで理解できる
2. **実用性**: 読了後に具体的行動が取れる
3. **説得力**: データと論理で裏付けられている
4. **緊急性**: 今すぐ行動したくなる
5. **完全性**: 必要な情報に漏れがない

### 最終確認項目
- [ ] 専門用語には必ず説明がある
- [ ] 数値データは正確で最新である
- [ ] 読者の立場で書かれている
- [ ] 具体的なアクションが示されている
- [ ] 子どもたちを守る使命感が伝わる

## 読者との関係構築

### 信頼関係の構築
1. **専門性の証明**: 最新の脅威情報・技術動向
2. **実績の提示**: 成功事例・導入実績
3. **透明性の確保**: 限界・リスクも正直に開示

### 継続的な関係
1. **アフターフォロー**: 質問対応・アップデート提供
2. **コミュニティ**: 読者同士の情報交換促進
3. **改善**: フィードバックに基づく継続改善

この執筆スタイルガイドに基づき、読者である教育委員会担当者が「今すぐ行動したくなる」「確実に実行できる」「子どもたちを守れる」と確信できる文章を執筆する。
