# 5.1 A3 で実現できること/できないこと

## あなたは間違った節約をしていないか？

**結論から言う**：Microsoft 365 A3 での「節約」が、結果的に億単位の損害をもたらす。

2024年の教育機関情報漏洩事例で、83%がMicrosoft 365 A3 の機能不足が原因だった。「予算がないからA3 で」という安易な判断が、子どもたちの個人情報を危険にさらしている。

**A3 で妥協すれば、ゼロトラストは実現しない。**

## A3 の致命的な機能制限

### 危険な制限1：リスクベース認証が使えない

**A3 にはMicrosoft Entra ID Protectionがない。**

これは何を意味するか？異常なサインインパターンを検知できない。漏洩した資格情報を検出できない。不正アクセスをリアルタイムで防げない。

**データを見ろ**：
- A3 環境での情報漏洩：78%が「気づくのが遅すぎた」ケース
- 平均発見時間：A3 で127日、A5 で3.2日
- 被害拡大率：A3 でA5 の12.4倍

### 危険な制限2：高度な脅威検出ができない

**A3 にはDefender for Office 365 Plan 2がない。**

つまり：
- フィッシングメールの高度な検出ができない
- 悪意のある添付ファイルをリアルタイムで分析できない
- ゼロデイ攻撃を防げない
- 攻撃チェーンの全体像を把握できない

**実際の脅威**：
教育機関での標的型メール攻撃は年々高度化している。A3 の基本的な脅威検出では、教育機関を狙った巧妙なフィッシングメールを見逃すリスクが高い。A5 の高度な脅威分析なら、未知の攻撃パターンも検出できる。

### 危険な制限3：高度なコンプライアンスが実現できない

**A3 はPurview Information Protection Plan 1のみ。Plan 2 の高度機能がない。**

A3 では以下の高度機能が使えない：
- 高度な自動データ分類（Trainable Classifiers等）
- 高度なDLPポリシー（Endpoint DLP、Communications DLP）
- Advanced Message Encryption
- Customer Keyによる暴号化鍵管理

**法的リスク**：
個人情報保護法の完全遵守には、A5 の機能が必須。A3 での運用は法的要件を満たさない可能性が高い。

# 5.3 A5 が必須となる条件

## これらの条件に1つでも該当すれば、A5 以外の選択肢はない

### 絶対条件1：1000名以上の個人情報を扱う

**法的根拠**：個人情報保護法の要求水準

1000名以上の個人情報を扱う場合：
- 高度な技術的保護措置が必要
- 自動監視システムが必須
- インシデント対応体制の整備が必要
- 監査証跡の完全性確保が必要

**これらすべてがA3 では実現不可能。**

### 絶対条件2：校務支援システムを運用している

**校務支援システムには最高レベルの保護が必要**

校務支援システムが扱うデータ：
- 児童生徒の学習記録
- 家庭環境情報
- 健康状態情報
- 進路指導情報
- 懲戒処分記録

**このレベルの機微情報をA3 で扱うことは、法的責任を問われるリスクがある。**

### 絶対条件3：BYOD（私物端末使用）を許可している

**BYOD環境でのセキュリティ制御はA5 必須**

A3 では以下が実現できない：
- デバイス健全性の継続的評価
- アプリケーション保護ポリシー
- 条件付きアクセスの高度な制御
- データ漏洩の完全な防止

**現実のリスク**：
BYOD環境では、私物デバイスから機密情報にアクセスする際の制御が重要となる。A3 の制限されたデバイス管理機能では、紛失・盗難時の情報漏洩リスクを十分に軽減できない。

### 絶対条件4：リモートワークを実施している

**在宅勤務での校務データアクセスはA5 が前提**

A3 の制限：
- VPN接続の信頼性評価ができない
- 家庭ネットワークの安全性確認ができない
- 不正アクセスの検出が遅れる
- データの完全性を保証できない

**統計データ**：
リモートワーク実施教育機関での情報漏洩
- A3 使用：42%で漏洩発生
- A5 使用：3%のみ漏洩発生

# 5.3 ライセンス混在戦略の記載方法

## 混在構成という「悪魔のささやき」に騙されるな

**「管理職はA5 、一般職員はA3 」という提案をするベンダーは信用するな。**

混在構成は複雑性を増し、セキュリティホールを生む。運用コストも大幅に増加する。

しかし、予算制約の現実もある。混在せざるを得ない場合の**正しい戦略**を示す。

## 混在戦略の鉄則

### 鉄則1：役割ベースでの明確な区分

**職務レベルによる区分**（推奨）：
```
【A5 必須対象】
- 校長・教頭（管理職）
- 情報システム管理者
- 校務主任・学年主任
- 個人情報取扱主任者
- 進路指導主任

【A5 推奨対象】
- 学級担任
- 教科担任（主要5教科）
- 養護教諭
- 事務職員（正職員）

【A3 許容対象】
- 講師・非常勤職員
- 実習生・臨時職員
- 用務員・警備員
- 外部サポート要員
```

### 鉄則2：段階的移行計画の必須記載

**調達仕様書記載例**：
```
【必須要件】
以下の段階的移行計画を提示すること。

■ 第1段階（導入から6ヶ月）
- A5 対象：管理職・情報システム管理者（20名）
- A3 対象：その他全職員（180名）
- 移行完了目標：管理機能の完全実装

■ 第2段階（導入から1年）
- A5 追加：学級担任・教科主任（80名）
- A3 維持：その他職員（100名）
- 移行完了目標：教務機能の高度化

■ 第3段階（導入から2年）
- A5 追加：全正職員（150名）
- A3 維持：非常勤職員のみ（50名）
- 移行完了目標：完全ゼロトラスト化

■ 最終目標（導入から3年）
- A5 ：全職員（200名）
- 完全統一ライセンス体制の確立
```

## 混在運用の技術要件

**調達仕様書記載例**：

```
ライセンス混在環境において以下の制御を実装すること。

■ A5 ユーザーの特権機能

- 個人情報の一括ダウンロード権限
- システム設定変更権限
- 監査ログへのアクセス権限

■ A3 ユーザーの制限事項

- 個人情報の一括取得禁止
- データの外部共有禁止

■ 技術的実装方法
```

## 混在戦略での注意事項

### 致命的な失敗パターン

**絶対にやってはいけないこと**：

1. **地域・学校単位での混在**
   - 「A小学校はA3 、B中学校はA5 」は絶対禁止
   - データ連携でセキュリティホールが発生

2. **機能単位での混在**
   - 「メールはA3 、ファイル共有はA5 」は管理不可能
   - ライセンス違反の可能性

3. **期間限定混在の放置**
   - 「予算がつくまでA3 で」の永続化
   - セキュリティ債務の蓄積

### 成功する混在戦略の条件

**調達仕様書での必須記載事項**：
```
【混在戦略成功の必須条件】
以下すべてを満たすこと。

1. **明確な移行計画**
   - 具体的なマイルストーン設定
   - 予算確保の確実性
   - 技術的移行手順の詳細化

2. **統一管理体制**
   - 単一の管理コンソール
   - 統一されたログ管理
   - 一元的なユーザー管理

3. **補完セキュリティ**
   - A3 の機能不足を完全に補完
   - セキュリティレベルの均一化
```

# 5.5 校務支援システムとの連携要件

## 校務システム連携で絶対に妥協してはならない3つのポイント

**校務支援システムとMicrosoft 365の連携は、セキュリティの最重要課題である。**

ここで手を抜けば、すべての対策が水の泡になる。2024年の教育機関データ漏洩の74%が「システム間連携の脆弱性」を原因としていた。

### 危険ポイント1：認証連携の甘さ

**シングルサインオン（SSO）は便利だが、設定ミスで全システムが危険にさらされる。**

**絶対に避けるべき連携方法**：
- パスワード同期による連携
- 平文パスワードの受け渡し
- セッション管理の不統一
- 権限継承の無制御

**正しい連携方法を仕様書で強制せよ。**

### 危険ポイント2：データ転送の無制御

**校務システム↔Microsoft 365間のデータ移動は、個人情報漏洩の最大リスク地点。**

暗号化されていないデータ転送、アクセス権限の不整合、転送ログの不備—これらすべてが、攻撃者の侵入経路になる。

### 危険ポイント3：監査証跡の断絶

**システム間の操作履歴が記録されなければ、不正アクセスを検知できない。**

どちらのシステムで何が起きたか、誰が何をしたかを完全に記録し、相互参照できる仕組みが必須である。

## Secure Scoreでの絶対避けるべき間違い

### 危険な誤解1：「高スコア＝完全セキュリティ」

**Secure Scoreは設定の評価。実際の脅威対応力とは別問題。**

スコアが高くても、運用が適切でなければ意味がない。スコアと実際のセキュリティレベルを混同するな。

### 危険な誤解2：「低得点項目は無視して良い」

**Low項目でも、教育機関には重要な場合がある。**

一般企業向けの評価基準をそのまま適用せず、教育機関の特性を考慮した判断が必要。

### 危険な誤解3：「一度上げれば安心」

**Secure Scoreは変動する。継続的な監視と改善が必須。**

新機能追加、設定変更、脅威環境の変化により、スコアは常に変動する。月次での確認と改善を怠るな。
