## この章で学べること
- セキュリティ侵害時の損害賠償責任を明確化する契約条項
- Microsoft Secure Score目標値の契約化による継続改善の担保
- 監査権確保による透明性とガバナンスの実現
- 契約違反時の迅速な契約解除条件の設定
- そのまま使えるセキュリティ契約条項集テンプレート

## なぜこの章が重要なのか
優秀な提案書を提出した業者が、契約後に手抜き運用を行う例は後を絶たない。口約束では何の保証にもならない。契約書に明記されていない要件は「実施しなくても良い要件」と業者は解釈する。あなたの教育機関と子どもたちを守る最後の砦が、この契約条項である。

# 契約でセキュリティを担保する

## 12.1 セキュリティ保証条項

### 12.1.1 セキュリティレベル保証の必須条項
**要件**：以下のセキュリティ保証条項を契約書に必ず記載すること

業者の「最善を尽くします」という曖昧な約束では、子どもたちの個人情報は守れない。具体的な数値目標と達成義務を契約書に明記し、法的拘束力を持たせることが必須である。

```yaml
【必須セキュリティ保証条項】

第●条（セキュリティレベル保証）
1. 乙（受注者）は、以下のセキュリティ水準を保証し、これを下回った場合は
   座に改善措置を講じる義務を負う。

   (1) Microsoft Secure Score基準値
       - 運用開始時：850点以上
       - 運用1年後：900点以上
       - 運用2年後：950点以上
       - 毎月15日までに前月実績を報告

   (2) システム稼働率保証
       - 校務系システム：99.5%以上（月次）
       - Microsoft 365サービス：99.9%以上（月次）
       - 計画外停止：月間4時間以内
       - 緊急メンテナンス：事前72時間通知

   (3) セキュリティインシデント対応時間
       - 重大インシデント（個人情報漏洩等）：検知後30分以内に第一報
       - 中程度インシデント（不正アクセス等）：検知後2時間以内に第一報
       - 軽微インシデント（設定変更等）：検知後24時間以内に報告
       - 全インシデント：発生から1週間以内に詳細報告書提出

2. 乙は前項に定める水準を下回った場合、甲（発注者）に対し以下のペナルティを支払う。
   - Microsoft Secure Score未達：1点あたり月額基本料金の0.1%
   - 稼働率未達：0.1%不足ごとに月額基本料金の1%
   - 対応時間超過：1時間超過ごとに月額基本料金の5%
```

#### 12.1.2 継続的セキュリティ改善義務
**要件**：業者に継続的なセキュリティ向上を義務付けること

```yaml
第●条（継続的セキュリティ改善義務）
1. 乙は、以下の継続的改善を実施する義務を負う。

   (1) 四半期ごとのセキュリティ評価
       - Microsoft Secure Scoreの詳細分析
       - 改善項目の優先順位付け
       - 3ヶ月以内の改善計画策定
       - 改善実施と効果測定

   (2) 最新脅威への対応
       - 新規脅威情報の月次報告
       - 脅威に対する対策の2週間以内実装
       - 既存セキュリティ設定の見直し
       - 必要に応じたポリシー更新

   (3) 教職員向けセキュリティ教育
       - 年4回の集合研修実施
       - e-ラーニングシステムの提供
       - セキュリティ意識調査の実施
       - 標的型攻撃メール訓練（月1回）

2. 乙が前項の義務を怠った場合、甲は乙に対し月額基本料金の10%相当額の違約金を請求できる。

3. 乙は、セキュリティ改善に関する全ての活動記録を7年間保存し、甲の要求に応じて提出する
   義務を負う。
```

### 12.1.3 NIST SP800-207完全準拠保証
**要件**：NIST SP800-207への準拠を契約で保証させること

```yaml
第●条（NIST SP800-207準拠保証）
1. 乙は、本システムがNIST SP800-207「Zero Trust Architecture」に完全準拠することを
   保証する。

2. 前項の準拠には、以下の7原則の完全実装を含む。
   (1) すべてのデータソースとコンピューティングサービスをリソースとみなす
   (2) ネットワークの場所に関係なく、すべての通信を保護する
   (3) 企業リソースへのアクセスをセッション単位で許可する
   (4) リソースへのアクセスを動的ポリシーで決定する
   (5) 企業はすべての所有・関連デバイスの整合性と安全性を監視・確保する
   (6) すべてのリソース認証と認可を動的に行い、アクセス前に実施する
   (7) 企業はアセット、ネットワーク、通信の現在の状態について可能な限り多くの情報を
       収集して改善に活用する

3. 乙は、第三者認証機関による準拠性監査を年1回受審し、証明書を甲に提出する義務を負う。

4. 準拠性に問題が発見された場合、乙は30日以内に改善措置を完了し、再監査を受ける義務を
   負う。
```

## 12.2 損害賠償条項

### 12.2.1 個人情報漏洩時の損害賠償責任
**要件**：個人情報漏洩時の賠償責任を明確化すること

個人情報漏洩の被害額は1件あたり平均2.3億円に達する。業者の過失による漏洩で自治体が被害を受けることは断じて許されない。賠償責任の上限を設けず、全額を業者負担とする条項が必要である。

```yaml
第●条（個人情報漏洩時の損害賠償）
1. 乙の故意又は過失により個人情報の漏洩、紛失、毀損が発生した場合、乙は甲に対し以下の
   損害を賠償する責任を負う。

   (1) 直接的損害
       - 個人情報1件あたり5万円の賠償金
       - システム復旧費用
       - 代替システム構築費用
       - 調査・分析費用

   (2) 間接的損害
       - 住民・保護者への謝罪費用
       - 信用失墜による逸失利益
       - 法的対応費用（弁護士費用等）
       - 再発防止措置費用

   (3) 社会的責任費用
       - 報道対応費用
       - 第三者委員会設置費用
       - コールセンター設置・運営費用
       - 住民説明会開催費用

2. 前項の賠償責任に上限は設けない。

3. 乙は、第1項の賠償に備え、サイバーセキュリティ保険（最低補償額10億円）に加入し、
   保険証券を甲に提出する義務を負う。

4. 漏洩等が発生した場合、乙は発見後1時間以内に甲に報告し、24時間以内に詳細報告書を
   提出する義務を負う。
```

#### 12.2.2 システム障害時の損害賠償責任
**要件**：システム障害による業務停止の賠償責任を設定すること

```yaml
第●条（システム障害時の損害賠償）
1. 乙の責めに帰すべき事由によりシステム障害が発生し、甲の業務に支障が生じた場合、乙は
   以下の損害を賠償する責任を負う。

   (1) 業務停止損害（障害時間に応じて算定）
       - 1時間以内の停止：月額基本料金の1%
       - 1時間超2時間以内：月額基本料金の3%
       - 2時間超4時間以内：月額基本料金の5%
       - 4時間超8時間以内：月額基本料金の10%
       - 8時間超の停止：月額基本料金の20%

   (2) 緊急対応費用
       - 職員の時間外勤務手当
       - 代替手段の実施費用
       - 外部業者への緊急委託費用

   (3) 機会損失
       - 成績処理の遅延による影響
       - 保護者連絡の遅延による影響
       - 各種証明書発行の遅延による影響

2. 計画的メンテナンス時間は前項の障害時間に含めない。ただし、事前通知なしに実施された
   場合はこの限りでない。

3. 障害復旧に48時間を超える場合、甲は他業者への緊急委託を行うことができ、その費用は
   乙の負担とする。
```

### 12.2.3 セキュリティ目標未達時のペナルティ
**要件**：数値目標未達時の具体的ペナルティを設定すること

```yaml
第●条（セキュリティ目標未達ペナルティ）
1. 乙が第●条に定めるセキュリティ目標を下回った場合、以下のペナルティを課す。

   Microsoft Secure Score未達ペナルティ:
   - 目標値850点未満800点以上：月額料金の5%減額
   - 目標値800点未満750点以上：月額料金の10%減額
   - 目標値750点未満700点以上：月額料金の20%減額
   - 目標値700点未満：契約解除事由とする

   稼働率未達ペナルティ:
   - 99.5%未達99.0%以上：月額料金の5%減額
   - 99.0%未達98.5%以上：月額料金の10%減額
   - 98.5%未達98.0%以上：月額料金の20%減額
   - 98.0%未達：契約解除事由とする

   インシデント対応遅延ペナルティ:
   - 対応時間30%超過：月額料金の5%減額
   - 対応時間50%超過：月額料金の10%減額
   - 対応時間100%超過：月額料金の20%減額
   - 対応なし：契約解除事由とする

2. 前項のペナルティは累積計算し、最大で月額料金の50%まで減額可能とする。

3. 連続3ヶ月間ペナルティが発生した場合、甲は契約を解除できる。
```

## 12.3 監査権の確保

### 12.3.1 包括的監査権限の設定
**要件**：甲（発注者）の監査権限を包括的に保証させること

業者に「企業秘密」を理由に監査を拒否させてはならない。子どもたちの個人情報を扱う以上、完全な透明性が必要である。監査権限の制限は、セキュリティリスクの隠蔽につながる。

```yaml
第●条（監査権の確保）
1. 甲は、本契約の履行状況及びセキュリティ状況を確認するため、乙に対し以下の監査を
   実施する権利を有する。

   (1) 定期監査（年4回）
       - システムセキュリティ設定の確認
       - 運用プロセスの適切性確認
       - ログ記録の完全性確認
       - 要員のセキュリティ意識確認

   (2) 臨時監査（必要時随時）
       - インシデント発生時の緊急監査
       - セキュリティ問題疑義時の調査
       - 第三者からの指摘事項確認
       - 新たな脅威発見時の対策確認

   (3) 外部監査（年1回）
       - 独立した第三者機関による監査
       - 国際的セキュリティ基準への準拠確認
       - 監査結果の公開（機密情報除く）

2. 前項の監査において、乙は以下の協力義務を負う。
   - 監査に必要な全資料の提供
   - システムへのアクセス権限の提供
   - 担当者による詳細説明の実施
   - 改善指示への30日以内の対応

3. 乙は、監査に要する費用を負担する。ただし、監査結果で問題が発見されなかった場合の
   外部監査費用は甲の負担とする。
```

#### 12.3.2 リアルタイム監視権限
**要件**：甲によるリアルタイム監視を可能とする権限を確保すること

```yaml
第●条（リアルタイム監視権限）
1. 甲は、システムのセキュリティ状況をリアルタイムで監視する権利を有し、乙は以下の環境を
   提供する義務を負う。

   (1) 監視ダッシュボードの提供
       - Microsoft Secure Scoreのリアルタイム表示
       - システム稼働状況の24時間表示
       - セキュリティアラートの即座通知
       - ユーザーアクティビティの可視化

   (2) ログ情報への直接アクセス
       - セキュリティログへの読み取り専用アクセス
       - システムログへの読み取り専用アクセス
       - 監査ログへの読み取り専用アクセス
       - アクセスログの完全開示

   (3) APIによるデータ取得権
       - Microsoft Graph APIへのアクセス権
       - セキュリティAPIへのアクセス権
       - 運用データAPIへのアクセス権
       - カスタムレポート作成権限

2. 前項の監視により問題を発見した場合、甲は乙に即座の改善を指示できる。

3. 乙は、監視を理由として追加費用を請求することはできない。
```

### 12.3.3 データ所有権の明確化
**要件**：データの所有権を明確化し、甲の権利を保護すること

```yaml
第●条（データ所有権）
1. 本システムで処理・保存される全てのデータの所有権は甲に帰属する。

2. 乙は、前項のデータを以下の目的以外に使用してはならない。
   - 甲への本契約に基づくサービス提供
   - 法令に基づく開示要求への対応
   - 甲の明示的な許可を得た場合

3. 甲は、自己のデータに対し以下の権利を有する。
   - データの完全なポータビリティ権
   - データの削除要求権
   - データの監査権
   - データの第三者提供拒否権

4. 契約終了時、乙は甲のデータを以下のとおり処理する。
   - 30日以内の完全なデータ移行
   - 乙の保有する全データの完全削除
   - 削除完了証明書の提出
   - バックアップデータの完全消去

5. 乙がデータ所有権を侵害した場合、甲は乙に対し損害賠償に加え、データ1件あたり10万円
   の懲罰的損害金を請求できる。
```

## 12.4 契約解除条件

### 12.4.1 即座契約解除事由
**要件**：以下の事由発生時は催告なしに即座契約解除できることを明記すること

業者の重大な契約違反に対して「改善の機会」を与える必要はない。子どもたちの安全に直結する問題では、即座の契約解除が唯一の適切な対応である。

```yaml
第●条（即座契約解除事由）
1. 甲は、乙に以下の事由が発生した場合、催告なくして本契約を解除できる。

   (1) セキュリティ重大違反
       - 個人情報の漏洩、紛失、毀損の発生
       - 不正アクセスの発生とその隠蔽
       - セキュリティ設定の無許可変更
       - バックアップデータの紛失

   (2) システム重大障害
       - 48時間を超えるシステム停止
       - データ破損・消失の発生
       - 復旧不可能な障害の発生
       - 計画外停止の月間24時間超過

   (3) 契約履行違反
       - 虚偽報告の発覚
       - 監査拒否・妨害行為
       - 要求された改善の90日間未実施
       - Microsoft Secure Score 600点未満の継続

   (4) 経営・体制問題
       - 乙の破産・民事再生手続開始
       - 主要技術者の大量離職
       - 事業譲渡・会社分割の実施
       - 反社会的勢力との関係発覚

2. 前項による契約解除の場合、甲は乙に対し以下を請求できる。
   - 違約金：契約残存期間の月額料金合計額
   - 損害賠償：実損害全額
   - 代替システム構築費用
   - データ移行費用

3. 乙は、契約解除通知から30日以内にデータ移行を完了し、システムを正常な状態で
   甲に引き継ぐ義務を負う。
```

#### 12.4.2 段階的契約解除手順
**要件**：軽微な違反に対する段階的解除手順を設定すること

```yaml
第●条（段階的契約解除）
1. 甲は、乙に軽微な契約違反がある場合、以下の段階的手順により契約解除を行う。

   第1段階：改善勧告（書面通知）
   - 違反事項の具体的指摘
   - 30日以内の改善要求
   - 改善計画書の提出要求
   - 改善状況の週次報告要求

   第2段階：改善命令（内容証明）
   - 違反継続の事実確認
   - 14日以内の改善命令
   - 改善未実施時の契約解除予告
   - ペナルティの発生通知

   第3段階：契約解除通知
   - 改善命令期限経過の確認
   - 30日前予告での契約解除通知
   - データ移行スケジュールの通知
   - 引継ぎ業務の詳細指示

2. 各段階において、乙は以下の権利を有する。
   - 改善実施による解除回避
   - 異議申立て（7日以内）
   - 第三者調停の申立て

3. 緊急性がある場合、甲は段階的手順を省略し、即座解除を行うことができる。
```

### 12.4.3 契約解除時のデータ処理要件
**要件**：契約解除時のデータ処理手順を詳細に定めること

```yaml
第●条（契約解除時のデータ処理）
1. 契約解除時、乙は以下のデータ処理を実施する義務を負う。

   (1) データ移行（30日以内完了）
       - 全データの完全移行
       - データ整合性の確認
       - 移行完了証明書の提出
       - 新システムでの動作確認

   (2) データ削除（移行完了後7日以内）
       - 本番環境からの完全削除
       - バックアップデータの完全削除
       - 開発・テスト環境からの削除
       - クラウド上の全データ削除

   (3) 削除証明（削除完了後3日以内）
       - データ削除証明書の提出
       - 第三者による削除確認
       - 削除作業ログの提出
       - 復旧不可能性の証明

2. データ処理に要する費用は、解除事由に応じて以下のとおり負担する。
   - 乙の責めによる解除：乙が全額負担
   - 甲の都合による解除：甲が全額負担
   - 不可抗力による解除：双方で等分負担

3. 乙がデータ処理義務を履行しない場合、甲は第三者にこれを委託し、その費用を乙に請求できる。

4. データ処理完了まで、本契約のセキュリティ関連条項は効力を継続する。
```
